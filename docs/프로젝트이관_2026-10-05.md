## 앞으로의 작업

1. 최신 main을 받아 AGENTS.md/CLAUDE.md와 [현재 배정](pm/현재배정.md)을 읽는다.
2. `project_report.py status --member {이름}`·`phase2.py next --member {이름}`로 조회한다. 새 보드 설정을 읽으므로 명령은 같다.
3. 자기 작업 의도/해석/행동/검증을 개인 docs 두 문서에 기록·push하고 담당 이슈로 보고한다. 팀원의 보드 직접 편집 권한은 제공하지 않는다.
4. PM은 검수·실제 병합·통합 확인 후 정확한 main에서 `sync_github_phase2.py --apply`로 공식 승인한다. 조직 소유자와 인증 PM 계정을 별도로 검사한다.

PR58은 실제 main `6b9dbe9298cd4e822132e617eaf30262d72d77e8`에 병합됐다. 원본 PR53/54는 그 인수본으로 연결해 닫았고 후속 Draft55/56/57은 별도 검수 대상이다. 실제 모델 연결은 확인했지만 제외 조건 충돌이 남아 Agent 전체 완료로 판정하지 않는다. 정식 Done5·신청31요구 verified0이다. 세 후속 배정은 황대겸 조건 검사, 최길웅 실제 웹 판단 흐름, 신진하 자료팩이며 각각 Gmail Sent를 직접 대조했다. 열람/개발 완료는 별도다.

최종 공유 PR·공식 승인·노션 반영은 최신 PM 종료 기록과 `final-verification.json`을 따른다.

## 저장소에서 보는 경로와 중단 구간 재점검

현재 GitHub Project는 조직/개인 소유로 만들고 저장소에 연결하는 구조다. 따라서 조직 URL이 남더라도 [LG 저장소 Projects](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-2026/projects)에서 동일 Private Project1을 열어 사용한다. 10/5 실제 목록에 열린 보드 한 개·올바른 조직 주소가 표시되는 것을 확인했다. 이 저장소를 기본 신규 이슈 저장소로 설정했다. 별도의 두 번째 운영 보드를 만들지 않는다. [공식 저장소 연결 안내](https://docs.github.com/en/issues/planning-and-tracking-with-projects/managing-your-project/adding-your-project-to-a-repository).

[공백 검수](../evals/project-migration/20261005/gap-reconciliation.json)는 전환 전 처리30건의 원문 해시·결과를 현재 서버와 대조해 변경/누락0을 확인했다. 등록된 보고·승인34건 중 미처리/수신증 누락/최근보고와 새보드 불일치는0이었다. 새 황대겸/최길웅 보고도 새보드에서 ACCEPTED였다. 이는 전송된 GitHub 보고의 보존 증거이며, 미전송 개인작업이나 참가작 품질을 입증하지 않는다. 과거 거절2건은 사유와 함께 보존했다. 기존 승인·최근보고·배정/메일/의존/근거 기록과 역사 보드는 지우지 않았다.

LG Notion과 전체 공모전 대시보드의 LG 부분을 재조회해 새 주소·상태 반영 및 비대상 내용 보존을 확인했다. 공개 확인 메타데이터는 [Notion 검수](../evals/project-migration/20261005/notion-verification.json)에 있다.
