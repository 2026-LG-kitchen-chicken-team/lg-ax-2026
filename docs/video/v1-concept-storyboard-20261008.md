# V1 콘셉트 영상 — 1단계 스토리보드 (2026-10-08)

담당: 최길웅(WEB) · 배정: [#239](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-2026/issues/239)(#234 V1) · 기록: [최길웅-20261008-060](../작업기록/최길웅/2026-10-08/최길웅-20261008-060.md)

V1의 흐름은 기획 → 스토리보드 → 참조 이미지 → 장면 → 자막·음성 편집이다. 이 문서는 첫 단계인 **스토리보드만** 다룬다. PM 지시대로 영상은 안정된 기획의 스토리보드부터 시작한다. 실제 영상, 이미지, 음성 생성은 아직 하지 않았다.

## 만들어진 것

- `apps/web/src/conceptStoryboard.ts`: 저장된 PlanningBrief(공통 계약 `research-planning.schema.json`)의 개선안 하나를 30~45초 스토리보드로 바꾼다. 장면 구성은 아래와 같다.
  - 제목 컷 1개
  - `visual_scenes`마다 '지금' 컷과 '제안(콘셉트)' 컷 1쌍
  - 마무리 컷 1개
- 컷마다 넣는 것: 길이(0.1초 단위, 총 길이는 목표 범위 안), 자막, 내레이션, 참조 이미지 메모, 근거 원문 ID.
  - '지금' 컷은 개선안이 다루는 문제의 원문을 근거로 단다.
  - '제안' 컷은 제안이라서 자체 근거가 없고 `proposed: true`로 표시한다.
- 모든 내용은 brief에서 그대로 옮긴다. 모델은 호출하지 않는다.
- 다음 경우에는 경고한다: 개선안이 `supported`가 아님, brief가 `complete`가 아님, 장면이 너무 많아 컷당 2초 미만, 빈 장면 제외.
- 장면이 모두 비어 있으면 스토리보드를 만들지 않는다.
- 실제 자료 기획 화면(`ResearchPlanningView`)의 개선안 카드에서 '스토리보드 Markdown/JSON'으로 내보낸다. 추가 서버 요청은 없다.

## 지키는 규칙

- 첫 자막과 마무리 자막에 '미래 콘셉트 시안이며 실제 성능·효과 증거가 아님'을 넣는다.
- 기획 revision·run ID·자료 묶음 지문을 스토리보드에 남긴다. 다른 revision의 영상과 섞지 않기 위해서다.
- 합성 리뷰나 하드코딩한 기획으로 스토리보드를 만들지 않는다. 테스트용 brief는 테스트 파일 안에만 있다.

## 다음 단계 전에 확인할 것(미완료)

- 참조 이미지·영상·음성 생성 모델 후보와 라이선스·상업적 사용 조건(공식 모델 카드 기준)
- 생성 장비(GPU)와 실행 시간: 연구실 GPU를 쓸 때는 기존 규칙대로 사용량을 먼저 확인한다.
- 실제 C3 기획 결과(안정된 revision)로 만든 스토리보드 검수. 현재는 실제 brief가 없어 단위·DOM 검사로만 확인했다.
- 30~45초 길이와 컷 수가 발표·제출 영상 규정에 맞는지(제출 영상 길이는 후속 확인 항목)
