- 범위 회귀는 #169에 이미 들어 있다. 직접 확인한 근거:
  - 패널 queryScope에 제품군·자료 스냅샷·문서 버전·기간이 들어 있다.
  - 검사: 모델 변경 시 대체 모델 미조회(96행), 빈 `topic_ids` 집계(20행), 주제 불일치 거절(206행).
  - 서버 `trend_validation._canonical_filters`는 빈 `topic_ids`를 `[]`로 두고 정렬만 한다. 웹 `sameIds`도 정렬해 비교하므로 빈 필터 대조가 맞다.
  - 그래서 신진하 요청 항목은 #169가 해결했다고 본다. #169가 병합된 main에서 다시 확인한다.
- PM 통합 영역(패널·클라이언트·판단 코드)은 #169 병합 전에 편집하지 않는다.
- 소비 경로 준비: 실제 collector(#148)는 DATA 소유라 만들지 않는다. 대신 다음 opt-in E2E를 새 파일로 만든다.
  - PM 테스트의 단위 `FixtureCollector`(실제 리뷰 36건 중 1건에만 시험 날짜·주제)를 주입한 시험 서버를 띄운다.
  - 웹 실제 화면에서 같은 aggregate ID → 숫자·분모 → 원문 → 기획 입력 → JSON·Markdown 내보내기를 확인한다.
  - MCP `get_review_trends`도 같은 ID·자료 hash·문서 버전을 주는지 확인한다.
  - #148 collector가 생기면 같은 시험을 실제 collector로 바꿔 돌린다.
  - 결과는 "연결 경로 검증"이다. 실데이터 숫자·수요의 증거로 쓰지 않는다.
