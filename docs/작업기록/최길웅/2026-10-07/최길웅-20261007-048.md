## 2. 브리핑(설명용, 약 3분)

**한 줄:** 웹은 코어 Agent가 남긴 실행 기록을 바꾸지 않고 그대로 보여 주는 기획 작업실입니다. 기획자가 판단 근거를 원문까지 따라가 확인하고, 조건을 바꿔 다시 요청하도록 돕습니다.

**다섯 영역**
1. **기획 요청:** 제품군·검토 모델·제외 조건을 입력합니다. 원 요청 대비 변경 사항과 요청 회차를 보여 줍니다.
2. **근거 대조:** 리뷰·설명서 원문을 모델·문서 버전·위치(행·쪽)와 함께 봅니다. 합성자료와 공개자료를 구분해 표시합니다.
3. **콘셉트 검토:** 코어의 결정(통과·보류·미해결)을 먼저 보여 주고, 그 판단 선언, 거절된 후보와 사유, 회차별 검사, 모델 호출·토큰·시간·검증 범위를 함께 보여 줍니다.
4. **수정 이력:** 기획자의 조건 변경 회차와 Agent 내부 수정 회차(최대 2회)를 구분해 연결합니다.
5. **리뷰 동향:** 월·계절별 리뷰 주제 언급 비율을 보여 주고, 막대를 누르면 원문으로 이어집니다. 같은 집계 ID로 JSON·Markdown 내보내기와 기획 요청 인계까지 연결됩니다.

**일반 LLM 대화와 다른 점(웹에서 보이는 것)**
- 모든 판단에 실행 ID·모델 digest·자료 해시·문서 버전·원문 위치가 붙습니다. 웹은 저장된 기록만 보여 주고 새로 판정하지 않습니다.
- 보류·실패를 성공처럼 보이지 않게 합니다. 통과하지 못한 후보는 선택할 수 없고, 거절 사유와 대상 Gap·후보가 표시됩니다.
