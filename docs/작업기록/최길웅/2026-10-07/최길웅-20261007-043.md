## 2. 해석(AI 해석)
- 값은 저장된 실행 기록에서만 읽는다. 새로 판정하거나 추정하지 않는다.
- 토큰은 호출별 `metadata.prompt_eval_count`/`eval_count`(모델 서버 보고)를 쓴다. 한 호출이라도 값이 없으면 합계는 null('미기록')로 둔다. 일부 합계는 전체 사용량처럼 읽히기 때문이다. 호출이 0회면 '호출 없음'이며 0 토큰으로 쓰지 않는다.
- 감사 r1d8: 기존 '모델 호출 3회 · 136.2초'는 trace 마지막 누적 시각, 즉 조회·검사를 포함한 전체 시간이었다. 이를 '모델 시간'(호출별 elapsed_ms 합)과 '전체 실행 시간(조회·검사 포함)'으로 나눈다. trace 시각은 '+x.xs, 실행 시작부터 누적'으로 표시한다.
- 회차: 요청 회차(`request_revision`, 기획자 조건 변경)와 Agent 내부 수정(`correction_budget.revision_count`/`max_revisions`, 같은 요청 안 자동 수정)을 한 줄에 나란히 적어 구분한다.
- 검증 범위: 아래 항목을 기록에 있는 그대로 알린다. 규칙 통과가 내용이 맞다는 뜻이 아님을 명시한다.
  - 의미 검토와 후보 없음 검토 횟수(0회면 미실행)
  - 규칙 모듈 3종의 위반 수와 `semantic_accuracy_verified`
  - `skill_trace.trusted_collector_verified`
  - 합성자료 여부
- 감사 r0d11: 호출별 저장 프롬프트와 원 응답을 접힌 목록으로 보여 준다. 판정 없이 원문 그대로 표시한다.
