## 2. 해석과 발견(AI 해석)
- PR #190은 웹 `judgement.ts`에 7개 설명만 추가했다. 그래서 각 코드가 어디에 저장되는지 원 소스에서 확인했다.
  - `need_extraction.py`: `REVIEW_SCOPE_MISMATCH`, `REVIEW_REASON_MISSING`, `REVIEW_ASSESSMENT_COVERAGE`, `UNCERTAINTY_CONTEXT_MISSING`, `UNCERTAINTY_SCOPE_MISMATCH`, `UNCERTAINTY_FIELD_MISSING`는 `DomainError("VALIDATION_FAILED", …, {"violations": [...]})`의 **details.violations[].code**에만 들어간다.
  - `skill_runner.py`: `EMPTY_NEEDS_WITHOUT_JUDGEMENT`는 **details.code**에만 들어간다.
  - `planning_agent.py`는 이 오류를 `result["errors"]`에 code·message·details 그대로 저장한다. 회차 결정의 violations에는 `VALIDATION_FAILED`만 남는다.
- **발견:** 웹은 `execution.errors`의 code와 message만 보여 준다. 그래서 PR #190을 병합해도 새 설명 7개는 화면·내보내기 어디에도 나오지 않는다. PM이 경고한 "label만 채운" 상태와 같다.
- 해결: 웹이 저장된 `details.violations[].code`·`details.code`와 함께 리뷰 ID(`evidence_id`)·필드 위치(`path`)를 읽어 각 오류 아래에 보여 준다. 코드 이름은 웹 registry 설명(`reasonText`)을 따른다.
  - PR #190 병합 전에는 새 코드가 '(설명이 등록되지 않은 검사 코드)'로 보인다. 병합 뒤에는 한국어 설명으로 보인다.
  - 모양이 맞지 않는 항목은 건너뛰고 추정하지 않는다.
- missing_information→unresolved, 질문→questions, 사유→hold_reasons는 CORE가 출력 필드로 옮긴다. 웹은 이미 이 필드를 '미해결'·'확인할 질문'·'보류 사유'로 보여 준다(기존 `JudgementPanel`·`OutputWithoutDecision`). 그래서 이번 변경은 오류 세부만 다룬다.
  - 실제 PR #190 run으로 hold 화면을 확인하는 일은 PM 병합과 실행 기록을 받은 뒤에 한다.
