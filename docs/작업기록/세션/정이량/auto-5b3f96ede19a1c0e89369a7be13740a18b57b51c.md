## 예정 행동과 실제 수행

처음에는 지침·공통 계약·기존 API/store/runner·소비자를 읽고 승인 경계 안에서 보완할 결함과 재현을 찾기로 했다. 실제로 AGENTS.md 및 CLAUDE.md를 읽고 `cmp`로 바이트 일치를 확인했다. README, 인수인계, 대회요건, 체크리스트, 기록 규칙과 정이량 재개/근거, workspace 문서를 참고했다. 큰 문서의 합산 출력 일부는 잘렸으므로 그 전체 운영 이력을 이번에 검증했다고 주장하지 않는다. 최신 직접 패킷을 작업 권한의 기준으로 삼았다.

초기 `git status --short`는 `/workspace`에 Git 메타데이터가 없어서 실패했다. 다른 checkout이나 인증 경로를 찾거나 설정을 바꾸지 않았다. 따라서 origin/main 차이·base 일치·기존 미커밋 변경을 Git으로 대조하지 못했다. 파일 읽기·편집만 계속했다.

코드에서 확인한 기존 동작: core가 run 생성·저장·권한 검사·고정 자료 해시·변경 회차·실패/보류 저장을 이미 담당한다. API는 이 결과와 DomainError를 그대로 반환했다. store의 계약 실패 fallback에는 거부된 실행 원본이 들어갈 수 있어 HTTP에서 예외 경로/인증 진단이 노출될 여지가 있었다.

실제 변경:

1. `apps/api/src/lgax_api/workspace_server.py`: `public_error`로 알려진 공통 오류 코드를 유지하고 메시지/상세는 안전한 서버 문구와 빈 details로 투영한다. 알 수 없는 코드도 반사하지 않는다. 권한/인증의 조기 반환에도 `Cache-Control: no-store`를 넣었다.
2. 같은 파일의 `public_run`: deepcopy 후 실행 오류 배열·trace/model_calls 안의 구조화 오류를 정제하고 `rejected_execution`을 전송에서 제외한다. 원 SQLite 기록, 요청, 제품/원문/버전, 판단 출력, 결정과 정상 모델 호출 출처는 보존한다. 생성·단건 조회·프로젝트 실행 목록 모두 `wrap`을 통해 같은 처리를 받는다.

4. `tests/test_api_run_failure_contract.py`: 실제 loopback TCP/Uvicorn/HTTPX·임시 SQLite·인메모리 fixture 인증·합성 자료를 쓰는 여섯 검사 메서드를 작성했다. 이 테스트 코드는 아직 실행하지 않았다. fixture 응답은 실제 모델 결과가 아니다.

## 자체 검토와 발견·수정

- API의 세 run 호출 경로 모두 `wrap` 사용을 읽기 대조했다. 생성만 정제하고 이후 GET/history에서 비밀이 재노출되는 누락을 피하도록 공통 함수를 사용했다.
- 처음 구상한 오류 탐지는 details가 없는 과거 오류를 놓칠 수 있었다. code/message 조합을 인식하고 errors 배열은 항목별로 안전하게 변환하여 부분 dict·문자열·알 수 없는 code도 처리하도록 보완했다. 해당 회귀 입력을 작성했다.
- 서버 출력 스키마 실패도 기존 전역 ValidationError 처리에서 사용자 입력 오류로 보일 수 있음을 확인해 `wrap`에서 명시적인 CONTRACT_MISMATCH로 보완했다. malformed saved output 회귀를 작성했다.
- 웹 `workspace.ts`, `judgement.ts`와 MCP workspace_client를 읽었다. 웹은 needs/gaps, 실행 상태, 결정, model_calls·model digest·trace를 사용하고 MCP는 공통 envelope/code를 소비한다. 이 필드를 통째로 삭제하는 방식은 채택하지 않았다. rejected_execution은 선택적 원진단이며 이 API에서는 제외한다. 웹/MCP 파일은 수정하지 않았다.
- 정상·보류·미구현 snapshot은 저장된 값과 HTTP 반환 전체가 같아야 한다는 회귀 assertion을 추가했다. 실패도 원본 출처/버전과 run ID를 유지하도록 비교한다. 오류 정제는 DB를 변경하지 않음을 별도로 검사하도록 작성했다.
- 자료 내용 변경 후 생성은409로 거절하고 과거 run 조회는 원 해시/원문 그대로 유지하는 회귀를 보완했다. 권한/잘못된 parent/model/version/body는 runner 호출 전에 거절되는지 calls 개수로 검사하도록 했다.
- 정적 검토에서 들여쓰기 정렬을 정리했다. repository 테스트, import, lint, build, Python 실행은 하지 않았다. 실행 성공/실패 수치는 없다.
