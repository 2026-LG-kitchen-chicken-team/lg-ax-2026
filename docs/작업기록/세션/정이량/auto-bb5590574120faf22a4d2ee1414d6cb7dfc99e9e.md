## 자기 검토와 수정

코드와 기존 호출자·테스트를 정적으로 대조했다. 다음 결함을 발견해 같은 승인 경로 안에서 수정했다.

1. 개별 기록만 있어 다섯 호출의 동일 실행/원 요청을 확인할 수 없음 → runtime trace, execution/sequence/request/schema digest 추가.
2. 실패·보류 응답에는 반환 sources가 없어서 실행 당시 자료 출처가 사라짐 → backend 선택 전 scoped 자료 스냅샷 저장. 잘못된 schema 입력은 원문을 저장하지 않는 기존 동작 유지.
3. 자료 버전 문자열이 같아도 내용이 바뀌거나 callback 중 자료가 바뀔 수 있음 → 전체 dataset digest 고정과 callback 직후 대조. 다른 내용을 조용히 같은 버전 재시도로 처리하지 않음.
4. bootstrap과 get_evidence가 다른 원문을 반환하면 스냅샷과 실제 판단 입력이 달라짐 → 문맥 근거와 최종 출력 근거를 기록된 sources와 대조.
5. 새 변경 연결이 review 회차를 낮춰 보이게 만들 수 있음 → 성공한 이전 결과 회차/실패한 이전 입력 회차와 새 입력 회차 일치 검사.
6. 공개 자료를 synthetic 응답으로 오표시할 수 있음 → 현 synthetic 전용 Skill 응답 계약 안에서는 명시 거부. 공통 계약의 실제 출처 값은 `public` 등이며 회귀에도 이 실제 enum을 사용.

기존 공개 Skill 응답 schema는 바꾸지 않았다. `planning_agent`의 `SkillRuntime(self.store)`와 `revision_guard.install()`은 기존 호출 형식을 유지한다. 다만 planning agent는 새 request 인수를 넘기거나 trace를 외부 실행 결과에 저장하지 않으므로 end-to-end 원 요청 연결은 후속 승인된 호출자 통합이 필요하다. CLI trace envelope는 허용 파일 안의 직접 소비자로 갱신했으며 기존 테스트의 records/cli_error 접근은 유지된다.

## 실제 검사·실패·한계

- 수행한 것은 파일 읽기, `cmp`, 텍스트 검색, `sha256sum`, 시각 조회와 승인 경로 파일 편집이다. `cmp AGENTS.md CLAUDE.md`는 출력 없이 exit 0이었다.
- 첫 `git status --short`는 `/workspace`가 Git 저장소가 아니어서 실패했다. 설정을 바꾸거나 저장소를 만들지 않았고 base/head/변경 목록을 Git로 확인했다고 주장하지 않는다.
- 새 테스트/세션 파일 최초 읽기·존재 확인은 아직 없어서 실패했다. 이후 승인 경로에 새로 만들었다. 선택한 `evidence_store.py` 탐색도 해당 파일이 없어 실패했으며 실제 `store.py`를 읽었다.
- 저장소 코드·테스트·빌드·모델·온라인 하네스·인증 조회는 실행하지 않았다. 14개는 작성된 테스트 수이며 통과 수가 아니다.
- runtime 기록은 메모리의 분리 복사본이고 trusted 수집기 증명이 아니다. callback 내부의 여러 모델 호출·토큰·provider revision 검증은 상위 adapter 기록이 필요하다. backend_id의 모델@digest 표현은 기존 등록자가 제공한 선언이다.
- `revision_of`는 같은 런타임 안의 입력 변경 연결이다. 서로 다른 사용자 요청/프로젝트 실행 간 저장 이력 연결, 동시 runtime 공유, 전체 공유 수정 예산 검증을 대신하지 않는다.

## 재개·다음 행동

종료 전 추가 정적 검토: reader 불일치 회귀가 공유 dictionary를 제자리 수정하면 bootstrap도 함께 바뀌는 결함을 발견했다. `_evidence` 인덱스 항목을 새 dictionary로 교체해 실제 스냅샷/조회 불일치를 만들도록 수정했다. 최종 테스트 해시는 근거 문서 표에 반영했다. 실행 재검사는 대기다. `stat`으로 네 승인 파일 모두 일반 파일임을 확인했다. 문서 정정의 첫 apply_patch는 문맥 불일치로 적용되지 않았고 정확한 문맥 재조회 후 반영했다. 종료 기록은 이 최종 상태로 인계하며 이후 validator 결과를 덮어쓰지 않는다.
