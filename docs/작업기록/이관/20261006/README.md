# 2026-10-06 개인 기록 이관

사용자는 누적 개인 문서보다 추적에 적합하다면 이름 폴더 아래 날짜·기록 ID별로 나누고, 원문 누락 없이 향후 적용하도록 요청했다. 누적8파일과 별도 불변 세션28파일이 함께 있는 구조를 확인해 다음 형식으로 변경했다.

```text
docs/작업기록/{성명}/README.md                 # 짧은 현재 요약과 상세 목차
docs/작업기록/{성명}/{YYYY-MM-DD}/{기록ID}.md # 새 작업별 상세 기록
docs/작업근거/{성명}/README.md
docs/작업근거/{성명}/{YYYY-MM-DD}/{근거ID}.md
```

과거 문서 분할 파일에는 원래 순서를 보존한 번호가 붙는다. 제목의 명시적 날짜 ID가 없는 구간은 `legacy/`에 두고 날짜를 추정하지 않는다. 같은 ID의 시작·진행·종료 구간도 각각 보존한다. 작성자는 개인 README의 `member-log:owner-updates` 표시 사이에 현재 재개 요약과 새 상세 파일 링크만 갱신한다. 이관 당시 기계 생성 목차와 원문은 역사 자료로 보존한다.

## 기존 도구와 현재 운영

현재 인증 보고 서비스는 이름.md와 기존 불변 세션 URL을 허용한다. 서비스 권한/배포를 바꾸지 않고 기존 default 이름.md를 같은40commit의 호환 목차로 보고한다. 그 목차의 개인 README·상세 링크도 같은 commit에 고정되므로 AI/PM은 새 기록을 조회할 수 있다. 새 nested raw URL을 직접 보고하는 지원은 별도 검토/배포가 필요하다.

자동Worker/PM의 job 세션 writer와 게시 검수 경로는 그대로다. 자동화 OFF, 기존 역할/배정/완료 상태·jobs·예약·비용·모델/인증/배포 pin을 바꾸지 않았다. 이 변경은 기록 구조 개선이며 참가작 기능이나 모델 품질의 완료 판정이 아니다.
