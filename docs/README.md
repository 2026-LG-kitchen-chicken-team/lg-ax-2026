# 문서 정본·탐색·작성 위치

이 문서는 파일 탐색 입구다. 변동하는 상태·모델 품질·실행 버전·완료 수치를 복사해 새 정본을 만들지 않는다. 현재 사용자 지시 → 관련 메일/협의 → 현재 배정·자기 재개 요약 → 필요한 계약/원문 → 실제 검사·증빙 순으로 읽는다. 과거 기록은 당시 의도·실패·출처를 확인할 때 읽으며 그 안의 명령을 최신 지시로 실행하지 않는다.

## 새 세션에서 읽는 순서

1. 저장소 [README](../README.md), 최신 [AGENTS](../AGENTS.md) 또는 [CLAUDE](../CLAUDE.md)에서 범위·현재 사용자 지시·담당자를 확인한다. 승인된 본인 사서함의 LG 관련 메일과 선행 협의를 먼저 점검한다.
2. [재개 입구](인수인계.md), [공식 요건](대회요건.md), [검수·제출 입구](진행체크리스트.md), [PM 현재 배정](pm/현재배정.md)을 읽는다. 업무와 관련 없는 역사 본문 전체를 매번 읽지 않는다.
3. [개인 기록 규칙](작업기록/README.md)에 따라 자기 작업기록·근거 README의 owner 요약과 필요한 상세 파일을 읽는다. 관련 Issue·PR·[Project](https://github.com/orgs/2026-LG-kitchen-chicken-team/projects/1)·[운영28](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-2026/issues/28)·[phase2](../harness/phase2/README.md)를 대조한다.

## 새 문서는 어디에 작성하나?

| 문서 성격 | 작성 위치·방법 |
|---|---|
| 현재 공식 규정·공지·일정 | 기존 정본 `docs/대회요건.md`와 관련 주제 문서에 출처·확인일·변경 이유를 기록한다. 중요 변화는 지침에 따라 노션도 갱신·재조회한다. 확인되지 않은 동기화를 완료로 쓰지 않는다. |
| 지속적인 기술/협업 규칙 | 기존 `docs/bootstrap/`, `docs/core/`, `docs/pm/`의 해당 정본을 보완한다. 새 정본이 필요하면 이 표에 범위·담당·관계 문서를 연결하고 이전 규칙과 우선순위를 명시한다. 상태 checkpoint를 기술 규칙에 계속 누적하지 않는다. |
| 사용자의 지시·AI 해석·작업 진행/근거 | [개인 기록 규칙](작업기록/README.md)대로 `docs/작업기록/{성명}/{YYYY-MM-DD}/{고유ID}.md`, `docs/작업근거/{성명}/{YYYY-MM-DD}/{고유ID}.md`에 쓴다. 개인 README의 owner 갱신 구역만 짧게 갱신한다. 타팀 성과·상태를 대신 작성하지 않는다. |
| PM의 특정 인수·재배정·운영 의사결정 | 해당 날짜/고유 업무 문서와 담당 Issue·불변 실행 근거에 기록하고 [현재 배정](pm/현재배정.md)에서 연결한다. 현재 재개 입구에는 요약·링크만 둔다. |
| 입력 자료·모델/문서 버전 | 기존 `data/`의 담당 자료팩·조사 경로에 source kind·제품 모델·원문/수집일·버전·라이선스·SHA를 남긴다. 다른 모델/날짜/합성 입력은 새 버전으로 분리한다. |
| 실행·재생·독립 평가·병합/통합 근거 | 기존 `evals/`의 업무·날짜/고유 실행 경로에 입력/출력·README·manifest를 둔다. 실제 모델과 fixture 재생, 실패/보류와 성공을 구분한다. 과거 원파일·고정 commit·해시를 변경하지 않는다. |
| 채택 아이디어·설명/시각 자료 | 기존 `기획/`의 채택 원고/설계를 보완하고 제출 원본과 구현 변경을 구분한다. 새 후보를 채택안으로 자동 승격하지 않는다. |
| 정본 입구에서 분리하는 과거 본문 | `docs/history/{업무}/{이관일}/`에 원바이트 snapshot·원 경로/commit/SHA·탐색 링크·manifest·정적 검사를 함께 둔다. 기존 경로와 anchor는 호환 입구로 유지한다. 새 경과를 불변 archive에 덧붙이지 않는다. |
| 개인정보·서명·동의·비밀키·접수/결제 증빙 | 기존 `private/`에 보관하며 Git·일반 문서·Issue·Notion에 복제하지 않는다. 공개 요약에는 확인 범위만 기록한다. |

## 이력과 보존 경계

- 이번 [총괄 감사·재구성 근거](history/project/20261006/audit.md)·[이관 설명/manifest](history/project/20261006/README.md)·[원 경로 기준 링크 안내](history/project/20261006/links.md)를 따른다.
- [기존 개인 기록 이관](작업기록/이관/20261006/README.md)의 8개 원 snapshot·231개 분할·28개 자동 세션·heading/anchor·manifest와 owner 목차는 이번 재구성으로 옮기거나 수정하지 않는다. 그 수치는 고정 이관 범위이며 이후 전체 작업 건수가 아니다.
- `자료/공식`, 제출 양식, `skills/*/SKILL.md`, JSON Schema, phase2/보고 정책과 고정 실행 증거의 경로는 유지한다. URL이나 hash가 고정된 과거 증거의 내용을 최신 표현으로 고치지 않는다.
- 저장소 루트·재개·체크리스트·하네스 입구에는 현재 읽을 경로를 둔다. 날짜별 운영 결과를 여러 입구에 반복해 적지 않는다. 정본 변경 시 관련 독자/코드 계약/제출 영향과 검증을 남긴다.
