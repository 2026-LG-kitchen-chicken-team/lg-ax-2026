# 웹 초기 프레임워크 구현·검증

- 확인일: 2026-10-04 KST
- 범위: `apps/web/` 및 이 보고서. 공통 API·MCP·서버 모델과 프로젝트 상태 문서는 별도 담당.
- 실행 환경: Windows PowerShell, Node.js 22.23.2, npm 10.9.8.
- 개발 서버: `http://127.0.0.1:5173/`. 검증 시 공통 API `127.0.0.1:18867` 사용.

## 구현 결과

React·TypeScript·Vite 기반 한국어 상품기획 화면을 구성했다. 기획 요청, 근거 대조, 콘셉트 검토, 수정 이력의 네 영역을 마련하고, 현재 실행 가능한 자료 조회와 향후 Agent 기능을 구분했다. 냉장고·식기세척기·전자레인지의 선형 SVG 아이콘을 직접 작성하고, 데스크톱·모바일 화면을 지원한다.

`/api/bootstrap`에서 공통 자료를 읽고 제품군·모델·자료 유형·검색어로 원문을 조회한다. 상세에는 제품 모델, 문서 버전, 원문 위치, 근거 ID, 출처 자료 ID, 연결된 기능을 표시한다. 현재 API의 합성자료 모델 5개, 리뷰 36개, 근거 42개를 확인했다.

공통 Draft 2020-12 JSON 스키마를 직접 가져와 Ajv2020으로 응답과 요청을 검증한다. 계약 불일치, HTTP 오류, 네트워크 오류를 정상적인 빈 자료와 구분한다. API 연결이 실패하면 임의의 대체 샘플을 표시하지 않는다. 기획 요청의 현재 `HTTP 501 / NOT_IMPLEMENTED` 응답은 분석 준비 중으로 표시하고 성공·가짜 콘셉트·가짜 수정 이력을 만들지 않는다.

## 실행 검증

저장소 루트에서 재실행한다.

```powershell
npm ci --prefix apps/web
npm run test --prefix apps/web
npm run build --prefix apps/web
npm run dev --prefix apps/web
```

## 의존성과 환경 문제 처리

처음 선택한 Vite 8의 Rolldown 네이티브 모듈은 Windows 애플리케이션 제어에 의해 로딩이 차단되었다. 보안 설정을 바꾸지 않고 안정 Vite 7.3.6, Vitest 4.1.11, 공식 Rollup WASM 4.64.0 및 esbuild 0.28.1로 고정했다. 수정한 잠금파일로 npm 10.9.8의 `npm ci` 재실행을 확인했다.

의존성 변경 과정에서 npm 10의 내부 `edgesOut` 오류가 발생했다. 생성 의존성 폴더 정리 요청은 자동 승인 검토가 차단하여 실행하지 않았다. 삭제를 다른 방식으로 시도하지 않고 Node 22와 호환되는 npm 12.2.0으로 정상 패키지 설치를 수행해 해결했다. 전역 npm과 사용자 보안 설정을 변경하지 않았다.

## 남은 범위

이 결과는 초기 실행 기반이다. 자동 니즈 구조화, 기능 대조 판단, 콘셉트 생성, 인용 검사, 추가 조건·문서 변경 후 재검토, 변경 이력 저장, 파일 업로드·내보내기, 배포·인증 및 ChatGPT/Claude 호스트 연결은 아직 이 웹 구현에서 완성하지 않았다. 프론트엔드 빌드 통과를 공모전 제출 기능 완성으로 해석하지 않는다. 다음 구현은 동일한 공통 계약에 실제 Agent 결과와 실행 기록을 연결하는 작업이다.

여러 TSX 파일 수정 후 React best practices 스킬을 적용해 Hook 정리, 이벤트와 자료 요청 분리, 파생 상태·안정적인 목록 키, 입력 레이블, 오류 상태, 키보드·스크린리더 접근과 reduced-motion 설정을 점검했다.
