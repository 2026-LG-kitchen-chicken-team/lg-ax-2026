## 자체 검토 발견과 수정 근거

- 오류가 canonical details를 항상 가진다는 초기 가정을 제거했다. 과거/부분 errors 항목은 코드·메시지만 있거나 문자열일 수 있으므로 항목별 safe 오류로 처리했다. 불완전 오류 회귀 추가.
- 기존 출력 schema 실패가 입력 오류와 섞이는 문제를 발견해 wrap의 출력 검증에서 CONTRACT_MISMATCH로 전환했다. stored malformed row fixture 검사 추가.
- 조기 인증/출처 거절도 민감 응답이므로 no-store 누락을 보완했다.
- create/get/history의 projection 일관성, 실패에서 원 DB 원진단 불변, 정상/보류의 전체 snapshot 보존을 테스트 assertion으로 보완했다.
- 웹 모델 호출 증빙을 통째로 삭제하면 호출자 요구를 깨므로 채택하지 않았다. source/judgement/provenance는 유지하고 구조화 오류·rejected_execution만 정제한다.
- API 함수/라우트와 모든 테스트를 텍스트로 다시 읽고 indentation을 정리했다. 컴파일·import·테스트·빌드·lint를 실행한 적 없다.

## 실제 검사 결과와 미완료

관찰된 검사 결과는 파일 읽기/grep·지침 cmp 일치·파일 SHA 측정이다. 저장소 테스트 성공 수/실HTTP 성공/CI 결과는 **없다**. Git 조회 실패 외에 실행 테스트의 실패 결과도 관측하지 않았다. 아직 실제 실패 여부 자체를 모른다. 작성한 검사가 실패를 잡는다는 주장은 실행 이후 확정해야 한다.

남은 validator 명령 (사용자 패킷 그대로):

```text
uv run --offline --no-sync python -m unittest tests.test_api_run_failure_contract -v
uv run --offline --no-sync python -m unittest tests.test_workspace_api -v
```

환경 조건: 별도 zero-auth, offline 설치 상태, 임시 디렉터리 쓰기·loopback TCP 허용. 테스트 자체가 임시 서버와 DB를 생성하고 cleanup한다. 외부망/provider/실제 토큰 불필요. 본 worker에서는 실행하지 않았다.

한계: HTTP 정제로 오류의 상세 진단은 줄어든다. 원 private 진단 삭제/암호화 정책은 범위 밖이다. 임의 입력·모델 출력 본문을 모두 비밀 탐지/변환하는 범용 redactor가 아니며 정상 원응답·모델 provenance는 보존한다. 실모델 판단 품질·실사용·독립 평가·웹 빌드/브라우저·MCP 계정 연결은 이번 결과로 입증되지 않는다.

다음 행동은 trusted validator의 실제 실행 결과 인수, trusted publisher의 scope/base/해시 확인 및 PR, 독립 PM 검수다. 실패하면 그 원결과를 보존하고 승인된 후속 단위에서 수정해야 한다. 현재 사용자 직접 할 일/추가 승인 요청은 없다. 정식 하네스·Project 변경, 커밋/푸시·인증 접근·부모 Done·최종 제출은 전부 미수행이며 이 자체 검토는 PR 승인이나 trusted verification을 충족시키지 않는다.
