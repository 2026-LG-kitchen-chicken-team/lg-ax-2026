# LG AX 검수·제출 점검 입구

[문서 정본·작성 위치](README.md) · [작업 재개 순서](인수인계.md) · [공식 요건](대회요건.md)

이 입구의 항목은 완료 판정에 필요한 확인 절차다. 현재 진행 수치와 담당별 상태는 [PM 현재 배정](pm/현재배정.md), [phase2 작업·요구사항](../harness/phase2/README.md), [운영 Issue #28](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-2026/issues/28)와 불변 실행 근거에서 조회한다. 아래를 복사해 새 작업의 확인 결과를 기록할 수 있지만, 이 파일에 모든 작업의 날짜별 결과를 누적하지 않는다.

**착수·담당 확인**

- [ ] 최신 사용자 지시·공통 지침·승인된 본인 계정과 관련 메일/선행 협의를 확인했다.
- [ ] 담당 Issue·요구사항 ID·작업 패킷·편집 영역·입출력·완료 조건·의존 작업을 읽었다.
- [ ] 개인 branch/worktree와 고유 기록 ID를 사용하고 공유 파일 편집은 PM과 조율했다. 자동화는 새 ON 승인 전 OFF다.

**구현·검수·통합 확인**

- [ ] 신청 범위를 31개 요구사항과 구현·검사·증빙에 연결했다. 미구현·보류·실패를 성공 응답으로 바꾸지 않았다.
- [ ] 자료·제품 모델·문서/모델 버전·원문 위치·실자료/합성자료를 확인했다. 같은 실행 기록을 웹·API·MCP가 소비하는지 대조했다.
- [ ] 실제 입력→판단→Skill·Tool→결과와 변경/보류/실패·수정 한도를 승인된 격리 환경에서 검증했다. 저장된 원결과 재생은 새로운 모델 판단 성공과 구분했다.
- [ ] 자기 검수·PR 증빙·PM 검수·실제 병합 commit·병합 후 통합 검사·하네스 상태를 대조했다. 검사 통과만으로 사용자 효용·품질·최종 Done을 주장하지 않았다.
- [ ] 지시 원문·AI 해석·실제 수행/실패·근거·미완료·다음 행동을 자기 상세 문서에 남기고 개인 README의 owner 갱신 구역에서 재개 요약을 갱신했다. [기록 규칙](작업기록/README.md)을 따른다.

**평가·컨설팅·제출 확인**

- [ ] [컨설팅 준비](컨설팅_2026-10-07.md)의 공식 접속 안내와 질문·답변을 실제 출처로 대조했다. [API 지원](LLM_API지원_2026-10-06.md)의 발급·공급 규격·허용 범위·한도와 새 비용 승인을 구분했다.
- [ ] [독립 평가](pm/evaluation.md)에서 강한 일반 LLM 기준선·동일 입력/자료·전체 호출/재시도·미측정 값·실패 근거를 확인했다.
- [ ] [2차 제출 요건](2차제출_평가안내_2026-10-03.md)과 [제출 절차](pm/submission.md)에 따라 발표자료·시연 영상·전체 소스 ZIP의 README·재실행 Skill/SKILL.md·촬영 코드/자료/모델 버전 일치를 확인했다. 정확한 제출 경로·시각·용량은 최신 공식 안내로 확인한다.
- [ ] 새 중요 일정·운영 안내·결정을 로컬 근거와 하네스에 기록하고 관련 노션 페이지 반영·재조회를 확인했다. 연결 실패면 남은 동기화로 보고했다. 개인정보·서명·접수 증빙은 private에 유지했다.

**과거 점검 결과와 기존 링크**

이전 날짜별 전체 결과는 원바이트 [불변 원문](history/project/20261006/originals/docs/진행체크리스트.md)에 보존했다. [이관 설명·manifest](history/project/20261006/README.md)와 [원래 위치 기준 링크 안내](history/project/20261006/links.md)를 따른다. 아래 과거 제목의 체크 결과·ON·‘최신’은 해당 시점의 기록이며 현재 상태를 대신하지 않는다. 새 작업의 결과는 개인 기록·담당 Issue/PR·하네스 근거에 작성한다.
