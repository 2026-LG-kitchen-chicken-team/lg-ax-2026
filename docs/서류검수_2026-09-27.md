# 접수 서류 검토본 검수

확인일 2026-09-27. 접수 완료 증빙이 아니라 로컬 서류 작성·검수 기록이다.

## 작성 결과

- 원본 `자료/공식/02_참가신청서.hwp`의 신청서·제안서·동의서·서약서를 유지한 별도 HWP와 PDF를 만들었다.
- 개인 정보가 들어간 모든 작성본·중간본·페이지 이미지·파일 해시는 Git 제외 `private/제출준비/`에 보관한다.
- PDF 총 8쪽: 신청서 1, 제안서 5(2~6쪽), 동의서 1, 서약서 1. 제안서 10쪽 제한 이내다.
- 공식 6개 항목을 유지하고 파란 작성 안내를 제거했다. 단락별 페이지를 배정하고 빈 페이지를 제거했다.
- Theme A 선택, 사용자 제공 팀장·학년·연락처 반영. 학번은 사용자 요청으로 비웠다. 팀명·이메일도 미제공으로 공란이다.
- 사용자가 팀원의 승인을 받았다고 밝히며 필기체 이름 표기를 요청해 반영했다. 일반 필기체 폰트이며 실제 서명 이미지나 필적을 복제하지 않았다. 해당 요청과 동의 체크·팀 최종 검토를 구분한다.

## 확인 방법과 결과

1. 한글 2022에서 생성 HWPML을 열어 native HWP 저장 및 PDF 내보내기를 실행했다.
2. 저장된 HWP OLE 컨테이너와 압축 본문을 다시 읽어 6항목·제공 팀 정보·안내 삭제를 확인했다. 별도 한글 UI에서 최종 HWP를 수동 재개방한 검수와는 구분한다.
3. PDF 8쪽을 모두 렌더링하고 직접 시각 검토했다. 마지막 수정 후 변경된 4~6쪽을 다시 확인했으며 나머지 5쪽 렌더는 직전 검수본과 바이트가 같았다. 글자 잘림·표 넘침·빈 페이지가 없었다.
4. 동의·서약의 원본 주요 본문 16개 구절이 그대로 남았음을 확인했다. 개인정보·초상권 동의 체크는 아직 선택하지 않았다.
5. 공식 HWP 원본의 Git blob 해시가 HEAD와 일치함을 확인했다. 원본 변경 없음.
6. 합성 사례·예정된 구현·평가 계획과 실제 수행 결과를 구분했다. 성능 향상률·시장 수요·LG 실제 사양을 창작하지 않았다.

## 접수 전 남은 항목

- 팀명, 팀장 이메일, 학번(현재 공란 유지 요청).
- 세 명의 창원캠퍼스 참가자격 확인.
- 개인정보·초상권 동의 선택 및 팀 최종 문안 검토.
- 최종 빈칸 반영 후 저장·페이지 확인.
- 홈페이지 로그인, 업로드 조건 확인, 실제 제출 및 접수 증빙 보관.

검토본 작성은 완료했지만 서류 완비·온라인 접수는 미완료다. 사용자 직접 채택은 `기획/채택안_Agent설계.md`, 본문은 `기획/제출제안서_원고.md`를 기준으로 한다.
