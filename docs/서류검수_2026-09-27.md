- 원본 `자료/공식/02_참가신청서.hwp`를 보존하고 별도 HWP와 PDF를 작성했다.
- 최신 파일은 `private/제출준비/LG_AX_참가신청서_사용예시3종.hwp` 및 같은 이름의 PDF다. 기존 검토본은 이전 버전으로 보존한다.
- 전체 11쪽: 신청서 1, 제안서 8(2~9쪽), 동의서 1, 서약서 1. 공식 제안서 10쪽 제한 이내다.
- 공식 6항목을 유지하고 파란 작성 안내를 제거했다. 각 항목을 독립 페이지에 배치하고 4번 항목은 사용 예시마다 한 페이지씩 3쪽으로 구성했다.
- Theme A, 팀명 **키친에서치킨먹기**, 팀장·학년·학과·연락처·세 명의 학번을 반영했다. 학번 값은 사용자 직접 제공 또는 사용자가 지정한 데이터통신 과제의 이름과 학번을 대조해 확인했다.
- 개인정보·서명·작성본·중간본·페이지 이미지·파일 해시는 Git 제외 `private/`에만 보관한다.

## 시각자료 수정

1. 2쪽: 누가 어떤 자료를 넣어 어떤 기획안을 받는지 보여주는 개요.
2. 4쪽: 불편 정리 → 기존 기능 대조 → 콘셉트 작성 → 중복·근거 검사와 수정의 작동 방식.
3. 5쪽: 냉장고 청소의 제품 구조 개선. 구획별 탈착 트레이 콘셉트와 냉장고 선형 도식.
4. 6쪽: 식기세척기 적재의 안내 서비스 기획. 식기 조합별 배치 가이드와 사용 흐름.
5. 7쪽: 전자레인지 반복 설정의 기능 중복 검사. 이미 있는 설정 저장 기능을 재제안하지 않고 추가 확인할 질문을 작성.

사용자 요청으로 비교 평가 계획 이미지를 제거하고 그림 위의 긴 메타 주석을 없앴다. 합성 입력과 향후 구현 범위는 본문에서 설명한다. 일정은 추진방향 본문으로 정리했다. IBM 기술 도표와 Carbon의 중립색·정보 계층 원칙을 참고한 300 dpi 도식이며 원본 이미지나 실제 제품 화면을 복제하지 않았다. 공개 그림과 참고 기록은 `기획/시각자료/`, 생성 코드는 `scripts/build_proposal_visuals.py`다.

## 검수 결과

1. 한글 2022에서 HWPML을 읽어 native HWP 저장 및 PDF 내보내기를 완료했다.
2. 저장된 HWP OLE 컨테이너와 압축 본문을 다시 읽어 6항목·팀명·세 명의 학번·제공 연락처·안내 삭제를 확인했다.
3. 최종 PDF 11쪽 전부를 렌더링했다. 새 사용 예시 3쪽·서명 2쪽을 직접 시각 검토하고, 나머지 6쪽은 이전에 시각 검수한 렌더와 파일 해시까지 동일함을 확인했다. 빈 페이지, 그림·글자 잘림, 표 밖으로 넘친 내용이 없었다. 그림 5장과 신청서 팀명·학번을 확인했다.
4. 서로 다른 손글씨 3개를 원본 `(서명/인)` 위 9곳에 배치했다. 사용자 제공 사진에 맞춘 기존 필체와 굵기 보정을 유지했다.
5. 동의·서약의 원본 주요 본문 16개 구절과 서명 안내를 보존했다. 개인정보·초상권 동의 선택은 아직 하지 않았다.
6. 공식 HWP 원본의 Git blob 해시가 HEAD와 일치한다. 다른 프로젝트 파일은 학번 확인을 위해 읽기만 했다.
