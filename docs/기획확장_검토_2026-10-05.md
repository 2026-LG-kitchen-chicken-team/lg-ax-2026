# 호스트 LLM·웹 작업실·리뷰 동향 분석 검토

확인일: 2026-10-05 KST. 직접 사용자 아이디어를 검토한 문서이며 **새 기능 채택·배정·구현 완료가 아니다.** 기본 출품 주제와 신청서 전체 구현 우선순위는 유지한다. 사용자의 후속 정정은 “채팅 안 뿐만 아니라 웹에서도 보여주는거임”이다.

## 판단

강한 ChatGPT/Claude가 요청 해석·후속 질문·가설·콘셉트 해석을 맡고 우리 서비스가 버전이 고정된 자료 조회·집계·근거 연결·조건 검사·저장·변경 이력을 제공하는 방향은 현재 상품기획 Agent의 가치와 맞는다. 리뷰 요약을 또 다른 LLM에 보내 비슷한 답을 받는 것만으로 효과를 설명하기는 어렵다. 같은 자료/결과를 웹과 채팅에서 이어서 사용하고, 판단의 근거와 수정 결과를 남기는 것이 구체적 사용 이유다. 호스트에서 제안한 내용도 검사 없이 정식 판단 결과로 저장하지 않는다.

월별/계절별/연도별 리뷰 분석은 구현 가능한 신규 확장이다. 이를 그래프에서 끝내지 않고 **패턴 선택→원문 확인→해당 모델의 기존 기능 대조→잔여 불편→콘셉트/요구사항→변경 조건 재검토**로 연결하면 출품 주제에 기여한다. 실제 계절성·판매량을 입증하는 문제는 집계 프로그램 구현과 별도다.

## 기존 제안과 새 확장의 경계

| 내용 | 현재 범위/증거 | 남은 것 |
|---|---|---|

| 조건/자료 변경, 원문·자료 버전·수정 이력 | 제출 원고와 작업실 규격 | 원격 호스트와 실제 웹 화면 통합 |
| 웹과 MCP의 같은 프로젝트/실행 조회 | 개발 구조에 포함. 10/5 TS→API→실제 Qwen3:8B 세 Skill→저장→MCP 동일 snapshot을 실행 | 실제 호스트의 개인 작업실 인증/호출·화면 검수 |

근거: `기획/제출제안서_원고.md`의 활용정보/차별성/추진방향, `기획/채택안_Agent설계.md`, `docs/pm/workspace-planning.md`, `packages/contracts/schemas/lgax.schema.json`의 Review. 초기 설계표에는 date가 있지만 현재 Review 계약은 날짜가 없고 `additionalProperties:false`이다. 날짜를 임의로 덧붙이는 화면 개발만으로 통합되지 않으므로 PM 계약 변경/소비자 검수 절차가 필요하다.

## 시너지의 구체적 사용 흐름 (제안)

예시 요청: “내 냉장고 기획 작업실에서 여름의 냄새·청소 불편을 확인하고, 이미 있는 기능을 제외해 콘셉트 두 개를 검토해줘.” 이 패턴이 실제로 존재한다는 주장이 아니라 시연 입력 예시다.

1. 호스트 LLM이 사용자에게 프로젝트/기간/제품 범위를 확인하고 인증된 작업실을 조회한다.
2. 서비스가 같은 자료 버전에서 전체 리뷰 수, 해당 불편을 언급한 리뷰 수·비율, 모델별 집계와 관련 근거 ID를 계산한다. LLM이 건수를 추측하지 않는다.
3. 웹과 채팅 UI가 같은 analysis ID/필터/자료 버전의 그래프를 표시한다. 선택한 구간에서 원문을 열 수 있다. 호스트별 UI 차이가 있어도 숫자·근거·판정은 같다.
4. 호스트/판단 Agent가 패턴의 가능한 원인을 가설로 설명하고 기능 대조·검사를 호출한다. 근거에서 확인한 사실과 해석/가정을 분리한다.
5. 검토할 콘셉트와 요구사항을 저장한다. 웹에서 선택한 후보/제외 조건을 채팅에서도 확인하고, 채팅의 변경 요청은 새 run으로 만들어 웹 이력에 연결한다.

개인 작업실과 사용자 인증 principal을 서버에서 확인한다. 동일 사용자의 웹/채팅 권한·project/run/자료 버전을 연결하고, 다른 사용자의 프로젝트나 전체 DB를 모델에 노출하지 않는다. 반복 대규모 집계·전체 리뷰 재전송을 피하려면 동일 자료 해시/필터의 집계 캐시, 요약과 페이지별 원문 조회, 변경 영향 범위만 재분석하는 경로를 검증할 수 있다. 공개 모델은 OCR·임베딩·대량 리뷰 구조화 등에 활용하고, 높은 품질의 호스트 판단과 같은 해석을 반복하는 내부 모델 호출은 필요 여부를 비교한다. 성능·토큰 절감은 실제 전체 호출/재시도 측정 전 확정하지 않는다.

## 양쪽 화면 구현 가능성

웹은 공통 API 결과를 받아 React 차트와 근거·후보·이력을 표시한다. 채팅은 MCP 도구 응답의 구조화 데이터에 MCP Apps UI 리소스를 연결하는 방식으로 같은 분석을 표시할 수 있다. **MCP 연결만으로 기존 웹 전체 화면이 자동 표시되지는 않는다.** 공통 차트/결과 컴포넌트와 호스트별 연결·인증/보안·실제 호출 검사가 필요하다. 도구는 UI가 없는 호스트에서도 결과를 반환해야 한다. 그래프를 그리는 데 이미지 생성 모델을 필수로 넣을 필요는 없다.

2026-10-05 공식 자료 확인:

- [OpenAI: MCP 서버 UI](https://developers.openai.com/plugins/build/chatgpt-ui) — 선택 도구의 UI 리소스·MCP Apps bridge·구조화 결과, UI 없는 호출도 유지.
- [Claude: interactive connectors](https://support.claude.com/en/articles/13454812-use-interactive-connectors-in-claude) — 대화 안의 인터랙티브 앱, 실제 연결/활성 및 추가 테스트 필요.
- [MCP: 공식 UI 확장](https://blog.modelcontextprotocol.io/posts/2026-01-26-mcp-apps/) — 호환 호스트의 차트·폼·대시보드 렌더링 구조.

공식 지원은 우리 플러그인이 계정 안에서 이미 실행됐다는 증거가 아니다. 현재 구현/연결 기록을 별도로 확인한다. 광고의 “힉스필드/아스트라”가 가리키는 정확한 제품/기능은 사용자 링크가 없으므로 동일 구조·품질이라고 추정하지 않는다.

## 데이터와 통계 해석

최소 필드: 리뷰 ID·원문·게시일·모델·제품군·출처·수집 범위/시점·실자료/합성 구분. 게시일은 구매일/사용일과 다를 수 있다. 날짜 미상은 별도 그룹으로 보관하며 LLM이 생성한 날짜를 관측값으로 채우지 않는다. 동일 리뷰·반복 수집을 중복 집계하지 않고, 한 리뷰가 여러 주제를 가지는 경우 집계 규칙을 명시한다.

전체 리뷰 수와 특정 불편의 건수/비율을 함께 보여줘야 한다. 표본이 적거나 기간이 빠진 그래프를 계절성으로 확정하지 않는다. 여러 해를 비교하는 실증에는 비교 가능한 반복 기간·제품/출시/판매채널 변화와 자료 확보가 필요하다. 판매량·시장 수요는 리뷰 수만으로 대체하지 않는다. 30~50개 합성 리뷰는 필터·집계·오류 처리와 기획 연결의 동작 시연이며 실제 시장 동향의 증거가 아니다.

에어컨은 사용자의 이해를 돕는 비유로 기록한다. 현재 Theme A 키친 출품의 실제 대표 시연은 냉장고·식기세척기·전자레인지로 유지하는 것이 범위에 맞다. 여러 제품의 실제 판단 지원과 제조 기능 용어/제약 검증을 완료했다고 확대하지 않는다.

## 난도·우선순위

| 업무 | 난도 판단 | 판단 이유 |
|---|---|---|
| 한 제품·날짜가 있는 샘플의 월별 집계와 웹 그래프 | 낮음~중간 | 계산은 단순. 계약/중복/날짜누락·분모 처리가 필요 |
| 그래프 구간→원문→기능 대조→콘셉트 연결 | 중간 | 기존 검색·판단 코어를 재사용하되 근거/범위/이력 통합 필요 |
| 같은 개인 작업실의 웹↔호스트 변경/저장 | 중간~높음 | 인증·권한·동시 변경·오래된 run·중복 요청·원격 노출 범위 확인 필요 |
| ChatGPT·Claude 두 호스트의 인터랙티브 UI | 중간 | 공통 표준 활용 가능, 두 실제 계정의 UI·도구 호출·상태 연결은 별도 |
| 실제 여러 해·여러 제품 계절성/판매 예측 | 높음 | 코드보다 비교 가능한 실자료 확보·해석/평가 부담 |

지금은 결합 방식과 출력/도구 계약을 설계할 단계다. 현재 제외 조건 위반과 실제 웹 판단 연결을 먼저 해결한다. 제출까지 선택할 최소 확장 후보는 **한 키친 제품의 날짜 있는 자료팩 + 월별 건수/비율 그래프 + 선택 근거로 기존 기획 흐름 실행 + 웹/한 호스트에서 같은 run 확인**이다. 나머지 호스트/연도/제품 확장은 초기 완주 뒤 실제 검증 여력에 따라 정한다. 신청서 전체 기능을 새 차트로 대체하지 않는다.

일정 추정/수상 가능성 확정은 하지 않는다. 10/6 컨설팅에서 실제 기획자의 동향 분석 빈도/요구 자료·대조 결과 형태를 질문하고, 10/20 제출 전에 같은 입력의 강한 일반 LLM 단독과 자료+도구+검사/이력을 결합한 흐름을 비교해야 가치가 검증된다.
