## 검증·초대

- GitHub `updateProjectV2Collaborators`에서 세 계정을 READER로 변경한 뒤 실제 Manage access 화면을 새로고침하여 세 명 모두 Role: Read임을 확인했다.
- 저장소 collaborators API에서 정이량 Admin, 황대겸/최길웅 Write가 유지되는 것을 확인했다. 신진하는 수락 전이므로 저장소 접근은 아직 없다.
- 신진하의 9/27 초대는 API의 expired=true였다. 해당 만료 초대만 삭제하고 10/4 16:50:55 KST 새 Write 초대를 발송했다. 새 invitations API에서 ginaginaring/write/expired=false를 확인했다.
- 신진하는 자신의 GitHub 계정으로 [저장소 초대 수락](https://github.com/jeongiryang/lg-ax-2026/invitations)을 해야 한다. 발송을 수락·작업 착수로 기록하지 않는다.
- 화면 증거: `private/운영증빙/GitHub_Project_조회전용_2026-10-04.jpg`. 개인 문서/비밀키를 공유하지 않았다.
- [GitHub 공식 권한 안내](https://docs.github.com/en/issues/planning-and-tracking-with-projects/managing-your-project/managing-access-to-your-projects): Project Read는 조회 전용이며 저장소 권한과 별도로 관리한다.

신청서 요구·구현 완료 상태는 이번 운영 변경으로 바꾸지 않는다. 초기 Done2/참가작31요구 verified0 및 PM 두 과제의 통합 의존 대기를 유지한다.
