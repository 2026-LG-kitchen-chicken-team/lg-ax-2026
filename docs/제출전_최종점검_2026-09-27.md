## 발견해 수정한 내용

1. 사용자에게 이메일·참가자격·전원 동의 여부를 확인받아 빈칸과 동의 선택을 채웠다. 실제 값은 공개 기록에 넣지 않았다.
2. 참고자료 목록을 기대효과 뒤에서 공식 양식의 **활용정보** 항목으로 옮겼다.
3. 기존 기능이 있다는 사실을 고객 불편이 해결됐다는 결론과 구분했다. 전자레인지 예시는 중복 후보를 제외한 후 사용 과정의 불편을 추가 확인하도록 설명했다.
4. 도표의 질문을 ‘저장 기능을 알고도 쓰지 않는 이유’에서 ‘알고 사용해 봤는가’로 바꿔 사용자 상황을 단정하지 않도록 했다.
5. 근거가 부족해도 콘셉트 2~3개를 억지로 생성하게 되는 조건을 없앴다. 본문·도표·설계를 ‘타당한 콘셉트 최대 3개, 근거 부족 시 보류’로 통일했다.
6. 추진방향에 인용 정확성·모델 연결 오류·중복·수정 시간·지연·비용 등 평가 항목과 기획 회의 자료로 연결하는 도입 방향을 보완했다. 비교 평가 이미지는 복구하지 않았다.

## 남은 확인과 완료 조건

- **팀 최종 검토:** 최신 제안서와 참가 서약 내용을 팀 전원이 검토했는지는 별도 완료 근거가 없다. 서명 이미지 배치 승인과 최신 내용 검토를 구분한다. 원본 서약의 직접 창작·권리 준수·표절 및 대리 작성 금지 문구를 보존했으며, 별도로 확인되지 않은 생성형 AI 보조 도구 세부 규칙을 허용 또는 금지로 단정하지 않는다.
- **업로드 조건:** 공개 신청 페이지는 로그인 전용 안내를 표시한다. 로그인 후 첨부칸의 허용 확장자·파일 개수·용량·추가 필수 입력을 확인해야 한다. 공고의 HWP 요건은 확인했지만 실제 첨부 위젯의 조건까지 확인한 것은 아니다.
- **실제 제출:** 신청 완료 화면·접수번호·완료 시각 등 증빙은 아직 없다. 서류 검수 완료를 접수 완료로 기록하지 않는다.
