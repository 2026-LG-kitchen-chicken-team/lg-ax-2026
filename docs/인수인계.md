# LG AX 작업 재개 입구

[문서 정본·작성 위치](README.md)에서 필요한 업무 문서만 선택한다. 이 파일은 현재 재개 순서를 안내하며, 실행 횟수·PR 인수·모델 품질·담당별 진척을 다시 집계하지 않는다.

**시작 순서**

1. 최신 `AGENTS.md` 또는 `CLAUDE.md`와 [공식 요건](대회요건.md)을 읽고 현재 사용자의 지시·담당자를 확인한다. 승인된 자기 사서함에서 LG 작업 관련 메일과 선행 협의를 먼저 점검한다. 조회 실패는 기록하며 다른 팀원의 계정이나 비밀을 사용하지 않는다.
2. [PM 현재 배정](pm/현재배정.md), [수동 운영](pm/manual-work-20261006.md), [운영 Issue #28](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-2026/issues/28), 관련 Issue·PR·[조직 Project](https://github.com/orgs/2026-LG-kitchen-chicken-team/projects/1)를 대조한다. 자동화는 새 사용자 ON 지시가 있기 전 OFF를 유지한다.
3. [개인 기록 규칙](작업기록/README.md)에 따라 자신의 작업기록·작업근거 README에서 최신 재개 요약과 필요한 상세 기록을 읽는다. 타팀 결과를 소비하면 해당 작성자의 관련 요약·원문 근거를 먼저 확인한다.
4. [개발 실행 안내](bootstrap/README.md)와 [phase2 하네스](../harness/phase2/README.md)의 작업 패킷·계약·완료 조건을 읽고 자기 branch/worktree에서 이어간다. 제품 실행은 승인된 격리 환경을 사용하며 사전 검사와 실제 실행·통합 완료를 구분한다.

**내용별 정본**

- 신청한 구현 범위: [제출 원고](../기획/제출제안서_원고.md), [채택 설계](../기획/채택안_Agent설계.md), [31개 요구사항](../harness/phase2/requirements.json). 기획 문서의 초기 설계 필드를 현재 구현 계약으로 사용하지 않는다.
- 현재 코드·판단 계약: [공통 JSON Schema](../packages/contracts/schemas/lgax.schema.json), [PM 작업실 규격](pm/workspace.md), [코어 판단 규격](core/judgement-contract.md). 실제 모델/자료 버전·품질·실패는 각 실행 근거를 조회한다.
- 일정·지원 안내: [10/7 컨설팅](컨설팅_2026-10-07.md), [2차 제출·평가](2차제출_평가안내_2026-10-03.md), [API 지원 조건](LLM_API지원_2026-10-06.md). 사용자 보고·공식 원문·직접 확인을 구분한다.
- 검수·제출 재개: [진행 체크리스트](진행체크리스트.md), [독립 평가](pm/evaluation.md), [최종 제출](pm/submission.md). 실제 합격·품질·동기화·제출은 해당 근거 없이 완료로 바꾸지 않는다.

**과거 내용과 기존 링크**

이전 본문 전체는 원바이트 [불변 원문](history/project/20261006/originals/docs/인수인계.md)에 보존했다. [이관 설명·manifest](history/project/20261006/README.md)와 [원래 위치 기준 링크 안내](history/project/20261006/links.md)를 따른다. 아래 과거 제목은 기존 anchor를 유지하는 목차이며, 당시의 ‘현재·최신·ON’은 새 작업 지시가 아니다. 새 수행·진척은 이 목차에 누적하지 않는다.
