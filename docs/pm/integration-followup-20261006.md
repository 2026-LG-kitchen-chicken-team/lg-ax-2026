## 문서 사용 규칙의 재구성

[문서 허브](../README.md)에서 목적별 정본을 찾는다. root README·인수인계·체크리스트·현재배정·harness README는 짧은 입구다. 기존5개 원문161,753바이트·제목104·링크169는 [역사 보관/manifest](../history/project/20261006/README.md)에 보존했고 개인 기록330개는 다시 이동하지 않았다. 새 상세 작업은 `docs/작업기록/{성명}/{날짜}/{ID}.md`, 근거는 `docs/작업근거/{성명}/{날짜}/{ID}.md`, 원 실행은 `evals/`, 입력은 `data/`, 민감정보는 `private/`에 둔다.

AGENTS.md와 CLAUDE.md는 동일한 정본·작성 위치·이관 검사를 명시한다. CI의 `check_document_navigation.py`는 원문/anchor/링크를 검사한다. `--check-protected`는 이관 당시 한 번의 보호 파일 대조이며 이후 정상 owner 기록 갱신을 금지하지 않는다. 날짜별 상태·모델 품질·main SHA를 여러 입구에 복사하지 않는다.

새 개인 상세 경로와 보고 서비스의 허용 URL은 구분한다. 현재 서비스의 보고 링크에는 고정40자리 commit의 기존 `docs/작업기록/{성명}.md`·`docs/작업근거/{성명}.md` 호환 목차를 사용하고, 그 목차에서 이름/날짜/ID 상세 파일로 이동한다. 직접 상세 URL의422를 회피하려고 새 기록을 누적문으로 되돌리거나 보고를 완료했다고 표시하지 않는다. PR187의 `record-proposals`는 작성자가 보존한 제안 원문이며 PM이 개인 수행 기록으로 대신 작성하지 않는다.
