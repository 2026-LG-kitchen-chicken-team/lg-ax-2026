## 보여줄 순서 (실제 실행 결과 확보 후)

| 순서 | 기획자가 하는 일 | Agent 개입 | 확인할 증거 |
|---|---|---|---|
| 정상 기획 | 제품·사용 상황·개선 목표 입력 | 리뷰 불편 추출 → 설명서의 기능·조건 대조 → 잔여 불편의 콘셉트 → 인용·중복·의미 검사 | 같은 모델/문서/자료와 새 run ID, 실제 호출/출력 |
| 조건 변경 | 자동 세척 장치 등 제외 조건 추가 | 원 실행을 보존하고 새 판단, 위반 발견 시 공유 예산 최대 2회 수정 또는 보류 | 이전/새 run ID·수정 횟수·제외 조건 반영 |
| 근거 부족 | 판단에 필요한 자료가 없는 요청 | 없는 사실을 만들어내지 않고 질문·보류 또는 명시 오류 | 누락 범위·실제 이유·추가 요청 |
| 웹/MCP 연결 | 채팅에서 만든 작업을 웹에서 검토 | 같은 실행/원문 조회·후보 검토·변경 이력 | 같은 project/run ID와 해시 |

냉장고·식기세척기·전자레인지 세 예시는 제출 아이디어의 서로 다른 구조 개선·안내 서비스·기능 중복 제외를 설명한다. 준비된 정상 출력이 없으면 화면 저장·오류 처리만 보여주고 정상 Agent 완주로 소개하지 않는다. 합성자료 동작 검증과 실제 수요·제품 설계 가능성은 구분한다.

## 기존 LLM에 추가하는 것 (30초)

자료/모델/문서 버전을 고정한 조회, 리뷰와 설명서의 근거 대조, 기존 기능 중복과 조건 검사, 제한된 수정·보류, 재조회 가능한 실행 이력이다. LLM의 언어 능력은 그대로 활용하며 웹은 긴 근거와 후보 비교를 검토하는 작업실이다. 현재 비교 실측이 없으므로 일반 LLM보다 정확하다거나 토큰을 절감했다고 주장하지 않는다.
