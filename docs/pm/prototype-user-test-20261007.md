# 실제 후기 기획 프로토타입 R5: WEB 사용 점검

기록 ID: `정이량-20261007-R5-WEB-001`. 담당자는 PM 정이량, 수행자는 PM 보조 AI `/root/remote_audit`다. 이 문서는 새 실행 화면과 발표·영상·소스 초안을 검수할 준비 기록이다. 사용자 테스트 완료나 최종 제출을 뜻하지 않는다. R4 원 기록과 실패를 보존한다.

## 지시와 해석

사용자의 직접 지시는 **“모두 진행해”**다. PM의 이번 배정 발췌는 “WEB 신규실행→로딩→품질실패/보류→실제추천/선택→조건변경→근거/내보내기 경로검토/필요fix”, “새모델0/배포0/외부게시0, localcommit 후 루트검수요청”이다.

보조 AI는 이를 다음처럼 해석했다. 새 자료에서 등록된 실제 SKU와 자료 버전을 그대로 사용하고, 기존 실행은 원 버전에 묶인 기록으로 보존한다. 화면이 응답 대기를 실제 Agent 단계로 추정하거나 실패·보류를 추천 성공으로 표시해서는 안 된다. UI 회귀 검증과 실제 운영·실모델 품질 확인은 별도 증거로 남긴다. API/Core·공유 계약·운영 정책·다른 팀원의 개인 기록은 수정하지 않는다.

## 첫 점검과 예정 행동

현재 live hero는 실제 자료 종류와 상관없이 “시연용 합성자료”를 표시한다. 또한 동일 프로젝트 판정은 제품군·모델만 비교하고 자료 버전을 비교하지 않아, 같은 SKU의 새 자료가 들어오면 옛 프로젝트에 새 버전 실행을 요청할 수 있다. 자료 출처/버전을 화면에 표시하고, 버전이 바뀌면 원 프로젝트를 이어 쓰지 않고 새 프로젝트로 저장하도록 수정한다.

신규 SKU 선택 → 요청 한 번 전송 → 응답 대기 → 실패/보류 표시 → 기록 조회·내보내기, 같은 자료의 조건 변경 계보를 격리된 UI 시험으로 확인한다. 테스트 입력은 명시적인 합성 계약 예시이며 실제 후기를 수집하거나 모델을 호출하지 않는다. 실제 추천 후보의 선택·조건 변경은 PM이 새 실제 실행을 인수한 뒤 같은 run ID/자료 해시로 확인해야 한다.

제품 코드의 테스트·빌드는 호스트에서 실행하지 않는다. Git commit을 고정한 소스를 읽기 전용으로 마운트하고 zero-auth/network-none Docker에서 기존 잠금 의존성으로 실행한다. 실패한 시도는 새 성공으로 덮어 쓰지 않는다. 완료 조건은 코드/자료 버전 경계의 회귀 시험, 검토 가능한 로컬 commit, PM의 실제 운영 후속 점검표와 제출 초안 인계다.

## 실제 사용자 점검표

아래의 “대기”는 완료되지 않았다는 뜻이다. PM이 직접 사용자에게 과제를 준 뒤 관찰 결과와 원 run ID를 채운다. 테스트 통과 수를 사용성·기획 효과 수치로 재사용하지 않는다.

| 과제 | 통과할 관찰 | 필요한 증거 | 현재 상태 |
|---|---|---|---|
| 실제 제품과 자료 선택 | 공개/합성/혼합 출처와 버전, 실제 SKU·문서 버전을 구분함 | 최종 R5 dataset pin과 화면 | 최종 자료 인계 대기 |
| 신규 기획 요청 | 고객·상황·개선점·제외 조건을 입력하고 한 번 실행함 | 요청 원문, project/run ID, API 저장 | 신규 API 연결 대기 |
| 오래 걸리는 실행 | 대기 시간과 자동 재전송 없음이 보이고, 단계 완료를 추정하지 않음 | 실제 응답 대기 화면·총 지연 | 실제 실행 대기 |
| 실패·보류 검토 | 후보를 임의 선택하지 않고 질문/위반/거절 후보를 원문과 함께 확인함 | 실제 failed/held run과 JSON/MD | 기존 R4 경로 확인, R5 대기 |
| 실제 추천 검토·선택 | 채택된 후보의 요구사항·가정·불편 Gap·정확한 모델 원문을 연결함 | 실제 completed와 독립 품질 검토 | 미검증 |
| 조건 변경 | 원 요청과 선택을 보존하고 새 run이 이전 run ID를 가리킴 | 변경 전후 요청·run·자료 SHA | 신규 실행 대기 |
| 내보내기 | 선택한 동일 run의 상태·근거 위치·버전·질문·미해결이 JSON/MD와 일치함 | 원 파일 SHA와 UI 비교 | 기존 R4 경로 확인, R5 대기 |
| 업무 효과 확인 | 수작업/단일 프롬프트와 같은 자료·모델에서 비교하며 모든 재시도를 포함함 | 독립 검토·실측 시간/토큰 | 미측정 |

## 발표·영상·소스 초안 인계

기존 [발표와 시연 준비](발표와시연_준비.md), [소스 제출 초안](submission.md)을 원본으로 유지한다. 이번 촬영용 구성은 다음과 같다. 모두 자료와 실제 실행을 인수한 뒤 촬영하며, 예상 콘셉트를 만들어 성공 화면으로 대체하지 않는다.

| 순서 | 촬영할 장면 | 말할 수 있는 주장 | 아직 말할 수 없는 주장 |
|---|---|---|---|
| 1 | 원 후기·매뉴얼 위치, SKU, 자료 pin | 이 범위의 공개 원문을 사용함 | 대표 표본·시장 수요 확정 |
| 2 | 입력·실행 클릭·대기 시간 | 요청과 실행을 한 번 저장하고 실제 응답을 기다림 | 모든 단계의 실시간 진행률 |
| 3 | 실제 실패/보류와 질문, 거절 후보 | 검사 결과와 부족한 근거를 보존하고 선택을 막음 | 완성된 기획 품질 달성 |
| 4 | 실제로 채택된 후보가 생긴 경우 원문/요구사항 검토 | 해당 run의 결과와 판단 근거 | 아직 없는 추천 성공·독립 효과 |
| 5 | 조건 변경·이전 run 연결·JSON/MD | 같은 자료에서 변경 기록을 보존함 | OS 재부팅/계정 안 MCP 발견 |
| 6 | 한계·재현 절차·같은 commit의 ZIP 초안 | 검증한 버전과 실행 범위 | 최종 제출·접수 완료 |

발표 첫 초안에는 1~3과 5~6을 넣고, 4는 실제 채택 및 독립 품질 검토 후에만 추가한다. 효과·토큰 절감·수정 시간은 측정하지 않은 칸을 비워 둔다. R4의 15회/91,587토큰은 보존된 3사례 실험 기록이며 신규 실험의 비용이나 절감 효과가 아니다.

소스 초안은 최종 촬영 commit을 정한 뒤 기존 패키저를 격리된 환경에서 실행한다. commit/전체 tracked 파일/Git blob/파일 SHA/ZIP SHA와 깨끗한 해제 재실행을 확인하고 `draft=true`, `submission_ready=false`를 유지한다. private DB·실제 토큰·접수/신청 개인정보가 들어가지 않았는지 검수한다. 이 WEB branch 자체를 최종 촬영본/제출본으로 포장하지 않는다. 최종 제출·메일 발송·외부 게시를 이번 배정으로 수행하지 않는다.
