# 발표와 시연의 준비 순서

이 문서는 10/4 PM이 작성한 구성 초안이다. 실제 평가 수치·완성 결과 화면·시연 영상을 대신하지 않는다. [2차 안내](../2차제출_평가안내_2026-10-03.md)의 기본 배점과 제출 신청서의 세 사례를 따른다. 기존 20쪽 이내를 우선 유지하고 최종 분량은 후속 안내를 확인한다.

## 발표 구성 초안

| 순서 | 전달할 내용 | 넣을 실제 증거 | 대응 평가 |
|---|---|---|---|
| 1 | 상품기획자가 리뷰와 기능 설명을 함께 읽어도 해결되지 않은 불편을 찾기 어려움 | 사용 대상/작업 전 과정, 사례 원문과 제품·문서 버전 | 고객 문제 20 |
| 2 | 익숙한 ChatGPT/Claude에 자료 조회·검사·기록 도구를 붙이고 웹에서 근거와 후보를 검토함 | 두 호스트 실제 도구 호출, 공통 ID와 웹의 동일 기록 | Agent 구조 20 |
| 3 | 입력 → 근거 조회 → 불편/기능 대조 → 후보/요구사항 → 검사 → 수정/보류 | 실제 각 Skill 입출력과 Tool 기록, 원문 인용/버전 | 구조 20·핵심 기능 30 |
| 4 | 세 제품 사용 예시와 조건이 바뀐 뒤 다시 판단하는 과정 | 아래 실제 시연 입력/출력과 변경 전후 run ID | 시연 10·핵심 기능 30 |
| 5 | 정보 부족·다른 모델·상충 의견·기능 중복을 처리함 | 독립 6유형의 원본 결과, 실패/보류/수정 과정 | 핵심 기능 30 |
| 6 | 같은 모델·자료·요청으로 강한 단일 프롬프트와 비교함 | 방식 이름을 가린 검토·실측 토큰/지연/비용, 미측정은 공란 | 고객 문제 20·효과 20 |
| 7 | 적용할 업무·현재 한계·다음 확장 | 재현 코드·5Skill·자료/모델 라이선스, 실제 확인 범위 | 효과 20 |

초기 합성 조회 3도구와 모델 JSON 실험은 개발 기반의 증거다. 위 3~6의 완성 판단/효과 증거로 재사용하지 않는다. 토큰 절감은 모든 호출·재시도를 포함한 실측 뒤 주장한다.

## 실제 촬영 시나리오

| 사례 | 촬영할 기획 요청과 변화 | 보여줄 Agent 개입 | 촬영 완료 조건 |
|---|---|---|---|
| 냉장고 구조 개선 | 청소할 때 식품을 모두 옮기는 불편. 선반 분리 기능 확인 후 구획별 처리 필요를 검토 | 리뷰/기능을 대조해 남은 불편을 설명, 후보/가정/설계 요구를 생성, 새 자료에 같은 기능이 있으면 재검사 | 해당 자료를 실제 조회하고 후보/검사/변경 출력이 코드에서 재실행됨 |
| 식기세척기 안내 서비스 | 적재 방식 때문에 사용자가 혼란스러움. 설명서 안내와 상충 리뷰를 함께 검토 | 기존 안내의 범위와 남는 어려움을 구분, 안내 서비스 콘셉트·사용 흐름·요구사항을 제안, 과한 일반화는 보류/수정 | 근거 없는 성능·실기기 제어를 약속하지 않고 기획 결과/검토가 실제 생성됨 |
| 전자레인지 기능 중복 제외 | 반복 설정의 번거로움을 줄여 달라는 요청. 기존 저장/호출 기능을 확인하고 문서 버전 변경 | 이미 있는 기능을 신규 후보에서 제외, 미충족 조건/다른 대안을 검토, 변경 영향과 제외 사유를 기록 | 신규성 판단에 사용한 정확한 모델/버전·원문 및 재실행 결과를 확인함 |

예상 콘셉트를 정답으로 강제하지 않는다. 실제 자료와 검사를 거친 결과가 다르면 결과와 이유를 그대로 촬영한다. 기획자를 위한 제품·서비스 콘셉트/요구사항이며 제조 설계도나 실가전 제어 시뮬레이션이 아니다.

## 촬영·파일 고정

1. 코어·웹·다섯 Skill을 인수하고 전체 시나리오/오류 대응을 실제 실행한다.
2. 독립 평가의 원본 결과와 가린 검토를 고정한다. 효과/토큰/수정 시간 미측정 칸은 결과가 생길 때만 채운다.
3. 촬영 코드 commit·자료 SHA·모델 digest와 요청/run ID를 기록하고 그 commit에서 영상을 만든다.
4. 같은 commit의 소스 ZIP을 만들고 별도 깨끗한 환경에서 설치·실행한다. 발표/영상/코드 일치와 31요구 증거를 PM이 확인한다.
5. 제출 경로/시각/용량/영상 길이의 공식 안내를 확인하고 최종본을 제출한 뒤 접수 증빙을 비공개로 보관한다.
