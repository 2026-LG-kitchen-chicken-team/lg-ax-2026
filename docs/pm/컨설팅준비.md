# 선정팀 컨설팅 준비

10/4 기준 실제 시간은 미확정이다. 컨설팅 희망 시간표 제출은 10/2 사용자 보고이며 10/6 오전까지 시간 안내 예정이다. 원문은 [1차 선정 안내](../1차선정_2026-10-02.md), 제출 기준은 [2차 안내](../2차제출_평가안내_2026-10-03.md)를 따른다. 질문 목록은 팀 내부 준비이며 주최 측에 발송하지 않았다.

## 안내를 받으면 PM이 확인할 것

- 실제 날짜·시각·회의 링크·참석 조건을 팀장 황대겸과 확인한다. 받은 공지의 위치·확인일을 기록하고 Project/Notion 일정을 갱신한다.
- 정확한 10/20 제출 시각/경로·파일 용량·영상 길이·발표 분량·토큰 절감 가산점 반영 방식을 확인한다. 안내되지 않은 값을 임의로 고정하지 않는다.
- 최신 main과 사용자 채택안·31요구 대응표·현재 구현/미구현 목록을 준비한다. 개발 기반의 실제 조회 호출과 완성 상품기획 Agent를 구분해 설명한다.

## 우선 질문

| 질문 | 확인할 이유 | 답변 뒤 작업 |
|---|---|---|
| 상품기획자가 ChatGPT/Claude에 MCP를 연결하고 웹에서 근거/후보/이력을 검토하는 흐름이 Theme A의 Agent 수행 요건을 충족하는지? | 기존 LLM의 대화 능력에 자료·검사·기록 도구를 붙이는 가치와 역할을 설명 | 역할/시연 구성 보완, 답변을 공식 평가 해석과 구분해 기록 |
| 세 제품 합성 자료로 분석·대조·검사·수정을 실제 수행하고 공개 원문으로 추가 검증하는 구성에서 기대하는 증빙은? | 합성 동작 검증·실고객 수요/실제품 근거의 범위 확인 | 자료팩·독립 사례·현재 한계 표현 조정 |
| 정보 부족 보류·모델/버전 혼동·중복 제외·상충 의견을 실제 처리하는 장면을 어떻게 우선 보여주면 좋은지? | 핵심 Agent·Skill 점수를 기능 수보다 실제 판단과 오류 대응으로 입증 | 세 사례와 실패/변경 시연 순서 확정 |
| 같은 모델/자료의 강한 단일 프롬프트 비교와 모든 호출·재시도 토큰 측정은 어떤 방식으로 제시하면 되는지? | 효과·토큰 절감 가산점의 근거 범위 확인 | 독립 평가 조건·가린 검토·실측 발표 구성 확정 |

## 소개할 현재 상태

고객 불편과 기존 기능을 대조해 신규 제품·서비스 콘셉트/요구사항을 생성하고, 근거·중복·모델/버전을 검사해 수정/보류하는 기획 Agent다. 기존 LLM의 능력을 사용하면서 같은 자료 ID·검사·실행 기록을 여러 클라이언트에서 재사용하게 만드는 목적이다. 현재 공통 작업실/API·모델 호출·Skill 실행 틀은 검증했고 판단 코어·완성 웹·독립 성능 평가는 후속 개발이다. 완료된 것처럼 발표하지 않는다.

컨설팅 답변을 받으면 질문별 답변·출처·변경 결정·담당 Issue와 다음 행동을 PM 기록에 남긴다. 답변만으로 코드 완료/성능 검증/제출 완료 상태를 올리지 않는다.
