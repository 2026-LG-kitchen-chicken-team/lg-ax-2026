# 수동 공유 프로토타입 — 2026-10-08

사용자 지시: 링크를 가진 팀원이 사용할 수 있게 웹/API·LLM을 열고, 사용자의 종료 지시 전 시간 경과를 이유로 자동 종료하지 않는다. 범위는 프로토타입 제공이며 자동 Worker·예약 배정은 OFF를 유지한다.

배포 대상은 main eab85d4에 기반한 디자인 PR #275와 이번 공유 서버 후보다. 배포를 main 병합·판단 의미 품질 승인·부모 작업 Done으로 표시하지 않는다. 실제 공개 자료 10묶음을 사용하며 새 합성 리뷰는 만들지 않는다.

`scripts/serve_shared_research_prototype.py`는 별도 HTTPS 게이트웨이·브라우저별 서명된 editor 세션·독립 SQLite를 제공한다. 외부에는 정적 웹과 실제 자료 `/api/research/`만 노출한다. 기존 작업실·공개 MCP·PM/하네스 제어는 열지 않는다. 요청 출처/Host를 정확히 확인한 뒤 내부 기존 allowlist에 맞춰 전달하며 최신 사용자 지시의 생성/수리는 최대4건 실제 병렬 처리한다. 활동8건까지 접수하고 초과 실행은 순서대로 대기하며, HTTP202 뒤 소유자 전용 상태 조회로 대기/실행/완료/실패를 표시한다. 같은 브라우저 세션은 활동1건만 허용하고 POST를 자동 재전송하지 않는다. 이전 모델1건 제한은012 당시 기록으로 보존한다.

`scripts/start_shared_prototype_model.py`는 기존 고정 Qwen 27B 캐시·binary/digest를 확인하고 여유 있는 GPU3 전용 포트18875만 사용한다. 기존 Naru/GPU1·다른 팀원의 프로세스/자료는 변경하지 않는다. 초기 Ollama는 keep_alive=-1이고, 최신 텍스트 전용 llama.cpp는 항상 로드된 모델을 유지하며 종료 예약을 두지 않는다. 단일 요청의 기존4콜·출력4096·문맥16384는 유지한다. 최신4병렬 요청의 모델콜 응답 제한은 설정 상한내300초이며 서버 수명과 별개다. Ollama의 Qwen 계열 강제1 제한을 실험에서 확인하여 같은 고정 GGUF와 bundled binary를 사용한 native4슬롯·총문맥65536·KV분리 경로로 전환한다. 여유36,000MiB/낮은GPU사용률 시작 검사와 native 모델/별칭/4슬롯/문맥 검증을 적용하고 실제 성공은013/E060의실측으로판정한다.

서버·터널은 연구실의 사용자 서비스로 실행한다. RuntimeMaxSec=infinity, Restart=always이고 SSH/현재 AI 턴의 종료와 분리한다. 자동화 OFF는 개발/배정 Worker에 적용하며, 사용자가 직접 요청한 서빙 서비스의 생존/장애 재시작과 구분한다.

공유 연결은 사용자가 명시적으로 종료할 때 해당 전용 서비스 세 개만 정지한다. 하드웨어/네트워크 장애에는 중단될 수 있으며 현재 모델 캐시는 tmpfs라 연구실 재부팅 후 재확보가 필요하다. Cloudflare Quick Tunnel 주소는 프로세스가 새로 만들어지면 바뀔 수 있다. 기존 Tailscale 경로는 보존하며 새 포트 추가는 실제 권한 부족으로 적용하지 않았다.

완료 증거는 정이량의 날짜별 공유 서빙 작업/근거와 배포 receipt에 기록한다. 실제 모델과 독립 의미 검수는 구분하며 AI 초안은 원문 확인이 필요하다.

현재 공유 주소는 [프로토타입 열기](https://consumption-tied-mens-alleged.trycloudflare.com/)다. 자료 묶음과 원문을 선택하고 기획을 생성한다. 실제 후기4·설명서2의 공개 웹 모델 생성1건과 서비스 수명은 [고정 실행 근거](../../evals/pm-r9/20261008/shared-prototype/serving-proof.json), 개인 [E059](../작업근거/정이량/2026-10-08/정이량-E059-SHARED-PROTOTYPE.md)에서 확인한다. 쿠키 삭제/브라우저 변경은 새 독립 작업실이며 공유 기록의 자동 승계를 약속하지 않는다.

최신 실제 모델4병렬 변경·접수 상태와 소유자 격리/재시작 복구 근거는 [E060](../작업근거/정이량/2026-10-08/정이량-E060-PARALLEL-FOUR.md)과 [고정 실행 증거](../../evals/pm-r9/20261008/parallel-four/serving-proof.json)를 따른다. 큐의 추론 실행자는 사용자 요청 처리용 서버 구성이고 개발/배정 자동Worker와 별개다. 서버 중단 당시 실행 중이던 모델 요청은 불확정 실패로 남기며 자동 중복 생성하지 않는다.

실제4 동시 요청은 GPU3의 같은 모델·4슬롯에서 기획과 저장까지 완료했다. 최초 Ollama의 강제1과 native CUDA 라이브러리 경로 누락으로 생긴 CPU timeout은 별도로 보존했다. 최신 launcher는 CUDA backend 바이트 pin·격리된 라이브러리 경로·명시적 CUDA0를 적용하며 배포 readiness는 소유 모델 PID의 GPU3 적재까지 확인한다. 여섯 원문 표본에서 측정한 지연을 전체 요청의 보장 시간으로 확대하지 않는다.
