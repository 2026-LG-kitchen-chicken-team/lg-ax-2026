## 담당 AI가 보고할 내용

1. 자기 `docs/작업기록/{이름}.md`의 최신 재개 요약 및 새 지시 원문·해석·실제 수행을 갱신한다. 관련 `docs/작업근거/{이름}.md`에는 입력/출력·자료/모델 버전·실행/실패·해시와 한계를 연결한다.
2. 자기 Issue와 PR에 작업 ID·관련 요구 ID·완료한 범위·남은 조건·다음 행동·PM에게 요청하는 판단을 적는다. 재실행 명령과 원본 출력 위치를 첨부한다.
3. 기존 공통 계약/모델 클라이언트/Skill 연결은 [작업실](workspace.md)·[모델](model-adapters.md)·[Skill](skills.md)을 따른다. 가짜 성공 응답으로 미구현을 숨기지 않는다.
4. PM은 실제 증거와 코드를 검수하고 추가 작업 배정 또는 수정 요청을 내린다. 병합 commit에서 통합 확인한 뒤 전체 작업을 완료로 판정한다. 검수 대기에는 PM이 지정한 후속 작업을 진행한다.

## 자기보고·공식 승인·새 배정 안내

세 팀원의 Project 권한은 Read다. 자기 기록과 근거를 같은 전체 commit SHA로 commit·push한 뒤 자기 인증 계정으로 자기 담당 Issue에 보고한다.

```powershell
uv run python scripts/project_report.py status --member 신진하
uv run python scripts/project_report.py report P2-DATA-001 --status doing --summary "자료팩의 제품·문서 버전 연결을 작성 중" --next-action "근거 ID와 원문 위치 검사" --send --wait 60
```

허용 상태는 `doing`, `blocked`, `review_requested`다. blocked에는 `--reason`, 검수 요청에는 자기 main 대상의 열린 비초안 PR `--pr-url`을 넣는다. 외부 PM 관리 서비스의 ACCEPTED 수신 확인이 있어야 보드 반영을 확인한 것이다. 반영 범위는 `Status`·`팀원 보고`·`최근 보고`·`다음 행동`이며 정식 완료·담당/우선순위·기한은 바꾸지 않는다. 의존 대기 중 부분 작업도 보고하되 남은 의존을 기록한다.

공식 완료·의존 해제·확장 채택은 PM의 실제 검수와 근거, 검증한 배포 정책의 승인 스냅샷, 운영 Issue #28의 실제 PM `/lgax-sync` 승인으로 확인한다. main 파일 수정만으로 승인되지 않는다. PM은 검증한 정확한 현재 main 버전에서 `uv run python scripts/sync_github_phase2.py --apply`를 실행한다.

PM AI가 새 작업을 배정할 때 공용 배정 JSON·Issue 댓글·비공개 발송 대기를 만든 뒤 연결된 Gmail로 안내하고 실제 Sent 메타데이터를 기록한다. 배정/메일 필드도 PM만 갱신한다. 상시 메일 감시 daemon은 없다. [협업 절차](../협업체계.md)와 [정확한 CLI·서비스 안내](../../services/project_reports/README.md)를 따른다. 2026-10-04 실제 배포·PM 보고/거절 시험·세 안내 메일 SENT 대조를 확인했고 Project에 반영했다. 수신자 열람·작업 착수는 별도다. 웹 PR36/37은 PR42 통합 및 실제 병합 버전 검증으로 WEB001/002 완료가 확인됐다. 추가 PR40/41은 PR43으로 선행 코드를 병합·106시험/실HTTP2·빌드 검수했고 실제 후보 재실행·전체 Agent 완료와 구분한다. #25 [후속 배정](https://github.com/jeongiryang/lg-ax-2026/issues/25#issuecomment-5979237925)의 안내 메일1건도 실제 SENT 대조했다. 첫3건을 다시 발송하지 않았다.
