# PM 배정 조회·인수 입구

[문서 정본·작성 위치](../README.md) · [작업 재개](../인수인계.md) · [검수·제출 점검](../진행체크리스트.md)

이 파일은 **현재 지시·배정·실제 결과를 어디에서 대조할지** 안내한다. 날짜별 배정/인수의 전체 본문은 해당 업무 문서·Issue·원 근거에 둔다. 모델 품질·PR 상태·main/배포 버전·완료 횟수를 이 입구에 복사해 별도 정본으로 만들지 않는다. 자동화는 새 사용자 ON 지시 전 OFF를 유지한다.

**현재 작업을 확인하는 순서**

1. 최신 사용자/PM 지시와 `AGENTS.md` 또는 `CLAUDE.md`를 읽고 승인된 본인 사서함의 관련 메일·선행 협의를 먼저 확인한다.
2. [운영 Issue #28](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-2026/issues/28), [조직 Project](https://github.com/orgs/2026-LG-kitchen-chicken-team/projects/1), 담당 Issue·PR의 최신 지시·인증된 자기 보고·PM 인수 근거를 대조한다. 메일 발송·열람·실제 착수·완료는 각각 구분한다.
3. [phase2](../../harness/phase2/README.md)의 담당자 `next`와 작업 `packet`에서 요구사항·편집 영역·입출력·검사·의존·완료 조건을 확인한다. Ready/Doing/검수·병합·통합 상태는 현재 조회와 실행 근거로 확인하며 문서의 과거 수치로 판단하지 않는다.
4. 자기 `docs/작업기록/{성명}/README.md`와 `docs/작업근거/{성명}/README.md`의 최신 owner 요약·상세 링크를 읽는다. 타팀 결과를 사용할 때 작성자 원문·관련 고정 commit/근거를 읽고 아직 인수하지 않은 부분을 구분한다.

기본 역할은 새 배정의 세부 편집 허가를 대신하지 않는다. PM의 고정 작업지시에서 허용 경로·작은 인수 단위·공유 계약/의존을 확인하고, 경계가 겹치면 협의한다. 원 모델/테스트 실패·비용·예약·과거 자동 job을 삭제하거나 수동 결과의 성공으로 바꾸지 않는다.

**업무 지시·인수 정본**

최신 업무별 checkpoint를 PM이 이 구역에서 링크하고, 실제 수행 수치와 처분은 그 문서·Issue/PR·불변 근거에서 확인한다. 과거 R1/R2/R3나 ON 기록을 링크했다는 이유로 현재 지시로 자동 승격하지 않는다.
