# 리뷰 동향을 상품기획으로 연결하기

사용자 2026-10-06 직접 요청을 검토해 채택한 추가 개발 범위다. 원 신청서 31개 요구와 실제 3제품 실행·독립 평가를 우선 유지한다. 이 기능은 추가 기획 지원이며 기존 필수 요구의 완료를 대신하지 않는다.

## 기획자가 하는 일

1. 작업실에서 제품·모델·자료 범위와 기간을 고른다.
2. 월별/계절별 불편 비율과 표본 수를 함께 본다. 불편은 한 리뷰가 여러 주제에 해당할 수 있다.
3. 증가한 구간을 누르면 해당 리뷰 원문과 자료 위치로 내려간다.
4. 선택한 불편 묶음을 기존 기능과 대조하고 새 콘셉트·요구사항의 가설로 이어간다.
5. 웹에서 만든 작업실 범위·집계 ID를 ChatGPT/Claude의 MCP로 조회한다. 같은 결과·근거를 두 화면에서 이어 쓴다.

예: 여름철 냉장고 냄새 불편이 늘었는지 확인 → 표본과 원문 확인 → 설명서의 탈취/청소 기능과 대조 → 해결되지 않는 상황에 대한 서비스나 구조 개선 가설. 리뷰 수만으로 판매량·시장 수요 증가를 추정하지 않는다.

## 공통 입출력 초안 v1

- 입력: project_id, 제품군/model_id, 허용 자료/source_ids, 시작일/종료일, granularity(month/season/year), topic_ids. 작업실 권한을 통과한 자료만 사용한다.
- 리뷰 레코드: review_id, source_id, 원문/원문 위치, 제품 모델/문서 버전, source_kind, published_at(nullable), topic_ids, dedup_key, 분류 모델/revision(nullable). 날짜가 없으면 추정해 채우지 않는다.
- 결과: aggregate_id, dataset_version, 필터, 시각/시간대(Asia/Seoul), 기간별 total_reviews·topic_review_count·ratio·evidence_ids, excluded_undated_count·duplicate_count, 표본 경고, 처리/분류 버전.
- ratio는 해당 기간의 유효한 고유 리뷰 수를 분모로 한다. 한 리뷰의 동일 주제는 한 번만 센다. 분모0은 null이며 0%와 구분한다. 데이터가 없는 구간과 측정 결과0을 구분한다.
- 계절은 봄3–5/여름6–8/가을9–11/겨울12–2로 정의하며 겨울 연도는 12월의 연도다. 연도별 겨울을 합쳐 비교하지 않는다. 경계일·윤년·정렬을 검사한다.
- v1은 표본20미만에 작은 표본 표시를 제공한다. 이는 통계적 유의성 기준이 아니며 전후 효과나 인과를 입증하지 않는다. 원자료 수/날짜 누락/중복/필터를 항상 조회할 수 있다.
- 결정적 집계는 코드로 수행한다. LLM은 근거를 인용한 패턴 설명·기획 가설에 사용한다. 분류 결과는 원문 해시·모델 버전으로 캐시하고 원문 전체를 매번 다시 보내지 않는다.

## 웹과 플러그인의 역할

웹: 기간/제품 필터, 월·계절 보기 전환, 분모를 보여주는 추이 그래프, 주제 비교, 구간 클릭 원문, 선택 묶음을 기획 요청에 추가, 집계 스냅샷 내보내기.

MCP: review_trends 조회와 trend_evidence 드릴다운을 같은 집계 서비스로 제공한다. MCP는 원자료 범위를 임의로 늘리거나 사용자 승인 없이 전체 리뷰를 업로드하지 않는다. 쓰기 기능은 기존 private 작업실 인증/승인 흐름을 따른다. 공개 읽기3도구를 곧바로 개인 자료 도구로 변경하지 않는다.

## 담당별 인수 단위

| 담당 | 산출물 | 필수 검사 | 선행 |
|---|---|---|---|
| 신진하 | 날짜/제품/중복 입력과 기간·주제 결정적 집계, 근거 드릴다운 | 날짜누락/중복/분모0/겨울 연도/같은 리뷰 다주제 | 공통 규격 확정 |
| 최길웅 | 추이 그래프·필터·표본/원문·기획 요청 연결 | 실제 페이지 도달·키보드/모바일·빈구간·필터/근거 일치 | 입력 규격으로 fixture 시작; 실제 API 뒤 통합 |
| 황대겸 | 근거 묶음→기존 기능 대조→기획 가설·과잉 해석 검사 | 리뷰 수≠판매, 설명서 근거, 반례·보류 | 코어 필수 품질 회귀 우선; 집계 뒤 연결 |
| 정이량 | 계약/API/MCP·권한·공통 결과 ID·실제 두 클라이언트 시연 | 웹/MCP 동일 집계·권한·실제 정상/빈결과·원문 연결 | 자료 집계 인수 |

추가 기능은 별도 연결 Issue와 배정으로 관리한다. 기존 원 실패 job을 성공으로 바꾸거나 필수 부모 작업을 Done으로 만들지 않는다. 개발 준비와 실제 자동 Worker claim·통합 완료를 각각 기록한다.
