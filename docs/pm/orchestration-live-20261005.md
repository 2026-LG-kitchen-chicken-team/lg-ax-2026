사용자가 승인한 세 연결은 공통 운영 코드에 통합됐다. 실제 최신 가동·main·진행 결과는 [운영 Issue #28](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-2026/issues/28)의 시각이 붙은 PM 보고를 따른다. 이 문서는 실행 흐름과 인계 기준이며, 역사 시각의 Running을 현재 상태로 추정하지 않는다.

PM은 배정 → 개발 결과 수집 → 독립 검수 → 수정 요청 또는 조건부 병합 → 병합 후 검사 → 상태 인수 → 다음 배정을 계속 수행한다. 일이 없으면 기다리며 새 결과나 승인된 작업이 생기면 이어간다. 원 오류·불명 실행·사용량을 보존하고 무한 오류 재시도로 바꾸지 않는다.

## 이번 배포와 검사

운영 source `0c9d95d263630c88df9ed1c24f580b8cbdf4a0dd`의 GitHub 필수 검사4개가 성공했다. 전체 native 검사1,058개도 통과(선택 실행6개 제외)했다. 새 외부 PM runtime의 entry SHA256은 `78e7b6521c9e7a83c8675b1b1b43813f7fec5c2e40a043e307cc57c4831768fe`다. 실행/게시 인증 분리·Worker와 같은 프로필 잠금·불변 요청/응답40회·변조/41번째 호출 거부를 검사했다. 새 코드 배포·사전검사와 실제 PM Running은 각각 증거를 남긴다.

원 계획/원 단위 대장·이전 실패·모든 누적 사용량을 보존했다. 수정 registry는 `core-product-correction-1/2`만 추가하며 부모별 최대2배정, job당1시도다. 누적 제품 사례 상한10→14는 기존8예약을 유지하면서 수정 통신·결과 검증 여유만 추가한 것이다. 같은 실패를 문서 변경/재시작으로 반복 배정하지 않는다.

사용자의 계속 작업 위임과 실제 구독 사용 가능 확인 후 내부 일일 토큰 한도를1,000,000→2,000,000으로 유한하게 확장했다. 기존 계수·불명 비용 예약은 차감하지 않았고 호출/행동/부모별 한도도 유지했다. 이는 Pro 사용량 초기화·추가 크레딧·API 구매가 아니다. 한도·인증·readiness·원본 불일치가 생기면 해당 이유로 대기/보고한다.

## 현재 미완료와 팀원 행동

- 신진하는 원 Git128 진단 대기로 개인 OFF다. 원 실행 사용자·checkpoint·publisher 읽기/fetch 진단 근거를 인계하고 PM이 실제 수정·제한 재시도를 확인한 뒤 켠다.
- 황대겸 PR97·최길웅 PR98은 게시됐지만 전체 부모 완료가 아니다. 독립 검수·현재 main 대조에 따라 다음 수정 작업을 받는다.
- 실제 상품기획 정상/조건 변경 사례는 의미 검사를 통과하지 못했다. `GAP_MANUAL_MISSING`, 후보/근거 연결과 변경 조건 대응을 고쳐 다시 실행해야 한다. 전송 성공이나 단위 병합을 품질 통과로 바꾸지 않는다.
- 정식 완료는 기존5작업, 신청서31요구 verified0이다. 나머지 제품 사례·독립 평가·발표·영상·코드 ZIP/재실행 Skill·공식 제출은 별도 검증한다. 10/6 오전 컨설팅 확정 안내와 10/20 제출 준비도 유지한다.

이미 준비한 팀원은 재설치·재로그인하지 않고 개인 Worker와 PC를 유지한다. PM도 숨김 CLI 예약 작업으로 계속 실행하며 이 채팅의 활성 여부와 별개다. PC가 꺼지거나 로그아웃하면 해당 개인 실행은 멈추므로 켜진 실행 환경이 필요하다. 현재 공개 연결도 PM PC 경로에 의존한다.

ON/OFF는 [자동화 운영 안내](automation.md)의 인증된 `scripts/automation.py mode`를 따른다. 팀 OFF는 새 자동 착수/게시와 실행 중 Worker를 중지하며 기존 Issue·상세 기록·PM 수동 검수는 유지한다. 실제 상태는 `scripts/automation.py status`와 [조직 Project1](https://github.com/orgs/2026-LG-kitchen-chicken-team/projects/1)을 함께 조회한다.
