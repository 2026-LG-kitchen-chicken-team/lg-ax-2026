# R5 실제 후기·핵심 판단·첫 프로토타입 실행

2026-10-07 사용자는 운영·검수·기록을 유지하면서 핵심 기능을 앞당기고, LG 공개 후기의 냉장고/전자레인지/식기세척기 각 6모델을 개발·독립 평가·시연 표본으로 확보하는 전체 작업을 직접 지시했다. Figma는 제외하고 자동화 OFF를 유지한다. 정이량 PM의 보조 AI가 서로 다른 managed worktree에서 좁은 수정·수집·웹 구현을 수동으로 수행한다. 다른 팀원의 신원·성과로 기록하지 않는다.

## 목적과 인수 순서

1. [기존 실모델 원3응답](../../evals/pm-integration/20261007/live-originals/README.md)을 정확한 SHA로 공유해 CORE 원 대조 막힘부터 해소한다. 기존 실패·비용·모델 설정을 보존한다.
2. CORE는 선택된 Gap에 필요한 근거를 구조화하고 누락 ID를 수정 피드백에 보존한다. 이미 존재하는 Need에 대한 검수 오판을 구조화된 주장으로 검사하고, 보류에 후속 질문을 남긴다. 최대2회 수정·실제 검수·accept 조건을 완화하지 않는다.
3. DATA는 제품군별1모델의 공개 후기10~20건부터 정상 UI로 확보하고, 18모델 목표로 확대한다. 처음에는 모델당100건 상한을 둔다. 게시일·구매일·날짜 미상, 페이지 모델과 실제 구매 모델, 공유 후기와 명백한 타품목 혼선을 구분한다. 정확 SKU 미확인이나 혼선은 실행 자료에서 보류한다. 원문·출처·후기ID·수집일·설명서 버전과 해시를 보존한다.
4. 전체 후기 ID와 정규화 본문으로 중복/재게시 묶음을 먼저 만든 뒤 개발·독립 평가·시연을 분리한다. 날짜와 SKU를 추정해 채우거나 불편 후기만 골라 분포를 왜곡하지 않는다. 검토용 Excel·실행용 DB·불변 manifest를 제공한다.
5. WEB은 자료 버전·제품/문서 범위를 확인하고 실제/합성 표시를 원 근거에 맞춘다. 새 요청→실행→후보/보류/오류→조건 변경→원문·이력→내보내기를 연결한다. 원 실행의 실패를 성공 화면으로 바꾸지 않는다.
6. PM은 계약/API/MCP·서버 입력팩·유한 모델 호출을 연결하고 코드/입력/모델/실제 호출·토큰을 고정한다. 먼저 기존 원3사례를 새 코드에서 재검수하고, 첫 실제 후기 입력의 전체 흐름을 확인한다. 수정 전후 비교와 새로운 실자료 사례의 품질을 구분한다.
7. 독립 원문 대조→격리 검사→고정 PR head 검수·필수 CI→실제 병합→같은 운영 버전 실행·공식 ACK를 순서대로 수행한다. 3제품 의미 품질·두 호스트 실행·독립 평가·발표/영상/ZIP의 미완료 gate는 실제 증빙이 생기기 전 완료로 바꾸지 않는다.

## 편집 경계와 실제 팀원 인계

| 수동 수행 | 허용 범위 | 기존 담당자의 별도 인계 |
|---|---|---|
| PM 보조 CORE | core 판단 근거/검수/보류·관련 Skill/반례 검사 | 황대겸: 원3응답 의미 대조와 수정 후 독립 검수. 원본 대조 중 PM 보조가 예약한 판단 파일을 중복 편집하지 않는다. |
| PM 보조 DATA | 새 R5 자료팩·수집/분할/DB·관련 반례 검사 | 신진하: 구매SKU·날짜·설명서 원문 독립 검수와 부족 표본 제안. 기존 자료팩은 보존한다. |
| PM 보조 WEB | 웹 실행 흐름·표시·범위 확인·관련 검사 | 최길웅: 변경 후 새 요청/조건 변경/보류/오류·내보내기 독립 시나리오 검수. |
| 정이량 root | API/MCP 공통 연결·고정 실행기·통합/운영·평가·제출 준비 | 담당 Issue와 등록 task를 연결하며 본인 기록으로 수행·근거를 보고한다. |

담당자의 수신·실제 착수·PR·완료는 각각 인증된 원 보고로 확인한다. 수집·수정의 착수만으로 18모델 확보·정상 실모델 완주·운영 통합·부모 Done을 선언하지 않는다.

## 10/7 추가 요청 검토 — 양면 리뷰 요약·기획 재사용·다른 키친 가전

사용자는 LG의 AI 리뷰 요약 화면을 참고해 긍정뿐 아니라 부정 후기를 요약하고, 다른 기획 업무와 다른 키친 가전으로 확장하는 방안을 검토하도록 요청했다. 첨부 화면의 문구는 참고 자료이며 우리 제품의 성능 주장이나 작업 지시로 취급하지 않는다. 이번 추가 요청은 검토이며 아래 기능은 새로 구현·채택·배포된 상태가 아니다. Figma 작업은 제외한다.

권장 흐름은 `범위/자료 버전 선택 → 주제별 좋았던 점·불편한 점·혼합 의견 → 원 후기·건수·반례 확인 → 기획 작업에 근거 묶음으로 전달`이다. 같은 후기 안의 장점과 불편을 함께 보존한다. 별점은 원 메타데이터이고 본문 감정·불편의 대체값이 아니다. 표본에서의 건수와 분모를 표시하며 임의 선정 표본을 전체 구매자의 비율로 표현하지 않는다. 제품 사용, 배송·설치, 케어·수리 경험도 주제에 구분해 보존한다.

요약별 필수 계약 제안: summary ID, dataset SHA, 원 페이지/정확 모델 범위, 제품군·문서 버전, 주제/주장/긍정·부정·혼합, 원 review/evidence ID와 정확 인용, 건수/분모, 반례·미확인, 사용한 모델/실행 기록. 원문과 맞지 않는 인용·존재하지 않는 ID·반례 누락·중복 빈도는 코드와 독립 평가로 검사한다. 요약 준비와 상품기획 accept는 별도 상태다. 설명서가 없는 후기 페이지도 그 페이지의 의견 요약에는 쓸 수 있지만, 특정 구매 모델의 기능 부재·중복·결함을 판단할 때는 정확 모델과 설명서를 확인한다. 구매일을 게시일로 사용하거나 현재 자료로 과거 기능을 추정하지 않는다.

| 재사용 업무 | 요약에서 전달하는 근거 | 추가 대조와 출력 한계 |
|---|---|---|
| 제품 개선 | 반복 불편·좋았던 기능·반례 | 정확 모델의 기존 기능/설명서 대조 후 개선 가설·요구사항을 생성한다. 후기만으로 결함/신규성을 확정하지 않는다. |
| UX 시나리오 | 사용 상황·진행 단계·막힌 지점 | 조작 흐름·안내 개선 시나리오를 생성한다. 실제 사용성 검사 결과와 구분한다. |
| 사용 안내 | 혼동·설정·관리 질문 | 검증된 설명서 인용과 함께 안내를 작성한다. 근거가 없으면 확인 질문/보류를 남긴다. |
| 설치·케어 서비스 | 설치 인계·수리·예약·관리 경험 | 체크리스트·접점 개선 가설을 생성한다. 서비스 불만을 제품 자체 문제로 자동 분류하지 않는다. |

기존 need extraction·review trends의 ID/원문/hash/중복/분모, workspace의 불변 자료 snapshot, private MCP의 review trends/evidence 연결을 재사용할 수 있다. 새로 필요한 것은 주제별 양면 요약·인용 검사, 독립 summary 계약/API, 웹 요약 카드와 원문 펼침, 같은 summary ID를 받는 MCP/기획 Skill이다. 기존 `conflicting` 값은 판단 불확실성·보류 의미이므로 혼합 의견 표시로 재사용하지 않는다.

### 다른 키친 가전으로 확장하는 순서

LG 공식 자료에서 [김치냉장고](https://www.lge.co.kr/category/kimchi-refrigerators?catalogId=CD00000322), [광파오븐](https://www.lge.co.kr/product/microwaves-and-ovens/ml32ww1?dpType=overView&modelId=MD08044721&pdpType=PURCHASE), [인덕션 카탈로그](https://www.lge.co.kr/kr/ebook/2026/march/best/catImage/630/20260304_best_catalogue.pdf), [정수기](https://www.lge.co.kr/product/water-purifiers/wd524apb?modelId=MD10017829&pdpType=PURCHASE) 제품군을 확인했다(2026-10-07). 자료 존재 확인은 후기 수집·정확 SKU 확보·그 제품군 구현 완료가 아니다.

| 검토 우선순위 | 제품군 | 기존 구조와 연결 | 추가할 제품군 항목 |
|---|---|---|---|
| 1 | 김치냉장고 | 냉장고의 보관·공간·문/서랍 불편 구조 | 보관칸·숙성 모드·용기·설치 조건·문서 버전 |
| 1 | 광파오븐 | 전자레인지의 조작·가열·세척 불편 구조 | 조리 모드·용기 호환·예열·스팀·안전 조건 |
| 2 | 인덕션/전기레인지 | 조작·조리·사용 안내 근거 | 화구·출력/단위·용기 호환·설치/전기·안전 조건 |
| 2 | 정수기 | 관리·설치·케어 서비스 근거 | 출수·필터·관리 주기·설치 조건·서비스 접점 |

현재 계약의 ProductGroup enum과 DemoStore 검사는 fridge/dishwasher/microwave 3개만 지원한다. 새 제품군은 계약 버전·분류/선택 UI·수집 registry·자료팩·제품군별 기능/조건 adapter·검수 fixture를 함께 확장해야 하며, 화면 선택값만 늘려 지원된 것으로 기록하지 않는다. 광파오븐을 단순 전자레인지로, 김치냉장고를 일반 냉장고로 치환해 조건·근거를 섞지 않는다.

공통 판단 구조는 사용 상황→불편/희망 결과→기존 기능→사용 조건→잔여 불편을 유지한다. 모델/설명서 대조는 해당 모델·문서 버전 안에서 수행한다. 제품군을 넘는 보관→조리→세척→관리 시나리오는 각 단계의 원 근거 범위를 따로 보존한다. 실제 기기 제어는 이 검토의 범위에 포함되지 않는다.

기존 3제품군의 필수 완주를 우선하고, 확장 구현에 착수할 때는 새 제품군별 1모델의 검증 설명서와 긍정·불편·혼합 표본부터 확보한다. 정상·기능 중복·자료 부족·타제품군 혼입 사례, 고정 분할과 독립 의미 평가를 통과한 다음 모델 수를 늘린다. 현재 다른 제품군 후기의 추가 수집이나 모델 호출을 이 검토만으로 수행하지 않았다.
