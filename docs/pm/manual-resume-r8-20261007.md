# 실제 자료 기획 수동 재개 R8

사용자 지시대로 자동화·예약 PM·원격 Worker는 OFF다. 이미 끝난 코드와 검사를 재사용하고 중단됐던 미완료 범위만 이어간다. 현재 채팅의 지원 구현과 기존 담당자의 직접 수행 보고는 구분한다. Figma와 새 합성 리뷰는 제외한다.

최신 수동 배정·의존·잔여는 [Issue234](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-2026/issues/234)와 [작업큐](manual-queue-20261007.json)에서 확인한다. 기존 열린47개 Issue의 잔여를 연결했고 완료5개를 다시 열지 않았다. CORE 황대겸, DATA 신진하, WEB 최길웅, PM 정이량의 담당을 유지한다.

## 새 흐름

실제 공개 자료 → 목적·제약 → 문제와 반대 근거 → 기존·경쟁 대응 → 개선 전후 단계·장면 → 조건 변경·이력 → 근거/기획 내보내기다. 사용자가 처음부터 불편을 지정할 필요가 없다. 새 ResearchBundle/PlanningBrief는 기존 exact-model 계약과 별도로 연결해 구매 SKU 미상인 자료도 제품군 수준에서 처리한다.

- 실제 후기238건 원문·해시·기존 split/hold 보존. 실행용 개발 후기141건만 묶고 독립평가·시연 후보는 자동 승인하지 않는다.
- 설명서3개·15발췌와 첫 FAQ/설치/경쟁 근거에, 공개 페이지6곳의 추가 FAQ5개·Q&A 질문/답변2개를 연결한다. 질문은 구매/재입고 문의이고 사용 불편 표본으로 세지 않는다. 공식 답변은 문서 맥락으로 사용한다.
- CORE는 작은 발견·문제별 기획 호출, 원문 facts 전체 복사, 수치/기대시간/발췌 오류 검사, 거절 필드1회 수정과 정상 후보 보존을 구현한다. 일부 자료만 읽으면 선정 범위·한계를 남긴다. 문서 존재를 불편 해결의 증거로 바꾸지 않는다.
- 웹은 좋은/나쁜/혼합 경험, 원문, 비교, 전후 과정과 장면, 작은 관계그래프, 조건 수정·실행ID 복구·내보내기를 제공한다. 관계는 추론 여부를 표시하고 동시언급을 인과나 시장 빈도로 해석하지 않는다.
- API는 Bearer/Origin/소유권·같은 자료 digest의 수정 관계를 확인한다. 원본 호출·국소 수정·실패 attempt는 private SQLite에 보존하고 외부 응답만 정제한다. MCP의 새4도구가 같은 서버·자료·저장 결과를 소비한다.

## 확인한 범위

새 소스·계약·경계·UI 검사는 각 변경에 필요한 범위에서 수행했다. 실제 브라우저와 MCP HTTP에서 자료 조회·전환, 원문 필터·출처 상세, 저장 기획 조회·수정 이력·관계그래프를 확인했다. 실제 공개자료의 정상·조건 변경·국소 수리5회와 공식자료 고의 제외 CORE1회를 수동 실행했다(새 모델 호출12회, 새 합성 리뷰0). 원문 facts, API/MCP의 저장·재조회 결과와 정상 비교 보존을 확인했다. 첫 긍정 전용 응답은 문제를 만들지 않은 정상 결과였고, 표본 선택을 낮은 별점·혼합·긍정으로 교차해 실제 불편과 기획을 생성했다.

현재 시험은 `qwen3.8:27b-q4_K_M`, digest `25b843619e944cd0ae6069f94ff4e5e26a16e109ccbc0a66a0f05979ed70098e`다. 역사 `qwen3.5:27b`/`64ae5b1d…`와 tag/digest가 다르며 동일 가중치는 확인하지 못했다. 이번 결과를 옛 챗봇과 정확히 같은 모델·설정의 재현이라고 부르지 않는다.

독립 원문 검수에서 기능/관리행동, 가족/구매자, 문서 지침/원인가설 오독을 찾았다. 새 국소 수리 경로는 검수 대상 필드만 수정하고 실패해도 원항목을 유지한다. 대상 인용 근거에 집중한 후속 수리에서 핵심 오독은 개선됐지만 냄새 발생·청소·손설거지 복귀의 시점/순서 정밀도와 양면 요약의 일부 확장 해석은 잔여다. 공식자료 고의 제외를 실제 기능 부재로 바꾸지는 않았으나 원인 확인·지원 해결 약속이 과해 의미 품질은 부분이다. 구조 acceptance, 독립 품질, 제품 전체 완료를 구분한다.

전용 시험 서비스 두 세션은 끝내고 자신의 프로세스만 종료했다. 보호 GPU1/타인 프로세스·기존 서비스를 변경하지 않았다. 현재 loopback 미리보기는 모델 생성 OFF, 실제 자료4묶음(61/54/51/66)과 저장 결과 조회만 제공한다. 냉장고66자료팩은 PR244 공식 발췌12개의 계약 변환이며 새 냉장고 모델 실행·품질 완료를 뜻하지 않는다. JSON/MD 직렬화는 확인했지만 Chrome 실제 다운로드 완료는 미확인이다.

PR231/232는 과거 회귀·인수 기록으로 검수·병합했다. PR233은 구조 검사 기반 코드로 검수·병합했다. 이 병합을 새 실제 후기 기획 성공이나 독립 품질 승인으로 확대하지 않는다. 기존 exact-model Agent의 전역 삭제 정책도 별도 잔여이며 새 공개자료 흐름의 국소 수정과 혼동하지 않는다.

PR241은 O2 저장 거절 상태 보존, PR242는 역사27B·D3소비 준비 기록, PR244는 공식 경쟁 자료팩 범위로 필수 CI 후 수동 병합했다. PR243은 새 PlanningBrief와 타입이 달라 중복 화면을 확장하지 않고 호환 가능한 국소 변경만 인수하도록 보류했다. PR246 감사 도구는 현재 producer 경로/필드 연결과 미등록 Excel행·잘못된 제품군이 함께 통과할 수 있는 두 P2 수정이 필요해 request-changes다. 준비용 감사 코드를 실제 D4 통과로 집계하지 않는다. 새 통합 코드는 [PR245](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-2026/pull/245)에 인계한다.

## 수동 실행과 인수

실제 공식문서 snapshot과 research bundle을 명시하고, 모델 실행은 준비됐을 때만 opt-in한다. 기존 사용자 작업실/운영 DB를 덮어쓰지 않고 별도 DB·loopback 포트를 사용한다. `lgax_api.workspace_server`에 `--research-bundle`을 제품군별 반복 지정하고 모델 설정이 준비된 뒤 `--enable-research-planning`을 추가한다. 공개 문서는 `--document-dataset`과 정확한 `--document-dataset-sha256`을 함께 지정한다. 새 흐름은 legacy 합성 bootstrap을 요청하지 않는다.

웹의 `/api/research`와 MCP `list_research_bundles`, `get_research_bundle`, `create_research_run`, `get_research_run`은 같은 인증 서버를 사용한다. 모델이 비활성이면 자료 조회는 가능하고 생성은501이다. 실패를 성공 기획으로 저장하지 않는다. 서버 opt-in 뒤에도 정상·조건 변경·근거 부족의 원 차단 사례를 독립 검수해야 한다.

`create_research_run`의 선택 `review_feedback`은 같은 목적·조건의 `previous_run_id`와 항목별 kind/ID/필드/검수 의견을 받는다. 항목·정체성·원문·scope를 모델 열기 전에 검사하고 새 revision에 국소 patch를 저장한다. API도 대상 밖 필드·요약·관계를 임의 재작성한 응답을 거절한다. `repair_outcomes.accepted`는 구조 검사 수용이며 의미 품질 승인이 아니다. 국소 수리의 새 model trace와 검수 지적은 private로 보존하고 안전한 상태만 공개한다.

첫 테스트는 실제 자료1제품군의 발견→구체적 제안→조건 수정→웹/MCP 같은 기록 확인으로 시작한다. 나머지15설명서·표본 확대·독립평가·검색/재정렬/OCR 실제 비교·플러그인 다섯Skill 인수·콘셉트 영상·다른 키친 제품군·최종 발표/재현ZIP의 미완료도 작업큐에 유지한다. 전체18모델·영상 완성을 첫 테스트 선행 조건으로 두지 않는다.
