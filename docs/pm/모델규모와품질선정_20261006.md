# 모델 규모와 실제 품질 선정 — 2026-10-06

## 사용자 지시와 결정

사용자가 연구실 A6000 네 장을 고려해 8B만 쓰는 이유와 더 큰 모델의 가능성을 재검토하도록 지시했다. 이어 “27B말고 더 좋은거도 쓰던지 검토해봐”라고 지시했다. **8B는 초기 연결·회귀·속도 기준선이다. 최종 판단 모델을8B/27B로 제한하지 않는다.**27B는 설치와 제한 시험을 완료했고, 다음 큰 품질 후보는 Qwen3.5-122B-A10B Q4_K_M이다. 설치·실행·실제 품질 평가·최종 채택을 구분한다.

초기에 작은 모델부터 시작한 이유는 설치와 반복 실행 비용을 줄여 자료·Schema·Skill·API 연결 오류를 빨리 확인하기 위해서였다. 영구 디스크 부족과 임시 캐시 소실도 실제 제약이었다. 이 이유는 초기 기준선에는 타당하지만 현재 판단 품질이 부족한데 8B만 유지할 이유가 되지는 않는다. 모델 확대와 공통 입력 결함 수정을 함께 진행한다.

## 직접 확인한 자원

10/6 PM SSH 읽기 조회: GPU 네 장 각각 49,140MiB, 사용량 16/18,510/16/17MiB. 활성 큰 프로세스는 기존 WAVE/Naru 런타임이며 변경하지 않았다. LG 전용 Ollama0.34.0은 loopback18864, `CUDA_VISIBLE_DEVICES=0`, 모델 캐시는 LG 전용 `/dev/shm` 경로다. 시스템 RAM251GiB 중 available215GiB, 루트 디스크 여유15GB, `/dev/shm` 여유107GB였다. 숫자는 조회 시점의 관측이며 장기 예약이 아니다.

27B Q4_K_M은 [Ollama 공식 항목](https://ollama.com/library/qwen3.5:27b-q4_K_M)의 실제 다운로드를 완료했다. 공식 registry와 실제 tag의 manifest digest는 `64ae5b1d651fb2709d5928ccb8dcfb4bb2cc9c2c8001ac34497e36a6cf905b59`, 크기는17,478,556,591B로 일치한다. 개별 로컬 가중치 blob SHA는 별도 검증하지 않았다. LG 전용 GPU0·loopback18864에서 기존8B pin을 바꾸지 않은 별도 후보로16K 문맥 제한 시험을 실행했다. 설치 후 임시 공간은 약89GB이며 정확한 잔여 byte는 다음 큰 모델 설치 직전에 확인해야 한다. 임시 캐시는 재부팅 때 사라지므로 지속 배포는 영구 공간 확보/재다운로드 절차가 필요하다.

## 공정한 시험과 채택 기준

동일한 코드 commit·입력/자료 hash·모든 원문·스키마·seed42·temperature0·context16,384·출력8,192, thinking false에서 비교한다. 냉장고 정상1건부터 시작하며 새 독립 수동 실행은 최대12 생성/100,000 tokens로 제한한다. 원 자동 작업/예산은 변경하지 않는다. 모델 고유 template와 명시하지 않은 샘플링 기본값은 같다고 가정하지 않고 실제 설정을 기록한다. GPT-OSS는 bool false로 reasoning 비활성화를 표현할 수 없으므로 이름 있는 reasoning 설정을 별도 계약으로 검증해야 한다. 모델만 바꾼 비교에는 두 모델 모두 같은 고정 코드의 완료 결과가 필요하다.

입력 길이·JSON 계약 통과만으로 채택하지 않는다. 불편의 실제 근거, 기능 지원과 불편 해소의 구별, 모델/문서 범위, 잔여 불편, 후보-검토 일대일 대응, 적절한 보류/중복 제외, 공유 수정2회 준수, 전체 호출·토큰·지연을 검토한다. accept 수를 올리려고 거부 규칙을 완화하지 않는다. 공급사 공개 benchmark를 우리 업무의 측정 결과로 표시하지 않는다.

## 이번 실패의 정확한 의미

PM 수정 후8B 실행은 입력 상한을 통과했으나 최초 시험의 외부 relay8회 상한이 파이프라인 최대12회보다 작았다. 8회39,180tokens의 실제 응답은 정상 종료했고 9번째 concept_draft는 호출되기 전에 거부됐다. OFF·서버 OOM·API 장애로 재분류하지 않는다. 동시에 positive 리뷰에서 불편을 만들고, 빈 concepts에 assessments를 붙인 의미 오류도 관측했다. 이 실패·원 usage를 보존하고 별도12회 시험으로 완주와 의미 품질을 구분한다.

같은 제품 commit45fe0f23의8B 냉장고·전자레인지12회 제한 시험은 각각9호출44,387/21,673tokens 뒤 failed,27B 냉장고는3호출13,284tokens 뒤 held였다. 정상 JSON과 실행 종료는 확인했지만 불편 polarity·기능 지원·중복 의미·근거 연결에 실패했다. 큰 모델 확대만으로 해결을 보장하지 않으며 enum 의미 안내와 CORE의 원문 대조 품질 보완을 함께 수행한다. 최신 설치/실행/선정 결과는 정이량007/E042의 실제 증거를 따른다. 이 문서는27B 채택 완료나 첫 정상 프로토타입 성공을 선언하지 않는다.

## 추가 지시 — 27B보다 더 좋은 모델도 검토

사용자가 “27B말고 더 좋은거도 쓰던지 검토해봐”라고 추가 지시했다. **27B를 최종 상한으로 두지 않고 Qwen3.5-122B-A10B를 다음 큰 품질 후보로 선정**한다. GPT-OSS-120B는 다른 계열 비교 후보,35B-A3B는 처리량/지연 후보로 유지한다. 공개 benchmark에서122B가 여러 Agent 지표에서27B보다 높아도 일부 지표는 역전된다. 한국어 키친 상품기획의 실제 결과는 미측정이므로 “무조건 더 좋다”거나 파라미터 수와 수상 가능성을 연결하지 않는다.

16:34 KST 읽기 재조회에서 영구 root 여유15,083,552,768B, 임시 공간96,626,905,088B, RAM available211,877,232,640B를 확인했다. 별도 영구 마운트는 확인되지 않았다. 공식122B 배포81,370,035,877B를 같은 임시 캐시에 추가하면15,256,869,211B(약14.2GiB)가 남는다. 다운로드 여지는 있지만 큰 모델의 지속 재현용 공간은 아직 없다. **원 모델/로그를 지워 해결하지 않고** 원자료 보관·임시 캐시 소실/재다운로드·2~3GPU 실제 적재/KV/지연을 먼저 확인한다. GPU1의 다른 연구실 서비스를 제외하고 GPU2·3 또는 LG 시험을 마친 GPU0·2·3을 사용한다. 65GB GPT-OSS는 더 여유가 있으나 어댑터 수정/호환 시험 비용이 있다. 이번122B는 조사·비교 후보이며 설치/한국어 실제 품질은 미실행이다. [공식 manifest와 실제 자원 수신증](../../evals/pm-prototype/20261006/model-candidates.json)을 따른다.

최종 결정은 같은 원문21개 또는 독립 입력에서 잘못된 불편·근거 연결·누락/보류·중복 후보·스키마 실패·전체 호출/토큰·응답 지연을 비교한다. 작은 모델은 검색/OCR/반복 회귀에, 좋은 판단 모델은 불편 대조·콘셉트·의미 검수에 활용할 수 있으나 이런 단계별 분기는 통합 계약과 평가를 먼저 확인한다.
