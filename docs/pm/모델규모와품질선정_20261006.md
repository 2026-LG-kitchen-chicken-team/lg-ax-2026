# 모델 규모와 실제 품질 선정 — 2026-10-06

## 사용자 지시와 결정

사용자가 연구실 A6000 네 장을 고려해 8B만 쓰는 이유와 더 큰 모델의 가능성을 재검토하도록 지시했다. **8B는 초기 연결·회귀·속도 기준선이다. 최종 판단 모델을 8B로 제한하지 않는다.** 다음 검증 후보는 Qwen3.5-27B Q4_K_M이며 설치·실행·실제 품질 평가·최종 채택을 구분한다.

초기에 작은 모델부터 시작한 이유는 설치와 반복 실행 비용을 줄여 자료·Schema·Skill·API 연결 오류를 빨리 확인하기 위해서였다. 영구 디스크 부족과 임시 캐시 소실도 실제 제약이었다. 이 이유는 초기 기준선에는 타당하지만 현재 판단 품질이 부족한데 8B만 유지할 이유가 되지는 않는다. 모델 확대와 공통 입력 결함 수정을 함께 진행한다.

## 직접 확인한 자원

10/6 PM SSH 읽기 조회: GPU 네 장 각각 49,140MiB, 사용량 16/18,510/16/17MiB. 활성 큰 프로세스는 기존 WAVE/Naru 런타임이며 변경하지 않았다. LG 전용 Ollama0.34.0은 loopback18864, `CUDA_VISIBLE_DEVICES=0`, 모델 캐시는 LG 전용 `/dev/shm` 경로다. 시스템 RAM251GiB 중 available215GiB, 루트 디스크 여유15GB, `/dev/shm` 여유107GB였다. 숫자는 조회 시점의 관측이며 장기 예약이 아니다.

27B Q4_K_M은 [Ollama 공식 항목](https://ollama.com/library/qwen3.5:27b-q4_K_M) 기준 약17~20GB다. 가중치 외 KV cache·실행 버퍼가 필요하지만 48GB 한 장에서 제한 context로 시험할 합리적 여지가 있다. 기존 LG 임시 캐시에 **별도 후보로 다운로드를 시작**했으며 기존8B pin·서비스·다른 GPU 프로세스를 교체하지 않았다. 임시 캐시는 재부팅 때 사라지므로 지속 배포는 영구 공간 확보/재다운로드 절차가 필요하다.

## 공정한 시험과 채택 기준

동일한 코드 commit·입력/자료 hash·모든 원문·스키마·seed42·temperature0·context16,384·출력8,192, thinking false에서 비교한다. 냉장고 정상1건부터 시작하며 새 독립 수동 실행은 최대12 생성/100,000 tokens로 제한한다. 원 자동 작업/예산은 변경하지 않는다. 모델만 바꾼 비교에는 두 모델 모두 같은 고정 코드의 완료 결과가 필요하다.

입력 길이·JSON 계약 통과만으로 채택하지 않는다. 불편의 실제 근거, 기능 지원과 불편 해소의 구별, 모델/문서 범위, 잔여 불편, 후보-검토 일대일 대응, 적절한 보류/중복 제외, 공유 수정2회 준수, 전체 호출·토큰·지연을 검토한다. accept 수를 올리려고 거부 규칙을 완화하지 않는다. 공급사 공개 benchmark를 우리 업무의 측정 결과로 표시하지 않는다.

## 이번 실패의 정확한 의미

PM 수정 후8B 실행은 입력 상한을 통과했으나 최초 시험의 외부 relay8회 상한이 파이프라인 최대12회보다 작았다. 8회39,180tokens의 실제 응답은 정상 종료했고 9번째 concept_draft는 호출되기 전에 거부됐다. OFF·서버 OOM·API 장애로 재분류하지 않는다. 동시에 positive 리뷰에서 불편을 만들고, 빈 concepts에 assessments를 붙인 의미 오류도 관측했다. 이 실패·원 usage를 보존하고 별도12회 시험으로 완주와 의미 품질을 구분한다.

최신 설치/실행/선정 결과는 정이량007/E042의 실제 증거를 따른다. 이 문서는 27B 채택 완료나 첫 정상 프로토타입 성공을 선언하지 않는다.
