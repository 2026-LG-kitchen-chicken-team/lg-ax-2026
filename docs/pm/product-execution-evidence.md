# 실제 제품 실행 근거 후속 작업

2026-10-05 PM의 연쇄 운영 점검에서 확인했다. 개발 Worker의 구현·fixture 검사·PR과 상품기획 Agent 자체의 실제 모델 실행은 별개다. 현재 보호된 완료 collector와 게시·승인·의존 해제 경로는 연결되었지만, 실제 제품 실행 근거를 자동 생성하는 실행기는 아직 연결되지 않았다. 기존 평가 실패를 성공으로 바꾸거나 코딩 모델의 토큰을 제품 실행으로 기록하지 않는다.

## PM003: 제한된 제품 모델 실행 연결

- 고정 main의 `PlanningAgent.run`과 기존 `OllamaAdapter.transport` 주입점을 사용한다. 인증 없는 validator의 `network=none`과 게시/PM/controller 인증 접근 차단을 유지한다.
- PM이 별도 검수·배포한 파일 RPC 중계기는 승인된 단위·호출 순번·입출력 해시만 처리한다. 컨테이너에 새 승인 요청/응답 파일을 제한적으로 제공하고, host 고정 코드만 기존 모델 gateway의 `/api/tags`·`/api/generate`를 호출한다.
- 모델 digest, 실제 원응답, 호출·토큰·시간 상한, OFF 중단과 중복·변조·임의 경로 거부를 검증한다. 일반 네트워크 개방, 인증 폴더 마운트, 코딩 `role=model`을 제품 테스트에 사용하는 우회는 허용하지 않는다.
- 설치·설정 이름만으로 완료하지 않는다. canary 차단과 정상 제품 모델 호출을 실제 증거로 남긴 뒤 고정 배포와 다음 실행 단위를 등록한다.

## PM004: 요구사항별 실행·독립 판정 인수

- `evals/core-planning/examples/`의 dataset·fridge 정상/변경 입력에서 시작한다. 고정 main·자료 버전·모델 digest와 원 출력·trace·model_calls·중계 원응답을 연결한다.
- 개발 실행과 다른 PM 검수 세션이 신청서의 요구사항을 각각 판정한다. 제품 Agent 자신의 `semantic_reviews`를 독립 평가로 재사용하지 않는다.
- 검증한 항목만 보호된 admission 및 `register_requirement_bundle`로 인수한다. 정상/변경 두 실행은 CORE002의 8개 요구 전체를 입증하지 않는다. 모델 혼입·미언급 기능·근거 부족 사례를 추가 확인하고 조건이 모두 충족될 때에만 부모 완료 후보를 만든다.
- 보호 완료 publisher의 실제 PR·CI·병합·Project 수신·중앙 Done 수신 전에는 다른 부모의 의존을 해제하지 않는다. 발표·영상·최종 ZIP·공식 제출은 별도 gate다.

## 현재 운영과의 관계

이 후속은 기존 PM003/004의 신청서 구현·검증 범위다. 별도 신규 아이디어를 채택하거나 기존 지시를 확대하는 작업이 아니다. 현재 연쇄 CLI는 이미 승인된 개발 단위를 계속 처리하며, 실제 실행 근거가 부족한 부모는 검증 대기로 표시한다. 위 RPC의 정책·마운트·고정 host 코드 변경은 PM이 검수·배포해야 하며 팀원 모델이 운영 권한을 바꾸지 않는다.
