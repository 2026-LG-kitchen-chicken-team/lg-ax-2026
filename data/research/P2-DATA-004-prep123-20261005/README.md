## 2. 변경·충돌 자료 준비

기존 원본을 보존하고 `private/evaluation/DATA004-20261005-prep123-01/`에 입력 전용 파생본을 만들었다. 전부 **합성 자료**이며 실제 LG 제품 사양·고객 후기·변경 이력이 아니다.

- 모델 혼동: 목표 제품과 다른 모델의 리뷰가 섞인 기존 입력을 재사용했다.
- 문서 버전 혼동: 제품 v1.0에 v2.0 설명서/기능이 섞인 보조 입력을 별도로 준비했다.
- 상충 리뷰: 원래 식기세척기 사례에 섞인 냉장고 리뷰 내용을 고쳐 같은 제품·같은 배치 조건의 서로 다른 두 사용 경험을 준비했다.
- 명세 변경: 같은 가상 냉장고의 v1.0/v2.0 자료를 각각 저장했다. 기존의 모호한 “추가 동작” 문구를 구체적인 합성 동작·조건으로 파생했고 변경 전 원문도 별도 보존했다.

각 원문은 제품·문서 버전·자료 성격·논리적 페이지/행과 실제 JSON pointer·해시로 연결했다. 합성 `page`/`row`는 원래 fixture의 논리적 위치이며 실제 PDF 페이지를 확인한 것으로 표현하지 않는다. 원래 입력, 파생 입력, 변경 연산, 변경 전후 쌍은 private의 `original-inputs/`, `materials/`, `adaptation-provenance.json`, `change-conflict-pairs.json`에 있다.

## 3. 개발과 분리한 6유형 평가 입력

| 유형 | 제품군 | 입력 준비 내용 |
|---|---|---|
| 정상 | 식기세척기 | 리뷰·설명서·기능을 같은 모델/버전에 연결한 요청 |
| 기존 기능 중복 | 전자레인지 | 새로 추가해 달라는 동작을 기존 설명서와 대조할 수 있는 요청 |
| 모델·버전 혼동 | 냉장고 | 목표 모델과 다른 리뷰 모델을 섞은 요청; 버전만 다른 보조 입력 별도 |
| 상충 리뷰 | 식기세척기 | 같은 조건에서 서로 다른 경험을 적은 두 리뷰 |
| 근거 누락 | 전자레인지 | 리뷰는 제공하되 설명서·기능 근거가 빠진 입력 |
| 명세 변경 | 냉장고 | v2.0 자료를 받은 입력과 보존한 v1.0 기준 입력의 쌍 |

주 평가 사례6개·보조 입력2개, 세 제품군 각2개다. 기존 초안이 원래 후보출력의 잘못된 인용/판정에 의존하던 부분을 입력 자체로 확인할 수 있게 파생했다. 예상 판단·수정/보류 정답은 아직 작성하지 않았다. 판단 계약 Schema는 기존 비공개 초안과 고정 `bbf4e1c` 스냅샷의 바이트가 일치한다. 최신 서버·main 계약 채택과 처리 경로 연결은 후속 검토가 필요하다.

평가 manifest는 기존 PM loader의 정확한 root3필드·사례5필드를 사용한다. `independent_from_development: true`는 자료 구성의 분리 선언이다. 실제 비교 범위는 기본 개발 자료2파일과 고정 CORE001 개발 입력6파일이며, ID와 원문/요청 텍스트의 **정확한 일치0건**을 확인했다. 의미·난도 독립성, 정답 타당성, 최종 평가 적합성은 아직 PM 확인 전이다. 정상/상충·중복/누락 유형의 관련 입력은 대조 설계에 따른 것이며 독립적인 시장 표본으로 세지 않는다.

## 확인 결과와 남은 단계

`runs/initial/preparation-checks.json`: 준비 확인 **48항목 PASS**. 8입력의 기존 JSON Schema, 유형/제품군 완비, ID·기능 근거 참조, 출력/답안 필드 부재, 합성 표시, 기존 PM manifest loader, 개발 자료 정확한 중복0·원본 해시 보존·private Git 제외를 확인했다. 기존 답안은 내용/바이트를 열지 않고 파일 크기/수정시각만 대조했다.

이번에 모델/API/OCR 호출·성능 평가·예상 정답 작성·전체 의미 검수·Issue/PR 게시·PM 승인/병합/통합은 수행하지 않았다. `P2-DATA-004`는 공식 `pending`이며 `P2-DATA-002` 의존성도 유지한다. 준비 확인을 R05/R06/R22/E01 전체 완료로 바꾸지 않는다.

다음은 **4단계: 파생 입력에 맞는 예상 대응과 정답 근거 작성**이다. 기존 답안은 원래 후보출력 검토용이어서 새 입력의 답안으로 자동 승계하지 않는다. 사용자에게 현재 필요한 추가 정보는 없다.

## 실행 기록


기존 준비 폴더를 덮어쓰지 않는다. 재생성하려면 코드의 `PRIVATE`/`REPORT`를 별도 작업 복사본에 맞춰 새 경로로 지정하고 고정 원입력·recipe·Schema·개발 대조 파일 해시를 먼저 확인한다. 기존 폴더 삭제·재사용을 재현 방법으로 삼지 않는다. 일반 사용자에게 실행 서비스를 제공한 것이 아니라 입력 구성/재현 출처를 남긴 것이다.

큰 로그·평가 원문은 private에 있으며 이 폴더는 `inventory.json`, `case-index.json`, 준비 코드와 확인 결과만 담는다. `artifact-hashes.json`은 생성 당시 해시이며 이후 작성한 README/개인 작업기록·근거 해시는 종료 검사에 별도로 남긴다.
