## 정확 SKU·날짜·매뉴얼 gate

`displayed_model_id`와 `review_list_model_id`는 화면의 연결 근거다. 구매SKU가 확인된 필드가 아니다. 정상 미디어 상세에서도 구매제품 SKU·구매제품 링크를 찾지 못했고 DUE6BGL2E 화면에 화력/하이라이트 후기800398이 섞여 있음을 확인했다. `actual_purchased_model_id=null`, `eligible_for_model_input=false`, 입력 보류 이유를 모든 행에 보존한다. 제품군이 의심되는 행은 따로 격리한다.

화면의 **구매 일자**는 `purchase_date`이고 **작성일**은 `published_at=null`이다. 구매일을 작성월·계절 동향의 대체값으로 사용하지 않는다. 기존3개 공개 매뉴얼의 MFL/Rev는 현재 참조판으로만 연결하며 구매 당시 판은 미확인이다. 신규15모델은 매뉴얼을 아직 검증하지 않았으므로 `manual_version=null`이다. 이들의 `document_version`은 PDP HTML 해시판이며 매뉴얼판으로 표시하지 않는다.

## 보존·개인정보·분할

원후기ID, 본문과 해시, 표시SKU, 원리스트MD, 출처 URL/CSS/HTML SHA256, 수집일, 구매일, 미상 작성일, 매뉴얼판과 입력 보류를 JSON/SQLite로 함께 보존한다. 구매자 이름·가구정보·사진/영상은 추출하지 않는다. 본문에 나타나는 이메일·전화번호는 제거하고 해당 행을 격리한다. 긍정 후기와 불편이 없는 결과도 그대로 둔다.

여러 제품 페이지의 같은 원후기ID는 전역에서1개로 만들고 모든 페이지 연결을 보존한다. 다른ID로 재게시된 같은 장문+구매일은 같은 그룹으로 묶는다. 흔한 짧은 칭찬은 서로 다른 고객으로 남긴다. 그룹 전체를 SHA256 고정버전 기준으로 개발/독립평가/시연 중 하나에만 배정하며 교집합을 실제 계산해0인지 확인한다. 첫 파일럿 분할은 학습·모델평가에 사용하지 않았다. 최종18모델 고정 버전을 새로운 불변 자료로 유지한다.

`public-reviews.sqlite3`는 앱 DB와 별도인 연구 landing이다. 정확 구매SKU와 해당 매뉴얼판이 확인되면 그 고정 개발 subset만 기존 `review_import` 계약으로 입력한다. 수집 성공과 정확SKU 실행 gate 완료를 구분한다.
