# 구현 난도와 1차 서류만으로 다시 선정

판단일: 2026-09-27. 선정자: Codex. 사용자의 기존 최종 선정 위임과 이번 원점 재검토 요청에 따른 결정이며, 사용자가 이 후보를 직접 승인했다는 뜻은 아니다.

## 결론

**Theme A — 고객 불편·기존 제품 대조 기반 키친 상품기획 Agent**를 출품 방향으로 선정한다.

키친 가전 상품기획자가 고객 리뷰와 제품 자료를 넣으면, Agent가 불편을 정리하고 해당 모델의 실제 기능과 대조한 뒤, 개선할 제품·서비스 콘셉트와 근거를 작성한다. 새 자료나 다른 기획 요청이 들어오면 같은 과정을 반복한다.

이번 판단은 ① 자료 준비를 포함한 실제 구현 난도 ② 현재 자료로 작성할 1차 제안서의 설득력, 두 축만 사용한다. 수상 시연의 화려함, 시장 규모, 장기 사업성, 포함 과제 개수는 별도 가점으로 쓰지 않았다. 구현성과 차별성은 서류에서 약속을 설명할 수 있는지를 판단하는 하위 근거다. 합격 확률·공식 배점·실제 우월성이 측정된 것은 아니다.

## 무엇을 바로잡았나

- 기존 폼팩터·연계 서비스 추천을 우선하지 않고, 각 주제를 가장 작게 구현했을 때의 부담을 다시 비교했다.
- B에 이미지 생성·3D·실가전·물리 시뮬레이터가 의무라는 조건은 확인되지 않았다. 간단한 흐름·와이어프레임 생성 B안도 비교했다.
- A도 제조 설계 검증까지 의무라고 해석하지 않았다. 폼팩터는 개념·공개 치수 검토로 줄여도 고객 요구와 형태 대안의 타당성을 설명할 부담이 남는다.
- 공개 데이터가 있다는 사실을 곧바로 쓸 자료가 확보됐다는 뜻으로 취급하지 않았다. 실제 내려받기와 연결을 실행하고 표본의 한계를 기록했다.

## 같은 두 축으로 비교

아래 평가는 제한된 첫 구현을 가정한 Codex의 상대 판단이다. '높음'은 합격 보장이 아니며, 쉬운 코드 작성만이 아니라 자료 선별·결과 점검까지 구현 난도에 포함한다.

| 후보 | 제한된 첫 구현 | 구현 난도 | 1차 서류 설득력 | 판단 근거 |
|---|---|---|---|---|
| **A 고객 불편·제품 대조 상품기획** | 한 제품군의 리뷰·제품 자료 → 불편/기능 대조 → 콘셉트·요구사항 | **낮음~중간** | **중상** | 텍스트·표 중심으로 완주 가능. 문제→근거→기획 결과를 보여주기 쉽다. 원자료 선별과 요약 도구 중복은 약점 |

간단한 B는 A와 비슷하게 쉽게 만들 수 있다. A가 모든 경우 더 쉽다는 결론은 아니다. 이 팀의 제한된 구현에서 **근거 있는 결과물과 좁은 자동화 범위를 함께 제시하기 쉬운 쪽**을 골랐다. 반대로 시연의 시각적 인상을 더 중요하게 두거나 검토된 가전 상태·UX 자료가 이미 있다면 B의 순위가 올라갈 수 있다. 이번 두 조건에는 그 가정을 넣지 않았다.

## 선정안이 하는 일

직접 사용자: 키친 가전 상품기획자. 최종 소비자를 대신해 가전을 조작하는 서비스가 아니라, 새 키친 가전·서비스를 기획하는 반복 업무를 맡는다.

1. 기획 요청, 출처가 붙은 리뷰, 모델을 식별할 수 있는 설명서·제품 정보를 입력받는다.
2. 근거 문장을 연결해 불편을 묶고, 모델·시점·용도가 다른 자료를 구분한다.
3. 해당 불편과 기존 기능을 대조해 **기능 부재 확인 / 기능은 있으나 불편 가능 / 근거 부족**을 구분한다. 문서에서 찾지 못한 것을 '기능이 없다'고 단정하지 않는다.
4. 근거가 있는 문제에 개선 콘셉트 2~3개와 요구사항을 제안한다. 기능이 있어도 사용하기 불편한 문제는 개선 대상으로 남긴다.
5. 근거 누락·모델 불일치·기존 기능과의 중복을 검사한다. 실패하면 자료를 다시 조회하거나 제안을 수정하고, 남는 불확실성은 표시한다.
6. 기획자가 선택·수정할 수 있도록 콘셉트 카드, 불편-제품 기능 대조표, 추가 검증 과제를 내보낸다.

예시 요청: “냉장고 정리·청소 불편을 줄일 개선 콘셉트를 찾아줘.” Agent는 불편에 맞는 원문을 찾고 기존 수납·분리·관리 기능과 비교해 개선안을 작성한다. 이 예시는 역할을 설명하기 위한 가상 입력이며, 특정 불편의 실제 빈도나 콘셉트 효과가 입증됐다는 뜻은 아니다. 냉장고나 작은 주방을 전체 주제의 제한으로 고정하지 않는다.

LLM 자체도 이런 분석을 할 수 있다. 따라서 'LLM은 못 한다'를 차별점으로 쓰지 않는다. 출처·모델 연결, 반복 검사와 수정, 같은 형식의 기획 결과를 제공하는 좁은 업무 자동화로 설명한다. Dovetail도 고객 자료 분석과 Agent 기능을 제공하므로 단순 요약·출처 표기만으로 신규성을 주장하지 않는다. 제품별 반대 근거 대조가 실제로 나은 결과를 내는지는 같은 자료를 준 강한 LLM과 비교해야 한다.

## 첫 구현의 경계

- **자료:** 한 제품군, 제품 3~5개, 검토된 리뷰 30~50개를 준비하는 것이 목표다. 확보 완료 수량이 아니다. 초기에는 CSV/문서 업로드와 미리 검토한 자료집을 지원한다. 전 쇼핑몰 자동 수집은 핵심 약속에 넣지 않는다.
- **Agent:** 모델 하나에 자료 조회·제품 대조·근거 검사·결과 저장 도구를 연결한다. 다중 Agent가 필수는 아니다. 결과를 한 번 출력하는 프롬프트를 넘어 검사 실패 시 재조회/수정이 작동해야 한다.
- **화면:** 입력과 기획 결과를 보는 기본 화면. 이미지 생성, CAD, 실가전 제어, 물리 시뮬레이터는 이 기획 업무의 필수 결과물이 아니다.
- **검증:** 서로 다른 요청으로 반복 실행, 잘못 연결된 모델·누락 근거·이미 있는 기능·여전히 남는 사용 불편 사례를 점검한다. 동일 자료의 일반 LLM 결과와 근거 오류·불필요한 제안·수동 수정 시간을 비교한다. 목표 지표이며 아직 측정하지 않았다.

완성 난도를 낮추는 핵심은 '가전 자동 설계'까지 약속하지 않고 **검토 가능한 기획안을 만드는 업무**에서 끝내는 것이다. 결과물만 고정 생성하는 데모로 축소해서는 공식 반복 수행 취지를 충족했다고 할 수 없다.

## 실제 확인 결과와 남은 비용

[Amazon Reviews 2023 공식 프로젝트](https://amazon-reviews-2023.github.io/)의 Appliances 리뷰·제품 메타데이터 경로에 접속해 제한된 앞부분을 내려받고 `parent_asin`으로 연결했다.

- 첫 시도: 리뷰 압축 데이터 256 KiB, 제품 메타데이터 256 KiB → 리뷰 1,491행·제품 310행, 연결된 리뷰 13개/제품 6개.
- 두 번째 시도: 제품 메타데이터만 2 MiB로 확대 → 제품 2,578행, 연결된 리뷰 71개/제품 51개.
- 제품명 단어 필터를 통과한 7개에도 오븐 부품·받침대·계란 보관함이 섞였다. 제목을 직접 검토해 본체로 식별한 것은 제빙기 2개, 연결된 리뷰 3개뿐이다. 해당 표본으로 고객 니즈·국내 수요·LG 제품의 문제를 입증하지 않았다.
- **확인된 것:** 데이터 접근·JSON 파싱·제품 ID 연결은 가능하다. **남은 것:** 대상 제품군의 적절한 원문, 공식 제품 문서와의 모델 대응, 언어·시점·지역 범위, 모델의 분석 성능. 표본은 2023년까지의 해외 자료이며 현재 한국 시장을 대표하지 않는다.

원문·사용자 ID를 저장소에 넣지 않는다. 이번 기록은 접근 결과·수량·해시·한계만 담았다. 데이터 확보와 선별은 여전히 구현 계획의 첫 작업이다. 이를 생략해 '이미 데이터가 충분하다'고 쓰지 않는다.

## 1차 제안서에 넣을 핵심 문장

> 고객 리뷰와 제품 정보를 연결하여 키친 가전의 사용 불편을 분석하고, 기존 기능과의 중복 및 근거 부족을 검토한 뒤, 개선 콘셉트와 제품 요구사항을 반복 작성하는 상품기획 Agent를 개발한다.

Theme A의 숨은 고객 니즈 발굴·제품/서비스 콘셉트 제안에 연결된다. 공식 포함 과제들을 모두 수행하거나 한 행만 골라야 한다는 뜻은 아니다. 원자료→불편→기능 대조→콘셉트→검사/수정의 한 사례를 제안서에서 끝까지 보여주고, 범위와 평가 계획을 함께 적는 것이 이 안의 서류 전략이다.

공식 자료는 A를 상품기획, B를 UX/UI 시나리오 설계 직무로 안내하며, 신청 제안서는 HWP 10쪽 이내다. [공식 신청 안내](https://anchor.changwon.ac.kr/main/menu?gc=Program&do=sinform&spod=s1&program_id=VUlvrXMnryLR&psin_id=VUlvrXN53VEd), `자료/공식/04_LG키친솔루션_해커톤주제.pdf` 19~20·29~31쪽, `docs/대회요건.md`를 근거로 검토했다. 1차 전용 배점·경쟁 팀 수준은 미확인이라 합격 보장은 할 수 없다.

## 완료와 미완료

두 조건 재비교·공개 데이터 접근 실험·구현 범위 검토·출품 방향 선정까지 완료했다. 설계 상세·Agent 구현·강한 LLM 비교·공식 HWP 제안서·서명·접수는 아직 완료하지 않았다. 이전 후보와 실험은 역사 기록으로 보존한다. 다음 단계는 이 선정안의 상세 설계와 공식 6항목 제안서다.
