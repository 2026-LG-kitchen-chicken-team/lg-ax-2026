# 제안서 시각자료

다섯 파일은 `scripts/build_proposal_visuals.py`에서 직접 작성한 설명 도식이다. 목적은 아이디어, Agent의 작동 방식, 기획자의 사용 예시를 빠르게 이해하도록 돕는 것이다.

| 파일 | 제안서 위치 | 전달할 내용 |
|---|---|---|
| `01_아이디어_한눈에.png` | 1. 개요 | 누가 무엇을 넣고 어떤 기획 결과를 받는가 |
| `02_Agent_작동방식.png` | 3. 활용정보 | 불편 정리 → 기존 기능 대조 → 콘셉트 작성 → 중복·근거 검사와 수정 |
| `03_냉장고_사용예시.png` | 4. 설명 및 차별성 | 기획 요청과 리뷰·설명서에서 남은 불편을 찾아 구획별 탈착 트레이 콘셉트로 연결 |
| `04_식기세척기_사용예시.png` | 4. 설명 및 차별성 (계속) | 기본 적재 그림과 실제 식기 조합의 차이를 찾아 조합별 배치 안내 서비스를 제안 |
| `05_전자레인지_사용예시.png` | 4. 설명 및 차별성 (계속) | 저장·호출 기능과 겹치는 후보를 제외하고 남은 불편을 확인할 질문을 작성 |

후속 요청으로 사용 예시를 세 가지로 늘렸다. 제품 구조 개선, 서비스 기획, 기존 기능 중복 제외라는 서로 다른 결과를 같은 레이아웃으로 비교한다. 각 예시는 제안서에서 한 페이지를 사용하며, 제안서 전체는 8쪽이다. 최초 참가작 구현은 냉장고 자료부터 시작한다.

2026-09-27 사용자 요청으로 비교 평가 계획 그림과 긴 메타 주석을 제거했다. 사용 예시는 짧은 제목과 구체적인 입력·판단·출력, 냉장고·트레이 선형 도식으로 설명한다. 합성 입력과 향후 구현 범위는 본문에서 설명하며 그림에 반복하지 않는다. 일정·평가 계획은 추진방향 본문과 설계 문서로 관리한다. 이전 그림은 Git 제외 `tmp/proposal_visuals/previous/`에 보관했다.

Windows의 맑은 고딕 폰트, reportlab, Poppler로 다시 생성한다. PNG는 300 dpi로 내보내며 한글 파일에 그림으로 내장한다. 제안서의 설명 문장은 편집 가능하다. 도표 내부 문구를 바꿀 때는 생성 스크립트 수정 → 도표 재생성 → 한글 작성본 재생성 → PDF 시각 검수 순서로 반영한다.

## 디자인 참고와 적용

확인일: 2026-09-27. 사용자 요청에 따라 공식 웹 가이드와 실제 예시를 참고했다. 원본 도식을 복사하지 않고 현재 Agent 내용에 맞춰 직접 작성했다.

- [IBM Design Language, Technical diagrams](https://www.ibm.com/design/language/infographics/technical-diagrams/design/): 작업 흐름과 운영 구조 예시를 시각 확인. 일정한 격자, 노드 정렬, 직선 연결, 짧은 라벨, 연결 의미의 명시를 적용했다.
- [Carbon Design System, Data table style](https://carbondesignsystem.com/components/data-table/style/): 이전 표의 헤더·본문 계층과 중립색 대비를 참고했다. 현재는 표를 없애고 같은 대비·간격 원칙을 설명 도식에 적용했다.
- A4 인쇄에 맞춰 흰 배경, 검정·회색 본문, 최소한의 강조색, 가로 구분선 위주로 구성했다. 원문 숫자나 측정하지 않은 성과를 시각화하지 않았다.

최종 점검에서 개요의 출력 수를 최대 3개로 맞췄고, 전자레인지 질문을 기능을 알고 사용했는지부터 확인하도록 보완했다. 기존 기능이 있더라도 고객의 불편이 해결됐다고 단정하지 않는다.

서명·작성된 신청서 등 개인 자료는 이 폴더에 넣지 않으며 Git 제외 `private/`에서 관리한다.
