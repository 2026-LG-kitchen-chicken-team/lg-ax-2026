## Theme A

### A1. 리뷰 속 조리 후 청소 부담을 찾아 개선 기능을 기획하는 Agent

**공식 포함 가능 과제:** SNS·검색 트렌드·제품 리뷰를 활용한 숨은 고객 니즈 발굴

**고객에게 제공할 제품/경험:** 조리 뒤 분해·닦기·건조·정리에 남는 수고를 줄이는 제품 기능이나 관리 서비스.

**예시:** 허가된 리뷰에서 '닦기 어려운 부분'을 찾아 기존 세척 기능으로 해결되는지 대조하고 남은 불편에 대한 기능 제안.

**Agent가 하는 일:** 고객 원문 수집→청소 작업·불편 구조화→모델별 기능/설명서 대조→반대 근거→개선 콘셉트.

**이 항목에서 고른 이유:** 단순 긍정/부정 요약보다 실제 수행 작업과 미충족 요구를 연결하므로 숨은 니즈 발굴에 적합.

**비교한 대안:** 범용 리뷰 감성 분석: 이미 알려진 불만 요약으로 끝날 가능성이 높음.

**LLM/기존 도구 대비 검증할 가치:** 모델·시점·출처별 반박과 데이터 추가 시 기획 갱신. Dovetail/문서 LLM 대비 수작업 감소를 입증해야 함.

**최소 범위·난도:** 실제 사용 권한이 있는 의견 30~50개, 2개 제품군 이내. 초기 목표 수량이며 아직 확보한 데이터가 아님. 중.

**가장 큰 문제:** 실제 원문 확보·대표성·기존 기능 중복.

**검증 지표:** 근거 연결 오류, 중복 불편 제거, 잘못된 신규 기능 제안, 검토 시간.

**출처·이력:** R10, S7, S9. A10의 조사 범위를 조리 후 청소 작업으로 구체화.

### A2. 1~2인 가구의 작은 주방에 맞는 가전 형태를 기획하는 Agent

**공식 포함 가능 과제:** 미래 라이프스타일과 가구 형태 변화에 따른 가전 및 폼팩터 제안

**고객에게 제공할 제품/경험:** 좁은 설치 공간과 필요한 용량·문 열림을 함께 만족하는 제품 형태 또는 배치 지원 서비스.

**예시:** 본체는 들어가도 문이 열리지 않는 조건을 찾아 크기·접근 방식 요구사항을 수정.

**Agent가 하는 일:** 가구·공간 조건→제품 명세 수집→치수·설치 제약 계산→미충족 조건→폼팩터/서비스 콘셉트.

**이 항목에서 고른 이유:** 가구·생활 변화가 제품 크기와 사용 방식으로 어떻게 이어지는지 계산과 근거로 보여줄 수 있음.

**비교한 대안:** 그냥 작은 냉장고 추천: 기존 상품 검색 결과에 그치며 기획 직무가 약함.

**LLM/기존 도구 대비 검증할 가치:** 설명서 조건 보존·단위 계산·미확인 질문·기존 공간 기능 반증. 스프레드시트 대비 검토 비용 비교.

**최소 범위·난도:** 한 제품군 5~10모델, 검토된 공간 사례 3개, 2D 수치 비교. 중.

**가장 큰 문제:** 모델별 설치·문 열림 자료와 실제 수요. 제조 가능성 별도.

**검증 지표:** 제약 누락·단위 오류·모델 혼동·새 모델 추가 시 요구사항 수정.

**출처·이력:** R1, R2. 기존 A8.

### A3. 농업·우주 분야에서 식재료 보관 기술을 찾는 기술 탐색 Agent

**공식 포함 가능 과제:** 논문·특허·기술 뉴스를 활용한 타 산업 기술 탐색

**고객에게 제공할 제품/경험:** 가정용 보관 모듈에 검토할 만한 선도 유지 기술 후보와 적용 조건.

**예시:** 농산물 저장·우주 재배 관련 기술을 찾아 작동 원리, 적용 규모, 소모품·전력, 검증되지 않은 조건을 비교.

**Agent가 하는 일:** 보관 문제 정의→논문/특허/기관 자료 탐색→원리·실험 조건 추출→가정용 적용 제약→기술 후보 카드·제품 가설.

**이 항목에서 고른 이유:** 범용 논문 요약보다 하나의 주방 문제를 기준으로 기술의 적용 가능성과 한계를 비교하는 역할이 명확함.

**비교한 대안:** 전 산업 기술 동향 요약: 비교 조건이 분산돼 설계와 평가가 어려움.

**LLM/기존 도구 대비 검증할 가치:** 원문 조건과 주장 추적, 상충 근거 비교. 일반 리서치 Agent와의 정확도/시간 비교 필요.

**최소 범위·난도:** 사람이 검토한 기술 문헌 10개 내외의 작은 자료집. 출처·수치·검증 조건 비교. 중~상.

**가장 큰 문제:** 원문 이해·실험 조건 전용·특허 권리 및 제조 가능성 미확인.

**검증 지표:** 원문 주장·수치 인용 정확도, 적용 불가 조건 누락, 근거 없는 성능 추정.

**출처·이력:** T1, T2. 기존 Cross-Tech Scout를 식재료 보관 문제로 제한.

### A4. 농산물 유통의 재고·이력 관리 원리를 가정용 보관 서비스로 옮기는 Agent

**공식 포함 가능 과제:** 자동차·의료·로봇·항공·농업 등 타 산업 기술의 키친 적용

**고객에게 제공할 제품/경험:** 보관 위치·입고/개봉 기록·표시 기한을 묶어 먼저 확인하고 사용할 항목을 안내하는 냉장고/보관함 서비스.

**예시:** 기한이 알려진 식재료와 모르는 식재료를 구분하고, 여러 공간에 분산된 재고의 확인 순서를 제안.

**Agent가 하는 일:** 유통 재고 원리→가정의 기록 부담/보관 조건 매핑→태그·구획·확인 규칙 설계→누락·변경 사건 검사→제품/서비스 콘셉트.

**이 항목에서 고른 이유:** 이미 알려진 산업 원리를 구체적인 가정용 기능·데이터 구조로 옮겨 적용 과정 자체를 시연 가능.

**비교한 대안:** 주방 로봇 팔 자동 정리: 기구·인식·실물 검증 의존이 큼.

**LLM/기존 도구 대비 검증할 가치:** 이력 누락·위치 이동·중복 등록 규칙을 실행하고 적용안을 수정. 재고 앱 대비 새 콘셉트 가치 필요.

**최소 범위·난도:** 수동/QR 입력한 재고·위치·표시 기한, 예시 보관함 3개. 자동 센싱과 실제 신선도 추정 제외. 중.

**가장 큰 문제:** 사용자 기록 부담과 기존 재고 앱 대비 가치. 날짜만으로 섭취 안전을 판단하지 않음.

**검증 지표:** 누락 처리·중복/위치 불일치 검출, 입력 수고, 기능 중복.

**출처·이력:** T3, T4, O2. 새 후보; A3의 기술 검색과 달리 선택된 원리의 기능 적용에 집중.

### A5. 조리 동작 인식으로 레시피 진행 안내 기능을 기획하는 Agent

**공식 포함 가능 과제:** 이미지·영상·음향 등을 활용한 음식 및 조리 상태 인식

**고객에게 제공할 제품/경험:** 사용자가 매 단계 화면을 넘기지 않아도 관찰된 동작을 바탕으로 다음 안내를 제안하는 주방 보조 기능.

**예시:** 짧은 영상의 자르기·붓기·젓기 등 관찰 가능한 행동과 불확실 구간을 표시해 '다음 단계 확인' 안내 기능을 설계.

**Agent가 하는 일:** 영상/선택적 음향→제한된 동작 인식 도구→레시피 단계 대응→불확실성·미확인 처리→오류 분석→제품 기능/센서 요구사항.

**이 항목에서 고른 이유:** 익음·부패 같은 관측하기 어려운 상태보다 행동 라벨을 검토하기 쉬워 멀티모달 기능의 평가 범위를 정할 수 있음.

**비교한 대안:** 사진 한 장으로 익음·부패·안전 판정: 관측 한계와 오류 영향이 큼.

**LLM/기존 도구 대비 검증할 가치:** 시간 구간과 불확실성을 기록하고 오인식에 따라 기능을 보수적으로 재기획. 기존 영상 LLM 대비 평가 필요.

**최소 범위·난도:** 영상 우선, 3개 동작, 허가·라이선스 확인한 짧은 클립 20~30개 목표. 새 모델 학습 없이 기존 멀티모달 모델/도구 검토. 상.

**가장 큰 문제:** 행동과 레시피 완료는 다름. 가림·동시 행동·환경 변화 및 실제 모델 성능 미검증.

**검증 지표:** 동작 구간 정답·오인식·보류율·잘못된 다음 단계 제안.

**출처·이력:** T5, T6. 새 후보; 직접 영상 판독 프로그램만으로 끝내지 않고 제품 기능 기획 산출물을 포함.

### A6. 소량 조리 가구를 위한 1회분 보관 모듈·재고 연동 서비스를 기획하는 Agent

**공식 포함 가능 과제:** 발견한 고객 니즈와 기술을 결합한 신규 제품·서비스 콘셉트 제안

**고객에게 제공할 제품/경험:** 한 번에 쓸 양으로 나누는 용기/구획과 재고 정보를 연결하는 제품·서비스 결합 콘셉트.

**예시:** 식재료 한 팩을 여러 번 나눠 쓰는 가구의 필요에서 용기 단위·필요 수량·꺼내기 동작·기록 방식을 조합.

**Agent가 하는 일:** 검증할 고객 니즈→기존 소분 용기·재고 기능 비교→구획/표시/입력 기술 조합→불편·부품 의존 검토→콘셉트 카드.

**이 항목에서 고른 이유:** 고객의 작업 부담과 구체적인 물리 제품·디지털 서비스를 함께 설계해 니즈+기술 결합을 명확히 표현.

**비교한 대안:** 용량·에너지 차트만 생성: 제품/서비스 콘셉트와 고객 니즈 연결이 부족.

**LLM/기존 도구 대비 검증할 가치:** 여러 제약과 기존 기능을 대조하며 콘셉트 조합을 수정. 단순 아이디어 프롬프트와 비교 필요.

**최소 범위·난도:** 식재료 3종의 대표 사용 시나리오, 수동 입력/QR 기반 서비스 목업과 모듈 요구사항. 중.

**가장 큰 문제:** 실제 니즈·기존 용기 차별성·세척/보관 부담·제조 실현성 미검증.

**검증 지표:** 니즈-기능 연결, 기존 기능 중복, 기록 단계/부품 수, 확인 안 된 효과 주장.

**출처·이력:** T7, R10, O2. 새 후보; A4는 재고 이력 원리 전이, 이 후보는 1회분 물리 모듈+서비스 조합.

## Theme B

### B1. 보관→조리→정리를 잇는 최소 조작 주방 시나리오 설계 Agent

**공식 포함 가능 과제:** 보관·조리·세척을 연결하는 Zero-Touch Kitchen

**고객에게 제공할 제품/경험:** 한 끼 과정에서 기기·앱마다 반복하는 확인/설정을 줄이고 다음 단계로 정보를 넘기는 경험.

**예시:** 재료 확인→조리 준비→완료→보관/세척 안내에서 자동으로 넘길 정보와 사람의 확인이 필요한 동작을 분리.

**Agent가 하는 일:** 한 끼 작업 흐름·기기 기능→단계별 인계 설계→지원/수동 확인 제약 검사→반복 입력 줄이기→정상/중단 UX.

**이 항목에서 고른 이유:** Zero-Touch의 핵심인 단계 간 연결과 조작 감소를 다루며, 구현되지 않은 물리 자동화를 약속하지 않고 시나리오를 검증 가능.

**비교한 대안:** 로봇이 준비부터 설거지까지 수행: 현재 실기기·로봇 환경이 없음.

**LLM/기존 도구 대비 검증할 가치:** 연결 시 상태/중단/사람 확인을 실행해 검사. 완전 무인 서비스 구현을 의미하지 않음.

**최소 범위·난도:** 보관·조리·정리 3단계, 검토된 기능 계약, 사람 개입을 표시한 웹 상태 목업. 중~상.

**가장 큰 문제:** 기기 API와 실제 자동화 범위. 손으로 해야 하는 작업을 자동 완료로 처리하면 안 됨.

**검증 지표:** 시나리오상 중복 입력·명시된 개입 횟수, 미지원 전이, 미확인 완료 처리.

**출처·이력:** O1, S4. 기존 보조 검사 재사용 가능; B4의 동시 일정과 달리 단계 간 인계가 중심.

### B2. 가족별 취향과 식사 조건을 함께 맞추는 조리 경험 설계 Agent

**공식 포함 가능 과제:** 사용자의 취향·건강·상황을 고려한 개인 맞춤형 조리

**고객에게 제공할 제품/경험:** 공통 조리와 개인별 옵션을 나눠 메뉴·준비 과정을 조정하는 가족 식사 경험.

**예시:** 같은 기본 요리에서 한 사람은 특정 재료 제외, 다른 사람은 다른 양을 원할 때 공통 단계와 분기 안내를 설계.

**Agent가 하는 일:** 명시된 취향·제외 조건·시간·인원→충돌/모르는 조건 질문→검토된 조리 옵션 구성→제약 검사→개인별 안내 UX.

**이 항목에서 고른 이유:** 무작정 레시피를 늘리는 것보다 가족 조건 충돌을 해결하는 경험이 구체적이고 조건 변경 시 재사용을 시연 가능.

**비교한 대안:** 질환별 자동 식단 처방: 전문적 근거와 개인 건강정보·검증 부담이 큼.

**LLM/기존 도구 대비 검증할 가치:** 가족 조건의 충돌·추가 질문·분기 안내 검사. LLM/기존 식단 앱보다 준비 수고가 줄어야 함.

**최소 범위·난도:** 가족 2~3명, 검토된 요리 3개, 취향/양/시간 우선. 건강 조건은 명시 입력만 전달하고 의학적 적합성 판단 제외. 중.

**가장 큰 문제:** 기존 맞춤 식단과 중복·레시피 변형 타당성. 알레르기 무해성 보증 불가.

**검증 지표:** 제외 조건 위반·불가능 조건 탐지·준비 단계/수동 수정량.

**출처·이력:** O2, R7. 새 후보.

### B3. 식재료 교체 때 알레르기 정보 재확인을 요구하는 UX 설계 Agent

**공식 포함 가능 과제:** 식재료의 신선도·알레르기·안전을 관리하는 스마트 키친

**고객에게 제공할 제품/경험:** 메뉴·제품이 바뀌었을 때 기존 확인을 그대로 재사용하지 않고 성분 정보와 미확인 항목을 다시 검토하는 경험.

**예시:** 선택한 소스를 다른 제품으로 바꾸면 성분 확인을 다시 요청하고 정보가 없으면 '확인 필요'를 유지.

**Agent가 하는 일:** 알레르기 확인 과제·표시 자료·변경 사건→확인/보류/안내 흐름→누락 정보 검사→화면·검토 기록.

**이 항목에서 고른 이유:** 관측 없는 신선도 판정보다 입력 출처와 변경 시점이 분명한 확인 누락 문제에 집중하여 검사 범위를 정할 수 있음.

**비교한 대안:** 이미지로 신선도와 섭취 안전 종합 판정: 필요한 정보가 부족하고 오류 영향이 큼.

**LLM/기존 도구 대비 검증할 가치:** 근거 버전·변경 후 재확인·미확인 상태를 강제하는 검사. 실제 위험 감소는 별도 전문 검토 필요.

**최소 범위·난도:** 검토된 예시 제품 표시 10개 목표, 교체/누락/표시 변경 사건의 UX 목업. 임상·식품 안전 시스템 아님. 중~상.

**가장 큰 문제:** 제품 표시·교차접촉·국가별 정보 차이. 경고가 없다는 이유로 안전 판정 불가.

**검증 지표:** 정보 누락/변경 때 잘못 완료 처리한 비율, 출처 보존, 재확인 경로.

**출처·이력:** T8. 새 후보; 안전 관리 과제 중 알레르기 정보 확인 UX에 한정.

### B4. 가전 자원과 조리 지연에 맞춰 다시 계획하는 식사 준비 UX 설계 Agent

**공식 포함 가능 과제:** 가전 간 연계를 통한 AI 기반 키친 서비스

**고객에게 제공할 제품/경험:** 여러 요리를 준비할 때 기기와 사람 작업의 충돌을 줄이고 지연 발생 후 남은 안내를 조정하는 경험.

**예시:** 오븐 1대를 두 요리가 동시에 요구하거나 한 작업이 늦어지면 가능한 작업 순서·알림을 재설계.

**Agent가 하는 일:** 기기/작업/시간 조건→일정 구조화→계산 도구→불가능 조건·대안→타임라인·알림 UX→변경 후 재검사.

**이 항목에서 고른 이유:** 가전 연계가 왜 필요한지 자원 충돌과 조건 변화로 보여줄 수 있고 코드로 실행 가능성을 검사 가능.

**비교한 대안:** 그냥 가전 원격 제어 챗봇: 기존 기능과 겹치고 UX 설계 역할이 약함.

**LLM/기존 도구 대비 검증할 가치:** 자연어 조건 추출과 실행 가능한 재계획·안내 생성. 강한 LLM/일정 계산기 비교 필요.

**최소 범위·난도:** 검토된 요리 3개, 기기 2종, 작업자 1명. 실물 제어 없이 가정된 상태 변화로 시연. 중.

**가장 큰 문제:** 실제 작업 시간·능동 작업 구간·계산기 대비 AI 기여.

**검증 지표:** 자원 충돌·선행 위반·불가능 판정·지연 시 재작업량.

**출처·이력:** R6, O1. 기존 B8; 공식 표에서 B의 네 번째 항목.

### B5. 남는 재료와 인분 변화를 반영하는 한 끼 분량 UX 설계 Agent

**공식 포함 가능 과제:** 식재료·물·에너지 사용을 최적화하는 지속가능한 키친

**고객에게 제공할 제품/경험:** 집에 있는 재료·포장 단위·먹을 인원으로 사용할 양과 남을 양을 보여주고 다음 식사에 재료를 이어 쓰는 경험.

**예시:** 식사 인원이 2명에서 1명으로 바뀌면 재료 사용량·남는 양·추가 구매 목록과 안내를 함께 수정.

**Agent가 하는 일:** 재고·검토된 레시피 양·인분→단위/수량 계산→부족/잔여 조건→조리·장보기 안내→조건 변경 재계산.

**이 항목에서 고른 이유:** 식재료 사용 최적화에 좁히면 센서 없이 수량을 검증할 수 있고 행동 변화 전후를 구체적으로 표현 가능.

**비교한 대안:** 식재료·물·에너지 모두를 한 번에 최적화: 실사용 계측과 물리 모델이 필요해 범위 과다.

**LLM/기존 도구 대비 검증할 가치:** 질량/수량 보존·부족·인분 변경의 일관성 검사. 레시피 추천 자체는 차별점 아님.

**최소 범위·난도:** 재료 10종·레시피 3개 목표, 명시 수량·단위. 실제 폐기/물/전력 절감 수치 미주장. 하~중.

**가장 큰 문제:** 입력 유지 부담과 기존 Use It Up/식단 앱 대비 차별성. 레시피 양의 단순 선형 확대 한계.

**검증 지표:** 수량 오류·중복 구매 제안·예상 잔여량, 실제 폐기 감소는 별도 실사용 측정.

**출처·이력:** O2, R7. 새 후보; A4 보관 이력과 달리 한 끼 수량·소비 안내가 중심.

### B6. 이사·동거로 생활이 바뀔 때 적응하는 모듈형 주방 UX 설계 Agent

**공식 포함 가능 과제:** 새로운 제품·서비스가 적용된 미래 키친 생활 시나리오

**고객에게 제공할 제품/경험:** 보관·조리 모듈을 재배치/추가하는 미래 제품을 가정하고 가족·공간 변화에 따라 설정과 일상을 다시 연결하는 경험.

**예시:** 혼자 살던 사용자가 동거를 시작하면 개인/공용 보관·식사 시간·새 모듈 등록과 첫 사용 안내가 달라짐.

**Agent가 하는 일:** 미래 모듈 기능 계약·생활 변화→이전/이후 여정→설치/등록/첫 사용 시나리오→설정/권한/불가능 전이 검사→화면·스토리보드.

**이 항목에서 고른 이유:** 미래라는 표현에 머무르지 않고 새 제품이 일상 변화에서 어떻게 쓰이는지 전후 상황으로 보여줄 수 있음.

**비교한 대안:** 미래 주방 영상·스토리보드만 생성: 반복 업무와 경험 검증을 보여주기 어려움.

**LLM/기존 도구 대비 검증할 가치:** 하나의 이야기 대신 기능 계약에 맞춘 여러 변화 시나리오와 검증 기록. 물리 제품 실현은 미검증.

**최소 범위·난도:** 가정된 보관/조리 모듈 2종, 이사·동거 2사건, 명시된 지원 기능만 사용하는 웹 목업. 중.

**가장 큰 문제:** 가상 제품의 과도한 능력 가정·실수요·제품 실현성.

**검증 지표:** 설정 누락·역할/권한 충돌·미지원 단계·상황 변경 재설계 비용.

**출처·이력:** O1, R1, R2. 새 후보; A2는 제품 형태 기획, 이 후보는 주어진 미래 제품의 생활 경험 설계.


## 비슷해 보이는 항목의 차이

- A3은 여러 산업에서 기술을 **찾아 적용 조건을 비교**하는 연구 업무, A4는 선택한 유통 이력 원리를 **가정용 기능으로 옮겨 구체화**하는 업무다.
- A4는 식재료의 위치·날짜·변경 이력 관리, A6는 1회분 물리 모듈과 디지털 서비스의 조합, B5는 한 끼의 사용량·잔여량·인분 변경 경험이다.
- B1은 보관→조리→정리의 **단계 간 인계와 반복 조작 감소**, B4는 **여러 기기의 자원 충돌·동시 작업·지연 후 재계획**에 집중한다.
- A2는 가구·공간 변화로 **어떤 제품 형태가 필요한가**를 기획한다. B6는 명시적으로 가정한 미래 모듈 제품을 **이사·동거 이후 어떻게 쓰는가**를 설계한다.

## 전체 후보를 함께 볼 때

현재 조건에서 먼저 검증할 후보는 B4 가전 연계 재계획, A2 작은 주방 가전 기획, B2 가족 조건별 조리 경험이다. 이는 기존 B8/A8 우선 검토의 연속이며 새 명칭으로 무조건 다시 확정한 것이 아니다. 최종 주제는 여전히 미확정이다.

A3/A5는 기술 문헌·멀티모달 평가 부담, B3는 정보 정확성과 실제 사용자에게 전달되는 안전 오해 위험, B1은 실제 자동화 범위가 주요 부담이다. 그 항목도 요청대로 빠짐없이 가장 범위가 명확하다고 판단한 대표안을 제시했다.

## 출처

기존 출처 R1~R10/O1~O2는 `research/official_alignment/comparison.json`, S4/S7/S9는 `harness/project.json`에 있다. 새 확인 출처는 다음과 같다.

- **T1 [NASA 에틸렌 제거 기술 사례](https://www.nasa.gov/technology/tech-transfer-spinoffs/at-home-nasa-spinoffs-create-a-breath-of-fresh-air/)**: 보관 문제에 관련된 우주 기술의 이전 사례. 한계: 이미 소개된 기술로 신규 발명/효능 보증이 아니며 가정용 조건은 별도.
- **T2 [WIPO PATENTSCOPE](https://www.wipo.int/en/web/patentscope)**: 특허 문헌 탐색 경로. 한계: 권리 판단·전체 신규성 조사·자동 수집 권한 확인은 수행하지 않음.
- **T3 [GS1 추적 표준](https://www.gs1.org/standards/gs1-global-traceability-standard/current-standard)**: 물체·장소·사건 이력 관리 원리. 한계: 국제 유통 표준을 가정용 서비스에 적용하는 안은 우리의 제안.
- **T4 [GS1 농산물 이력 안내](https://www.gs1.org/standards/fresh-fruit-and-vegetable-traceability-guideline/current-standard)**: 농산물 유통 사건과 식품 이력 구조. 한계: 섭취 안전이나 가정용 실효성 보증 아님.
- **T5 [EPIC-KITCHENS](https://epic-kitchens.github.io/)**: 주방 동작 영상 데이터셋과 연구 과제 존재. 한계: 다운로드·라이선스·특정 동작의 필요 표본 수·우리 모델 성능은 미검증.
- **T6 [EPIC-SOUNDS](https://epic-kitchens.github.io/epic-sounds/site)**: 주방 행동 소리 구간 주석 데이터 존재. 한계: 음향만으로 조리 완료/안전 판정 불가; 이번에 학습·평가 실행 안 함.
- **T7 [LG 식품 보관 안내](https://www.lg.com/us/support/help-library/lg-refrigerator-storage-im-curious-about-how-to-store-different-foods--20154629492130)**: 소량으로 나눠 보관하는 안내의 존재. 한계: 1회분 모듈 수요·기존 제품 대비 이득이나 안전 보증의 증거 아님.
- **T8 [FDA 알레르기 표시 안내](https://www.fda.gov/consumers/consumer-updates/have-food-allergies-read-label)**: 성분 및 주의 표시를 확인할 필요. 한계: 미국 안내이며 국내 규정 전체를 대신하지 않음; 경고 부재를 안전으로 판단할 수 없음.

공식 과제명은 사용자 첨부 표를 그대로 대응했다. 대회의 직무·산출물 해석은 보관된 공식 주제 PDF 19~20·28쪽 및 대회요건 문서에 근거한다. 이번 완료 범위는 목표 정리·출처 조사·12개 대표안 도출·비교이고, 모델 호출 실험·제품 제작·사용자 검증·접수는 포함되지 않는다.
