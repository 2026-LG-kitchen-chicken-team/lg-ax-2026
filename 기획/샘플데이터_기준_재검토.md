# 샘플 입력·모의 연동을 공통 적용한 재검토

2026-09-27. 사용자 정정: 리뷰를 포함해 시연에 필요한 데이터는 우리가 만든 샘플로 준비하는 방안도 고려한다. 같은 원칙을 다른 후보의 유사 의존성에도 적용한다.

## 바뀐 판단 기준

구현 난도와 1차 서류 설득력의 두 축은 유지한다. **먼저 모든 후보를 샘플 데이터·가상 제품 명세·모의 API로 구현할 수 있는 최소 범위로 비교한다.** 실제 데이터 수집과 실기기 연결은 해당 기능을 실제로 주장해야 하는 경우에만 필수 부담으로 포함한다.

앞선 평가에는 운영용 자료 확보와 시연용 Agent 개발의 부담이 섞여 있었다. 공개 리뷰 수집을 반드시 마쳐야 첫 시연을 만들 수 있다는 전제를 제거한다. B에도 같은 완화를 적용한다. 샘플 작성·일관성 검토에는 작업이 들지만, 외부 데이터·실기기 접근과 동일한 비용이나 장애로 취급하지 않는다.

## 공통 대체 방법과 실제 구현할 부분

| 항목 | 시연에서 준비할 수 있는 것 | Agent가 실제 수행할 부분 |
|---|---|---|
| 고객 리뷰 | 우리가 작성한 가상 리뷰 CSV, 별도로 표시한 공개 자료 표본 | 불편 추출·제품 연결·대조·제안·근거 검사 |
| 제품 기능·치수 | 가상 제품 3~5종의 일관된 명세표 | 요구 충족·충돌 계산과 후보 수정 |
| 가족·생활 조건 | 가상의 가구·공간·취향·일정 | 변경된 조건을 해석하고 결과 재작성 |
| 가전 상태·연동 | 준비·사용 중·완료·오프라인을 반환하는 모의 API | 상태 조회·실패 감지·흐름 수정 |
| 조리 시간·사용 자원 | 가상의 작업·소요 시간·선후 관계 | 자원 충돌·마감 검사와 재계획 |
| 사용자 화면 | 고정 UI 구성요소와 화면 템플릿 | 생성한 흐름을 화면에 연결하고 선택에 따라 상태 변경 |
| 기술 자료 | 선별된 문헌 묶음, 명시적으로 가상인 시험 입력 | 조건 추출·적용 제약·추가 검증 항목 제시 |

샘플 입력을 준비해도 분석·계산·검사·수정은 실행해야 한다. 결과를 미리 정한 화면만 재생하는 것으로 대체하지 않는다. 동일 자료에서 요청을 바꾸거나 누락·충돌 입력을 추가했을 때 결과가 변하는지를 확인한다. 샘플 수와 제품 수는 계획 예시이며 이번에 새 자료집이나 API를 만든 것은 아니다.

## 여섯 후보에 적용한 비교

정성적 구현 검토이며 공식 점수·합격 확률·실측 개발 기간은 아니다. 서류 설득력은 문제 배경에 실제 근거를 붙이고 합성 입력의 범위를 설명하는 제안서를 전제로 한다.

| 후보 | 공통 샘플 전제의 구현 난도 | 1차 서류 설득력 | 샘플을 준비한 뒤에도 남는 핵심 |
|---|---|---|---|
| **A 고객 불편·제품 대조 상품기획** | **낮음~중간** | **중상** | 불편·기능·제안의 근거 연결과 수정 |
| A 생활 조건별 폼팩터 기획 | 낮음~중간 | 중상 | 치수 계산과 형태 제안의 연결. 개념·2D 도식 범위, 제조 검증 약속 없음 |
| A 타산업 기술 적용 기획 | 중간 | 중간~중상 | 문헌의 조건을 다른 용도에 적용할 논리. 가상 기술 성능으로 실효성 입증은 불가 |
| B 사용자 흐름·화면 초안 | 낮음~중간 | 중간 | 흐름과 화면 생성·수정. 일반 생성 도구와의 중복 |
| B 가전 연계 설계·검사 | 중간 | 중상 | 모의 상태·자원·사용자 역할·화면 간 일관성. 물리 시뮬레이터는 제외 |
| B 가구별 조리 정책 설계 | 낮음~중간 | 중간 | 샘플 조건의 우선순위·충돌과 안내 흐름 연결 |

**Theme A 고객 불편·기존 제품 대조 상품기획 Agent 선정을 유지한다.** A만 자료를 미리 준비할 수 있어서가 아니다. 텍스트·표의 근거 연결과 기획안 수정으로 좁은 업무를 끝낼 수 있다는 점을 선택 이유로 삼는다. 폼팩터 A도 개념 수준으로 줄이면 비슷한 난도까지 내려오므로 큰 난도 차이를 주장하지 않는다. 가전 연계 B는 이전의 '중간~높음'에서 '중간'으로 낮추며, 더 많은 산출물 사이의 일관성이 남는 작업이다.

이는 비슷한 후보 중 현재 범위를 더 단순하게 유지할 수 있다는 판단이다. A의 합격률이 B보다 높다고 입증한 것은 아니다. 제품별 대조와 수정까지 구현하지 못하고 리뷰 요약만 남는다면 선정안의 서류상 강점도 약해진다.

## 시연 자료와 문제 근거의 역할

- **직접 만든 리뷰·제품·상태:** Agent의 반복 수행, 오류 처리, 재계획을 시험한다. 합성/가상 자료로 표시한다.
- **실제 문서·관찰·리뷰:** 왜 이 문제가 필요한지 설명하는 근거다. 시연 자료 전체를 실제 데이터로 채워야 한다는 의미는 아니다.
- 합성 리뷰로 실제 고객 비율을 산출하거나 모의 API를 실가전 제어 성공으로 보고하지 않는다. 모델 실행과 모의 외부 환경은 함께 사용할 수 있다.

제안서의 구현 계획은 '초기에는 자체 제작 샘플 리뷰·제품 명세와 모의 상태로 반복 실행을 검증하고, 이후 실제 자료·연동으로 범위를 확장한다'로 쓸 수 있다. 실제 수요·효과·차별성은 별도로 입증할 항목이다.

## 이번에 확인하고 기록한 범위

기존 `research/theme_selection/probe_inputs.json`은 합성 공간·작업 시간·자원 조건을 사용했고, `research/topic_trial/protocol.md`는 기능 추가·누락·완료 이벤트를 합성 입력으로 구분했다. 이 자료와 저장된 실행 결과를 재검토했다. 기존 코드 실험은 이런 분리가 가능하다는 제한된 사례이며, 새 선정안 전체의 모델 성능이나 UX를 검증한 것은 아니다. 이번에는 새 모델 호출·샘플 제작·실기기 실행을 하지 않았다.

샘플 우선 원칙과 여섯 후보의 난도 보정을 하네스 brief·비교·선정 근거에 반영했다. 다음은 이 원칙으로 선정안의 상세 설계와 제안서를 작성하는 단계다. 접수와 Agent 구현은 미완료다.
