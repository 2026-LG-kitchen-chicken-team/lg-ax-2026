# 최종 선정: Theme A · Kitchen Gap

**사람에게 남은 주방 수고를 찾아, 기존 제품 기능과 대조하고 근거 있는 제품·서비스 기회를 제안하는 AI 상품기획 Agent.**

선정일: 2026-09-27. 선정자: Codex, 사용자 위임에 따른 결정. 사용자가 개별 아이디어를 직접 승인했다고 기록하지 않는다. 근거: [3개 후보 검증 결과](주제검증_결과.md). 이 문서는 주제·범위 결정서이며 공식 HWP 제안서가 아니다.

## 누구의 어떤 문제를 해결하는가

사용자는 **주방 가전 상품기획자**다. 제품 설명서·지원자료·고객 의견과 경쟁 기능을 함께 읽어, 사람이 아직 수행하는 작업을 찾고 이미 해결된 기능과 구분하는 조사 업무를 돕는다. 이 업무의 실제 소요시간·불편 빈도는 아직 측정하지 않았으며 문제 가설로 표시한다.

최초 적용 영역은 **식기세척기의 적재 전 확인부터 세척 후 사용 준비까지**다. 다른 가전으로 확장할 수 있는 구조를 지향하지만 초기 구현은 식기세척기로 제한한다. 공개 자료에서 사용자에게 요구하는 작업은 확인했으나 그 작업 모두가 불만이거나 제품 기회라는 뜻은 아니다.

## 사용자가 보게 될 흐름

1. 기획자가 조사할 주방 작업, 대상 모델·지역, 검토 문서 묶음을 넣는다. 없는 조건은 미확인으로 둔다.
2. Agent가 조사 계획을 세우고 출처별 사람 작업·조건·기능을 구조화한다.
3. 기존 기능이 같은 수고를 줄이는지 반대 근거를 찾는다. 제품 세대·지역·모델을 구분한다.
4. 부족한 근거는 추가 조사하거나 보류한다. 검색 결과에 없다는 이유만으로 신기능이라고 판정하지 않는다.
5. 남은 후보를 **근거·반례·콘셉트·실현 조건·다음 검증 방법**이 포함된 기획 카드로 출력한다.
6. 새 제품 자료를 추가하면 기존 판단을 다시 검토하고 바뀐 이유를 보여준다.

예: '오염도를 보고 세척 조건을 조절하자'는 기존 LG 발표와 겹쳐 제외한다. '적재 간섭을 사용자가 확인하는 수고'는 초기 가설로 남기되 실제 사용자 관찰과 경쟁 기능 추가 조사를 요구한다. 후자의 수요나 신규성까지 검증됐다는 뜻은 아니다.

## 최소 구현 범위

| 항목 | 고정 범위 |
|---|---|
| 입력 | 텍스트/HTML에서 검토한 작은 자료 묶음, 조사 질문, 모델·지역 메타데이터 |
| 자료 시작점 | 이번에 확인한 공개 출처 중 작업·기능 자료. 추가 목표 10~20개, 현재 확보 수와 구분 |
| 모델 | 제공자 1개, 구조화 출력. 실제 계정·API 설정과 비용은 첫 구현 단계에서 검증 |
| Skill | 자료 읽기, 인간 작업 추출, 기존 기능 대조, 근거 검증, 콘셉트/검증 계획 작성 |
| 실행 제어 | 단계별 기록, 최대 2회 수정, 실패/정보 부족 시 보류 |
| 화면 | 질문·문서 입력 / 처리 기록 / 근거 카드와 제외 후보 / 자료 추가 후 변화 |
| 저장 | 원문 위치, 문서 버전·적용 범위, 출력 JSON, 간단한 결과 내보내기 |
| 핵심 시연 | 동일 질문→기회 가설→기존 기능 추가→판단 수정, 다른 질문으로 반복 |

구현 방향은 Python 백엔드와 간단한 웹 UI다. 구체 프레임워크는 팀 경험과 모델 연결 결과에 맞춰 정한다. 핵심 계산·시연은 PC에서 완결한다. 결과로 제안하는 가전 제품·서비스의 형태는 웹으로 제한하지 않는다. 실기기 관찰은 근거 보완 수단이며, 실기기 제어·사진 기반 자동 재질 판정·대규모 크롤링은 초기 필수 범위가 아니다.

- 미완료: 원문 자동 추출, 모델 연결, 자동 조사·수정 루프, 웹 UI, 독립 평가, 실제 사용자/기획자 검증.
- 지금 만든 실행 코드는 **수동으로 정리된 기능 태그를 대조**한다. 실제 문서의 의미 대응을 모델이 정확히 수행한다는 증거는 아직 없다.

## 주요 위험과 축소 경로

| 위험 | 다음 검증과 대응 |
|---|---|
| 문서가 모델·지역마다 달라 잘못 합쳐짐 | 한 모델군과 작은 문서 집합부터 시작. 출처 위치/적용 범위가 없으면 보류 |
| 요약 서비스와 차별성이 약함 | 후보별 채택/제외 이유와 반대 근거, 재검토 전후를 필수 산출물로 고정 |
| 수요·새로움을 과장 | 고객 인터뷰/VOC 확보 전에는 가설 표시. 검색 범위와 미확인을 공개 |
| 모델 출력이 부정확 | 검토한 문서로 정답 레코드 구축. 구조화 출력과 코드 검사, 2회 이내 수정 후 보류 |
| API 연결·비용 | 첫 구현 세션에서 실제 호출·소량 예산 측정. 실패 시 접근 가능한 제공자로 변경하거나 범위 축소 |
| 일정 부족 | 크롤링 대신 문서 업로드, 벡터 DB 대신 작은 문서 집합, 화려한 그래프 대신 근거 카드 |
