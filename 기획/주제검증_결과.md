# 3개 후보 검증 결과

2026-09-27. [사전 계획](../research/topic_trial/protocol.md)에 따라 A4/B1/B5를 같은 기준으로 비교했다. **최종 선정: Theme A / Kitchen Gap.** 선택은 테스트 점수의 자동 순위가 아니라, 실제 자료 조사와 제한된 Skill 실행 결과를 종합한 Codex의 판단이다. 사용자가 선정을 위임했다.

## 무엇을 실제로 했는가

1. 공개 1차 자료 9건을 읽고 출처·범위·한계를 [자료 목록](../research/topic_trial/sources.json)에 기록했다. LG 설명서/지원자료와 신제품 발표, Bosch 제품 안내, Dovetail·Figma 공식 설명, ThinQ 공식 저장소다. 공식 과제/접수 조건은 기존 S1/S2와 대회요건을 재확인했다.
2. 같은 식기세척 여정에 대해 Codex가 구조화 입력과 콘셉트 초안을 작성했다. 자동 문서 추출 또는 실제 고객 VOC로 표시하지 않았다.
3. 세 후보의 최소 Skill을 Python으로 실행했다. 각 3개 입력, 합계 9개 개발용 실험을 수행했다. 기본·반례·정보 누락/변경을 포함한다.
4. 별도 9개 회귀 검사를 더해 기존 23개와 함께 총 32개 테스트가 통과했다. 이는 검사 코드의 회귀 확인이며 Agent 정답률이 아니다.

실행: `python scripts/topic_trial.py`. 재현 확인: `python scripts/topic_trial.py --check`.
입력은 [pilot_inputs.json](../research/topic_trial/pilot_inputs.json), 전체 출력은 [pilot_outputs.json](../research/topic_trial/pilot_outputs.json)이다. 출력에 입력/코드 SHA256을 포함한다.

구현 부담은 팀 가용 시간·모델 비용이 확인되지 않은 상태의 상대적 판단이다. 어느 후보도 실사용 효용이나 시장 신규성이 입증되지는 않았다.

## 실제 실험에서 얻은 결과

### A4: 새 아이디어처럼 보이는 기존 기능을 걸러냈다

Codex가 작성한 초기 콘셉트 4개 중:

- 오염도에 따른 세척 조건 자동 조절: S10의 LG AI SenseClean 발표와 기능이 겹쳐 신규 핵심 아이디어에서 제외하도록 반환.
- 세척 종료 알림: S12의 Bosch 공식 기능과 겹쳐 동일하게 반환.
- 적재 간섭 확인 지원, 실제 사용 준비 확인: 조사 범위 내 직접 대응 기능은 연결되지 않았다. **미해결이 증명된 것으로 표시하지 않고** `investigate_hypothesis`, `novelty=not_established`, `demand=unmeasured`로 반환.
- 유럽/미국 발표 기능을 한국의 모델 미상 기기가 지원한다고 판단하지 않았다.
- 합성 반례 기능을 추가하자 기존에 남겨둔 적재 확인 후보를 중복으로 변경했다. 해당 기능은 실제 발견한 제품이 아니라 변경 대응을 검증하기 위한 시험 입력이다.
- 출처를 제거하면 기획을 보류했다.

**한계:** 기능 의미를 공통 태그로 맞추는 작업과 콘셉트 초안 작성은 Codex가 했다. 실행 코드는 그 태그를 대조한다. 문서에서 자동으로 기능을 알아내거나 새로운 콘셉트를 생성하는 능력은 이번에 검증하지 않았다. 기획 카드의 구체성·가치는 추후 사용자/컨설팅 평가가 필요하다.

### B1: 충돌 검사는 가능하지만 현실적인 UX 검증은 별개다

합성 프로필에서 적재→세척→사람 확인→정리 흐름을 실행했다. 세척이 적재보다 먼저 시작하고 같은 기기를 중복 사용하는 입력에서 **2종 위반을 검출**했고, 탐욕적 순서 조정 후 해당 위반이 없어졌다. 세척 기능을 프로필에서 제거하면 자동으로 지원한다고 만들지 않고 설계자 확인으로 종료했다.

시간 5/60/2/5는 모두 가정이다. 실제 세척시간, 조리·물리 동작, 사람의 만족도는 측정하지 않았다. 화면 생성은 Figma Make의 공개 기능과 겹치므로 규칙 검사만 붙였을 때의 추가 효용을 더 입증해야 한다. 같은 자원을 순차 배치하는 기능만으로는 참가작의 가치가 충분하지 않다.

### B5: 종료 알림과 준비 완료를 구분했다

기기 종료 이벤트만 주면 `ready=false`, 사람에게 확인을 요청했다. 잔여 수분 입력에는 모델별 지침 미확인을 유지하고 기기 제어 명령을 생성하지 않았다. 목표를 '지금'에서 '나중'으로 바꾸고 사용자가 응답하지 않으면 강조 흐름을 바꾸되 확인 대기를 유지했다.

이는 상태 분기 구현 가능성을 보여준다. 실제 센서 연동이나 사용자 행동 예측이 아니다. 추가 확인 절차를 사용자가 원하는지, 기존 종료 알림보다 유용한지는 미검증이다. 이 검증은 지인 대상 UX 과제로 보완하기 쉬워 차선 후보로 남긴다.

## 자료 조사로 달라진 판단

- [LG 2026 발표](https://www.lg.com/global/newsroom/news/home-appliance-solution/lg-electronics-to-showcase-new-dishwasher-lineup-at-eurocucina-2026/)와 [Bosch 공식 안내](https://www.bosch-home.com/us/products/dishwashers/homeconnect/)에 이미 있는 기능을 신규 기능처럼 제안하면 차별성이 약하다.
- [Dovetail](https://dovetail.com/roles/customer-experience/)도 고객 자료 군집·문서 생성을 제공한다. Kitchen Gap은 요약 기능만으로 차별화할 수 없다. 기획자가 **어떤 아이디어를 왜 버리고 무엇을 추가 조사할지** 결정하는 산출물에 집중한다.
- [Figma Make 공식 설명](https://help.figma.com/hc/en-us/articles/31304485164695-Create-a-Figma-Make-file)은 동작하는 프로토타입 생성을 이미 지원한다. B1의 기본 화면 생성은 차별점에서 제외한다.
- LG의 [범용 잔여 수분 안내](https://www.lg.com/us/support/help-library/lg-dios-dishwasher-there-is-water-left-on-the-dishes-even-after-dry-has-finished--20154848491113), [식기 종류 안내](https://www.lg.com/us/support/help-library/lg-dishwasher-dishes-are-not-clean-after-washing--20155101652263), [개별 설명서 계열](https://gscs-manual.lge.com/CDZ/MFL71467502/en-us/topics/topic_3.html)은 재질 조건의 표현과 적용 범위가 다르다. 원문 범위를 잃고 합치면 잘못된 일반화가 생길 수 있다. 이번에는 Codex가 이를 식별했으며 자동 충돌 탐지를 구현했다고 주장하지 않는다.

## 선정 이유와 한계

세 후보 모두 좁은 규칙 기능은 구현 가능했다. 통과 개수로 우열을 정하지 않았다. Kitchen Gap은 **실제 공개 문서의 사람 작업과 현재 제품 기능을 연결해 잘못된 기획 결론을 줄이는 흐름**이 Theme A 직무와 직접 맞고, 실기기 없이도 판단 전후를 시연할 수 있어 선정했다. 사용자 수요를 검증하지 않은 가전 앱을 먼저 만드는 부담도 줄일 수 있다.

보완이 가장 필요한 부분은 상품기획자가 이 산출물을 실제로 유용하게 여기는지와, 모델이 원문을 정확히 구조화하는지다. 모델 API·비용·지연은 미검증이다. 신규성 검색은 제한적이며 사내 도구 미보유나 세계 최초를 주장하지 않는다. 오늘 접수 시점의 구현 범위를 정하는 결정이지 수상·완성 보장이 아니다.
