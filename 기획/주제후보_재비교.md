# 주제 후보 재비교 — LLM 직접 사용 대비 가치

2026-09-27. 요청: 하네스를 적용해 여러 주제를 분석해 보여주기. **최종 주제는 재검토 중**이며 이번에는 후보를 확정하지 않는다. 기존 Kitchen Recovery 선정·설계는 역사적 기록이다.

## 적용 범위와 판단

AtoZ 하네스의 목표 정렬 → 공개 근거 조사 → 후보 발산 → 비교를 수행했다. 이번에는 모델/API 실험을 실행하지 않았으며, 후보의 수요·수상 확률·기존 LLM 대비 성능 향상을 입증하지 않았다. 테스트 43개 통과는 하네스 코드의 과거 검증이며 이 후보들의 우수성 검증과 무관하다.

모든 후보는 상품기획자 또는 UX 설계자의 업무를 돕는 Agent다. 실기기 없이 PC에서 핵심 도구를 실행할 수 있도록 최소 범위를 잡았다. 소비자에게 직접 제공할 서비스의 형태까지 PC로 한정한 것은 아니다.

공통 기준: 공식 A/B 적합성 / 실제 문제 근거와 데이터 접근 / 강한 LLM 기준선 대비 추가 가치 / 기존 비AI/Agent 도구 대비 가치 / 최소 구현 부담 / 측정·시연 가능성. 우선 검증 대상은 **B8 동시 조리 흐름**, **A8 공간 제약 기획**, 차선은 **B9 쉬운 화면 설계**다. 순위는 설계 수준의 판단으로 실제 성능 순위가 아니다.

## 1. 동시 조리 흐름 설계 Agent (B8, Theme B)

**누구의 어떤 일:** 주방 서비스 UX 기획자. 여러 요리의 사람·기기 사용과 완료 시점을 맞춘 안내를 설계하기 어려움.

**입력에서 결과까지:** 요리 단계·시간·기기 조건→불명확 조건 질문→선후관계 구조화→일정 계산→불가능 조건 설명/대안→알림·화면 시나리오.

**시연 장면:** 오븐 1대가 필요한 두 작업의 충돌을 발견하고, 한 작업이 지연됐을 때 타임라인과 안내를 다시 생성.

- LLM 직접 사용 대비 검증할 가치: 문장 일정이 아닌 계산으로 검사 가능한 타임라인과 재계획 결과.
- 기존 도구라는 반론: 고정 입력 일정 계산기. Agent는 자연어 조건 해석·추가 질문·안내 시나리오에 기여해야 함.
- 최소 구현: 검토된 3개 요리·10개 안팎 작업, 2종 기기, 한 명. 고정·범위 시간 가정과 미확인 표시. 물리 제어·식품 안전 판정 제외.
- 자료 상태: 일정 계산 방법 확인; 개발용 조리 단계·시간 자료는 아직 구축하지 않음.
- 가장 어려운 부분: 실제 조리 시간 변동, 사람의 주의가 필요한 구간, 조건 구조화 정확도.
- 경쟁력의 약점: 레시피 추천만 하면 기존 서비스와 중복. Theme B의 UX 설계 결과가 필요.
- 진행을 중단할 조건: 손으로 입력하는 비용이 크거나 고정 일정 계산기 대비 이득이 없으면 보류.
- 비교 실험: 같은 검토된 작업표로 강한 LLM 프롬프트/계산기/Agent 비교; 충돌·선행 위반·지연 시 재설계 시간.
- 후보 이력: 기존 B1의 자원·시간 계획을 핵심으로 축소. 완전히 새 아이디어 아님.
- 참고 출처: R6, R7.

## 2. 공간 제약 기반 주방 가전 기획 Agent (A8, Theme A)

**누구의 어떤 일:** 가전 상품기획자. 작은 주방의 공간·문 열림·설치 조건을 기존 제품 명세와 함께 대조하기 번거로움.

**입력에서 결과까지:** 가구별 공간 조건→모델별 명세 확인→단위 정규화·제약 계산→제외 원인 묶기→개선 제품/서비스 요구사항→기존 기능 재대조.

**시연 장면:** 본체는 들어가지만 문 열림 조건이 안 맞는 가정을 찾아 제품 요구사항을 바꾸고, 이미 해결한 모델이 있으면 신규 기회 주장을 철회.

- LLM 직접 사용 대비 검증할 가치: 모델 범위가 명시된 계산·제외 이유·기능 중복 확인을 재현.
- 기존 도구라는 반론: 스프레드시트 필터·설치 계산기. Agent는 문서 구조화·누락 질문·제품 요구사항 도출에서 가치를 보여야 함.
- 최소 구현: 냉장고 한 제품군 5~10모델·명시적 공간 3사례, 2D 수치 검토. 임의 3D CAD·사진 자동 측정 제외.
- 자료 상태: 공식 설치 항목과 기존 기능 확인. 5~10모델의 완전한 명세 확보는 미완료.
- 가장 어려운 부분: 모델별 문 열림·설치 여유 자료 확보와 정확한 추출.
- 경쟁력의 약점: 추천 쇼핑몰로 끝나면 Theme A 약함. 표본 부재는 시장 공백/제조 가능성을 입증하지 않음.
- 진행을 중단할 조건: 소수 모델조차 조건을 확보 못하거나 기존 기능의 재발견만 하면 보류.
- 비교 실험: 검토한 명세표를 동일 제공; 제약 누락·모델 혼동·계산 오류·새 모델 추가 시 기획 수정 시간.
- 후보 이력: 기존 A6 Kitchen Fit을 수치 제약과 반증에 집중시킨 개선안.
- 참고 출처: R1, R2.

## 3. 사용하기 쉬운 주방 앱 화면 설계 Agent (B9, Theme B)

**누구의 어떤 일:** 주방 앱 UX 디자이너. 예약·취소·상태 확인 화면을 읽고 조작하기 쉽게 바꾸면서 기능을 유지해야 함.

**입력에서 결과까지:** 사용 과제·기능·화면 조건→제한된 컴포넌트 화면 생성→브라우저 렌더링→대비·크기·키보드 경로 검사→수정→전후 보고.

**시연 장면:** 예약 취소 화면의 버튼·문구를 개선한 뒤 대비·조작 경로를 다시 검사.

- LLM 직접 사용 대비 검증할 가치: 결과 화면을 실제 렌더링하고 측정·반복 검사.
- 기존 도구라는 반론: 접근성 검사기+디자이너 또는 코드 Agent. 기존 검사 자체를 신규성으로 주장하지 않음.
- 최소 구현: 직접 만든 예약/취소 웹 화면 3개·고정 컴포넌트·제한된 검사. 모든 앱/스크린샷 자동 재설계 제외.
- 자료 상태: 공식 검사 설명·경쟁 도구 확인; 화면·사용자 검토 미실행.
- 가장 어려운 부분: 검사 통과와 실제 사용성의 차이, 일반 개발 도구와 경쟁.
- 경쟁력의 약점: Axe 등과 겹침. 고령자·장애 당사자 사용성은 실제 검토 없이 주장 불가.
- 진행을 중단할 조건: 범용 코드 Agent+검사기와 결과·작업량 차이가 없으면 보류.
- 비교 실험: 동일한 초기 화면·과제 제공; 검사 오류·기능 유지·수동 수정량, 사람의 과제 수행은 별도.
- 후보 이력: 새 후보. 기존 First Kitchen의 설명문 생성을 넘어 실행 화면 검사에 집중.
- 참고 출처: R3, R4, R5.

## 4. 용량·에너지 균형 상품기획 Agent (A9, Theme A)

**누구의 어떤 일:** 주방 가전 상품기획자. 같은 제품군에서 용량과 에너지 등 상충 목표를 비교해 설계 목표를 정하기 번거로움.

**입력에서 결과까지:** 목표 고객 조건→공개 인증 데이터 정리→동일 유형 비교→상충 관계 계산→요구사항 후보→표본·기존 제품과 재검토.

**시연 장면:** 목표 용량을 바꾸면 비교군과 에너지 목표 범위·기획 근거가 달라짐.

- LLM 직접 사용 대비 검증할 가치: 수치 집계와 후보 비교를 반복 재현.
- 기존 도구라는 반론: 엑셀·BI로 충분한 부분이 큼. Agent는 비교군 선택·누락 처리·요구 변경 재분석에서 이득 필요.
- 최소 구현: 미국 인증 냉장고 한 유형·용량/연간 에너지 2축. 국내 요금 예측·신제품 실제 성능 예측 제외.
- 자료 상태: 공개 다운로드/API와 필드 존재 확인, 정제 실험 미실행.
- 가장 어려운 부분: 표본 편향·모델 중복·비교 가능한 제품 분류.
- 경쟁력의 약점: 단순 차트는 혁신성이 약함. 데이터 빈 곳은 수요·기술 실현성을 뜻하지 않음.
- 진행을 중단할 조건: 차트 요약 수준을 넘는 기획 판단 개선이 없으면 보류.
- 비교 실험: 동일 표에서 계산 정확도·비교군 일관성·목표 변경 재작업 시간.
- 후보 이력: 새 후보.
- 참고 출처: R8, R9.

## 5. 고객 불편을 검증하는 상품기획 Agent (A10, Theme A)

**누구의 어떤 일:** 상품기획자·고객 조사 담당자. 고객 의견을 실제 제품 한계·사용 오류·이미 개선된 기능으로 구분하기 번거로움.

**입력에서 결과까지:** 허가된 후기/인터뷰→문제 묶기→모델/날짜별 설명서 대조→반대 근거→요구사항·검증 질문.

**시연 장면:** 많이 언급된 불편처럼 보였던 항목이 중복 후기이거나 최신 모델에서 해결됐다는 반대 근거로 우선순위 변경.

- LLM 직접 사용 대비 검증할 가치: 원문·모델·시점·반대 근거를 추적하며 반복 업데이트.
- 기존 도구라는 반론: LLM 문서 분석 및 Dovetail. 단순 요약·출처 링크만으로는 차별성 약함.
- 최소 구현: 사용 허가한 실제 의견 30~50개와 제품 2종. 대규모 크롤링·빈도 일반화 제외.
- 자료 상태: 비교할 공식 제품 자료 확인. 고객 코퍼스 미확보가 핵심 장애.
- 가장 어려운 부분: 권한 있는 실제 고객 자료와 해석 정답 확보.
- 경쟁력의 약점: 합성 후기를 실제 수요처럼 쓸 수 없음; 기존 고객 분석 제품과 강하게 겹침.
- 진행을 중단할 조건: 실제 자료와 반증 가치가 확보되지 않으면 접수 주력에서 제외.
- 비교 실험: 사람이 검토한 의견 집합으로 잘못된 신규 기회·근거 연결·분류 수정 비용 비교.
- 후보 이력: 기존 A4 Kitchen Gap을 고객 원문·모델별 반증으로 구체화.
- 참고 출처: R10, R1, R2.

## 6. Kitchen Recovery: 실패 상황 UX 설계 (B7, Theme B)

**누구의 어떤 일:** 주방 서비스 UX 기획자. 연결 끊김·미응답 시나리오의 처리 흐름을 빠뜨릴 수 있음.

**입력에서 결과까지:** 사용 목표·기기 계약→상태 흐름→실패 경로 검사→수정→화면 명세.

**시연 장면:** 응답 없는 기기를 완료로 처리하는 흐름을 찾아 수정.

- LLM 직접 사용 대비 검증할 가치: 구조화된 경로 반복 검사 가능.
- 기존 도구라는 반론: 강한 LLM 프롬프트+상태 검사기. 기존 도구로 해결 가능한 부분이 큼.
- 최소 구현: 두 상황·정해진 사건·기존 그래프 검사 사용.
- 자료 상태: 기존 출처와 합성 그래프 2개 존재. 실제 모델/기획자 비교 없음.
- 가장 어려운 부분: 범용 LLM/상태 흐름 검사 도구 대비 효용.
- 경쟁력의 약점: 문제가 주방 특유인지와 효용이 약함; 쉬운 검사라는 이유만으로 선정하면 안 됨.
- 진행을 중단할 조건: 직접 LLM 방식 대비 개선이 없으면 탈락.
- 비교 실험: 같은 요구사항/조건으로 경로 누락·완료 오판·수동 수정시간 비교.
- 후보 이력: 기존 선정안 재평가; sources의 R6는 제약 계산 참고일 뿐 문제 수요의 근거가 아님. 기존 연구 자료도 참고.
- 참고 출처: R6.

## 공정하게 비교할 다음 실험

1. 모델·원문 자료·과제·정답 기준을 고정한다. 기본 프롬프트가 아닌 조건·검토 지시를 포함한 강한 프롬프트를 기준선으로 쓴다.
2. LLM 대화만 / 관련 기존 도구 또는 코드 Agent / 제안하는 전용 Agent의 세 방식을 구분한다. 전용 Agent에만 정답이나 더 좋은 원문을 제공하지 않는다.
3. 도구 접근·호출 횟수·비용·사람의 준비 작업을 함께 기록한다. 계산기를 붙여 좋아진 부분과 Agent의 문서 해석·질문·재계획 기여를 분리한다.
4. 개발과 분리된 조건 변경·누락·불가능 사례로 오류·수동 수정량·소요시간을 측정한다. 빠른 소수 사례는 탈락 판단의 예비 실험이며 통계적 우월성 주장이 아니다.
5. 사용자의 실제 효용은 팀 외 사용자의 과제 수행으로 별도 확인한다. 모든 후보를 완제품으로 만들지 않고 상위 2개에서 가장 위험한 가정을 먼저 확인한다.

## 출처와 적용 한계

- **R1 [LG 설치 확인 안내](https://www.lg.com/us/support/help-library/lg-refrigerator-prepurchase-installation-checklist--20154752570350)**: 설치 공간·문 열림·반입 경로를 따로 확인할 필요. 한계: 특정 모델 치수와 수요 빈도를 제공하는 자료가 아님.
- **R2 [LG 구매 가이드](https://www.lg.com/us/refrigerator-buying-guide)**: Zero Clearance 등 기존 공간 대응 기능 존재. 한계: 신규 아이디어나 모든 국가/모델 지원을 입증하지 않음.
- **R3 [W3C 목표물 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)**: 웹 조작 대상 크기·간격 및 예외의 검토 기준. 한계: 가전 물리 버튼 기준으로 전용 불가; 전체 접근성 인증 아님.
- **R4 [W3C 명암 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)**: 웹 텍스트 대비 계산 기준. 한계: 실사용 이해도·접근성 전체를 보증하지 않음.
- **R5 [Deque Axe](https://www.deque.com/axe/devtools/)**: 자동·AI 접근성 검사 경쟁 기능 존재. 한계: 주방 특화 설계 흐름의 부재를 입증하지 않음.
- **R6 [Google OR-Tools 작업 일정](https://developers.google.com/optimization/scheduling/job_shop)**: 선후관계·동시 자원 사용 제한 일정 계산 방법. 한계: 조리 시간과 현실 적합성은 별도 자료가 필요; 자체 신규 알고리즘 아님.
- **R7 [Samsung Food](https://samsungfood.com/)**: 레시피 저장·식단 계획·장보기 기능 존재. 한계: 세부 다중 조리 최적화 지원 여부는 이번 조사로 단정하지 않음.
- **R8 [ENERGY STAR 데이터 도구](https://www.energystar.gov/products/productstr)**: 제품 데이터 내려받기·API 제공. 한계: 이번에 전체 자료 수집·정제·계산을 실행하지 않음.
- **R9 [ENERGY STAR 냉장고 목록](https://www.energystar.gov/most-efficient/me-certified-refrigerators/results?is_most_efficient_filter=Most+Efficient)**: 용량·연간 에너지 사용 항목을 확인할 수 있음. 한계: 미국 인증 표본이며 전체 시장·한국 실사용 전력과 다름.
- **R10 [Dovetail](https://dovetail.com/)**: 피드백 분석·출처 연결·기획 문서 생성 Agent의 경쟁 기능. 한계: 제조사 자체 설명; 우리 분석 도구의 차별성을 보장하지 않음.
