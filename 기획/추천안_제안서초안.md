# Kitchen Rehearsal - 주방 연결 경험을 설계·검증하는 AI Agent

**미선정 B1 후보의 참고 초안 / 사용자가 추가 후보 검토를 요청함 / HWP 제출본 아님.** 현재 작업 기준은 `추가아이디어_비교.md`와 `harness/project.json`이다.

아래 문장은 공식 6항목에 맞춘 출발점이다. 팀이 내용을 검토하고 실제 구현 범위·자료·역할을 반영해야 한다. 제안서 10쪽 이내 여부는 HWP 편집 후 확인한다.

## 1. 아이디어 제안내용 개요

Kitchen Rehearsal은 주방 UX 기획자가 고객 상황과 가전 기능을 바탕으로 연결 경험을 설계하도록 돕는 AI Agent이다. 설계 조건을 구조화하고, 이용 시나리오를 작성한 뒤, 기기 기능과 작업 순서의 충돌을 검사해 수정한다. 기획자는 시나리오뿐 아니라 화면 흐름, 실패 상황의 대응, 근거와 검증 기록을 함께 받는다. 고객 상황이나 기기 구성이 바뀌면 같은 과정을 반복할 수 있도록 구현한다.

## 2. 제안배경

LG의 AI Home 방향은 여러 가전과 서비스를 고객의 상황에 맞게 연결하는 경험을 포함한다. 이런 경험을 기획하려면 정상 상황의 흐름과 함께 시간 변경, 기기 미지원, 사용자 응답 누락 같은 조건을 점검해야 한다. 본 제안은 이러한 반복 설계와 점검에 부담이 있다는 가설에서 출발한다. 현업의 실제 소요시간과 효과는 아직 확인하지 않았으며 선발 후 컨설팅과 과제 수행 평가로 검증할 계획이다.

## 4. 제안 아이디어 설명 및 차별성

Agent는 조건 정리, 기능 확인, 시나리오 설계, 제약 검사, 수정·출력 Skill을 사용한다. 자연어 해석과 설계는 모델이 수행하고, 지원 기능과 작업 순서처럼 명확한 제약은 코드가 검사한다. 검사에서 문제가 발견되면 Agent가 수정하고 다시 검사하며, 정해진 횟수 안에 해결하지 못하면 이유를 명시하고 기획자에게 확인을 요청한다.

예를 들어 손님 방문 시간이 바뀌고 하나의 오븐에 작업 두 개가 겹치는 상황을 입력하면, Agent는 충돌을 표시하고 작업 순서와 소비자 안내 흐름을 다시 설계한다. 실행 결과에는 가정한 조건, 기능 출처, 수정 내역과 재실행 가능한 구조화 데이터가 포함된다. 실제 가전 제어와 조리 안전 판정은 MVP에 포함하지 않는다.

공개된 소비자용 가전 비서와 비교해 본 제안의 중심은 기획자가 시나리오를 만들고 검토하는 업무이다. 근거 연결과 제약 검사를 통한 반복 수정, 상황 변경에 따른 재설계, 검증 기록의 재사용을 차별점으로 검증할 계획이다. LG 내부 또는 모든 상용 설계 도구와의 우월성을 확인한 것은 아니다.

## 5. 추진방향

3인 팀이 PC·웹 환경에서 한 가지 주방 여정과 제한된 기기 기능 목록을 대상으로 MVP를 구현한다. 먼저 모델 연결과 구조화 출력, 규칙 검사 기능을 검증하고, 시나리오 생성·수정과 화면 흐름을 연결한다. 연구원 컨설팅에서 역할과 실무 활용 가치를 검토하고, 개발용과 별도 평가용 시나리오로 결과를 확인한다.

10월 초 핵심 실행 흐름을 완성하고, 중순에는 예외 처리와 평가를 진행하며, 10월 20일 결과물을 제출한다. 실제 API 접근·실기기 제어에 의존하지 않아 장비 확보가 개발의 선행 조건이 되지 않도록 한다. 모델 사용 환경과 비용은 개발 착수 전에 확인한다.

## 6. 기대효과

기획자가 상황 변경에 따른 시나리오 수정과 제약 점검을 반복하는 부담을 줄이고, 설계 결과의 근거와 변경 이유를 검토하기 쉽게 만드는 것을 목표로 한다. 다른 가전 기능 목록을 입력하면 같은 설계·검사 절차를 재사용할 수 있도록 구성한다.

효과는 같은 입력에 대한 1회 생성 방식과 비교해 제약 위반 수, 오류 수정 결과, 소요시간과 사용성을 평가한다. 아직 감소율이나 성능 수치를 측정하지 않았으므로 정량 효과를 확정 성과로 제시하지 않는다.
