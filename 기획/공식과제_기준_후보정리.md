# 공식 포함 가능 과제에 따른 후보 정리

2026-09-27. 사용자의 첨부 표와 추가 주제 자료를 함께 적용한다. **공식 A/B → 포함 가능 과제 → 구체적인 키친 문제·콘셉트 → 그 기획/설계를 반복 수행하는 Agent** 순서다. 포함 가능 과제 중 정확히 한 줄만 택해야 한다는 명시 규정은 확인되지 않았지만, 이번 비교는 표에 직접 연결되는 후보를 우선한다. 새 주제 확정이나 접수 완료를 의미하지 않는다.

## 우선 후보 1 — 여러 가전의 조리 완료를 맞추는 주방 경험 (B8, Theme B)

**공식 항목:** 가전 간 연계를 통한 AI 기반 키친 서비스. 사용자의 상황을 고려한 조리는 보조 연결이다.

**고객 문제 가설:** 한 사람이 여러 요리를 준비할 때 사람의 작업과 기기 사용이 겹치고, 한 작업의 지연이 전체 식사 준비를 바꾼다. 실제 불편 빈도는 아직 측정하지 않았다.

**키친 콘셉트:** 식사 목표 시각과 집에 있는 기기에 맞춰 준비 순서·안내 시점을 조율하고, 작업 지연 때 남은 안내를 바꾸는 경험. 단순 메뉴 추천과 구분한다.

**우리가 만드는 Agent:** UX 기획자가 고객 상황·검토된 요리 단계·기기 기능을 입력하면 조건을 구조화하고 모르는 정보를 질문한다. 일정 계산 도구로 자원/선후관계 충돌을 확인한 뒤 서비스 흐름과 화면·알림 명세를 생성한다. 조건이 바뀌면 다시 계산하고 시나리오를 수정한다.

**최소 범위:** 검토된 요리 3개, 기기 2종, 작업자 1명. 시간은 제공된 가정이며 실제 조리 완료·안전 판정이 아니다. 실기기 제어 없이 상태와 일정 입력을 바꾸는 웹 시연.

**산출물:** 정상/지연/기기 부족 상황의 UX 흐름, 기기별 역할·타임라인, 화면 문구, 계산 근거, 미해결 조건. 하나의 레시피 결과에 고정되지 않고 다른 조건으로 재실행한다.

**LLM 직접 사용 대비 검증할 가치:** 만들어진 일정의 실행 가능성 검사와 상황 변경 후 재설계. 기존 계산기 대비 자연어 조건 추출·추가 질문·화면 안내 생성의 수고 절감이 실제로 있어야 한다.

**한계:** 조리 시간·사람의 능동 작업 구간 자료가 필요하다. LG의 공개 ThinQ Claw 방향에도 식재료 기반 레시피와 가전 연결이 있어 연결 자체를 신규성으로 주장할 수 없다. 해당 발표가 이 후보의 모든 세부 기능을 제공하거나 미제공한다는 뜻도 아니다.

**최소 검증:** 동일 작업표와 조건으로 강한 LLM 프롬프트/고정 일정 계산기/제안 Agent를 비교한다. 충돌·선후관계 위반, 불가능 조건 보고, 지연 후 수정시간·수동 입력량을 측정한다. 이번 턴에는 실험하지 않았다.

## 우선 후보 2 — 작은 주방·가구 조건에 맞는 가전 콘셉트 (A8, Theme A)

**공식 항목:** 미래 라이프스타일과 가구 형태 변화에 따른 가전 및 폼팩터 제안.

**고객 문제 가설:** 작은 주방에서는 필요한 기능·용량을 갖춘 제품이 설치 공간이나 문 열림 조건과 맞지 않을 수 있다. 작은 주방 고객의 실제 수요와 표본 대표성은 미검증이다.

**키친 콘셉트:** 가구·공간 조건별로 기존 제품이 충족하지 못하는 요구를 찾아 제품 크기·접근 방식·배치 지원 서비스 등의 개선 요구사항을 제안한다. 어떤 폼팩터가 정답인지는 자료 조사 결과로 정한다.

**우리가 만드는 Agent:** 상품기획자가 가구 조건과 검토된 제품 자료를 입력하면 모델별 설치 제약을 구조화·계산하고 불충족 원인을 묶는다. 기존 공간 대응 기능과 반대 근거를 조사해 제품·서비스 콘셉트를 만들거나 기획 기회 주장을 철회한다.

**최소 범위:** 한 제품군 5~10모델·공간 사례 3개. 최초 냉장고 사례로 검증할 수 있지만 전체 대회를 냉장고로 제한하는 의미가 아니다. 2D 수치 검토이며 사진 자동 측정·3D 설계·제조 가능성 보증은 하지 않는다.

**산출물:** 고객 조건별 미충족 요구, 기존 제품과의 차이, 제약 계산표, 출처·반대 근거, 제품 콘셉트 카드. 쇼핑 추천 목록만으로 끝내지 않는다.

**LLM 직접 사용 대비 검증할 가치:** 모델/국가별 조건과 출처를 보존한 계산 및 새 제품 추가 시 기획의 재검토. 스프레드시트 대비 추출·누락 확인·콘셉트 수정의 실질 이득을 확인해야 한다.

**한계:** 모델별 문 열림 자료 확보가 핵심이며 LG Zero Clearance 등 기존 해결 기능이 있다. 조사 표본에 없다는 사실을 시장 전체의 공백이나 신제품 제조 가능성으로 바꾸어 말하면 안 된다.

## 조건부 후보 — 고객 불편에서 제품 개선 기회를 찾기 (A10, Theme A)

**공식 항목:** SNS·검색 트렌드·제품 리뷰를 활용한 숨은 고객 니즈 발굴.

**키친 문제·콘셉트:** 예를 들어 보관 공간이나 조작 과정의 불편 의견이 실제 제품 한계인지, 사용 방법의 문제인지, 이미 개선된 사항인지 구분한 뒤 개선 기능을 제안한다. 지금 실제 원문에서 그 문제가 확인됐다는 뜻은 아니다.

**Agent 업무:** 허가된 원문 묶기 → 모델·시점별 공식 자료 대조 → 중복·반대 근거 검토 → 우선 개선 요구와 콘셉트 생성. 출력은 근거/반증이 붙은 기획 카드다.

**조건:** 사용 가능한 실제 원문 30~50개와 제품 자료 2종을 확보한 경우 검토. 숫자는 MVP 목표이며 현재 확보량이 아니다. Dovetail 같은 기존 고객 분석 도구와의 차이가 있어야 한다. 현재 자료 부족으로 B8/A8보다 후순위다.

## 나머지 기존 후보의 처리

- **A9 용량·에너지 분석:** 보류. 공식 A의 니즈+기술 기반 콘셉트 항목에 연결 가능하지만, 현재는 고객 니즈와 새 콘셉트보다 데이터 분석에 치우쳤다. 쉬운 계산이라는 이유만으로 통과시키지 않는다.
- **B9 접근성 화면 설계:** 독립 주제에서 제외. 구체적 미래 키친 서비스가 정해졌을 때 화면 품질을 확인하는 보조 기능으로 활용할 수 있다.
- **B7 Kitchen Recovery:** 독립 주제에서 제외. 선정된 서비스의 미응답·연결 실패 UX를 검사하는 보조 기능으로 활용할 수 있다. 기존 검사 코드를 버릴 필요는 없다.

이번 발산 단계의 후보 6개는 비교를 위해 유지하고, 비교 단계에서 2개를 제외·1개를 보류했다. 후보 수를 채우려고 새 이름으로 다시 나열하지 않는다. 추천은 B8, 대안은 A8이며 **실제 기준선 비교 전 최종 확정하지 않는다**.
