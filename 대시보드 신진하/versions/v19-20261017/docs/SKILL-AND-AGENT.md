## 한눈에 읽는 규칙

- 간판의 도구 아이콘과 `SKILL · 일하는 방법`은 업무 방법이다.
- 주황색 `SKILL 사용 중`은 현재 요청의 실제 작업 명령을 관측했을 때만 켠다. 해당 구역만 소품 동작을 실행한다.
- 사람 아이콘과 `담당 · 메인 AI` 또는 보라색 `도우미 · 역할 이름`은 담당자다. 같은 AI가 여러 Skill을 쓸 수 있다.
- 파란색 `진행 보고`는 CLI가 공개한 진행 소식이다. 확인된 Skill 명령으로 승격하지 않는다.
- 도우미 시작만 확인하고 Skill은 모르면 보라색 `도우미 작업`이며 사용하는 Skill은 확인 중이라고 표시한다.
- 지침 조회는 확인 중/응답 확인/실패를 구분한다. wrapper 경로는 조회한 지침의 이름을 증명하지 않는다. get_work_instructions는 main·다른 Skill·known_context를 선택할 수 있으므로, 본문 receipt ID가 없는 v1 기록에서는 일반 설명서 조회로만 표시한다. 직접 SKILL.md 파일을 읽은 기록과 구분한다. `get_work_instructions`와 caller의 `known_context`는 지침의 적용·이해·업무 성공·도우미 생성을 증명하지 않는다.
- 메인 주황색 강조는 최신 현재 요청이 작업 중일 때만 표시한다. 완료·취소·연결 끊김·오래된 관측에서는 멈춘다. 동작 축소에서는 정지된 표시를 사용한다.
- 연구원은 관측된 작업을 쉽게 표현하는 캐릭터다. 움직이는 연구원 수 자체를 LLM 호출 수나 실제 도우미 수로 세지 않는다. 실제 도우미 수와 각 native ID는 오른쪽 담당 AI 상세에 표시한다.

## 고친 관측 오류

이전에는 현재 선택한 native 세션 전체에서 Skill과 담당 이력을 고를 수 있어 이전 질문의 담당자가 현재처럼 보일 여지가 있었다. 현재 요청 및 명시적으로 연결된 continuation만 현재 상태로 사용하고 전체 세션 이력은 별도로 보존한다.

동일 역할의 도우미 여러 명은 native agent ID별로 유지한다. 시작·종료·실패·취소·종료 미확인·위임 요청을 구분한다. 도우미 종료 시 그 도우미의 미종료 Tool은 결과 미확인으로 닫고 Skill 애니메이션을 끈다. 일반 셸·파일 작업을 Skill 또는 새 도우미로 바꾸지 않는다.

혼합 명령은 wrapper 경로가 아닌 각 실제 operation의 Skill로 귀속한다. 지침 조회만 들어 있는 명령은 Skill 작업으로 세지 않는다. 명령 응답이 종료돼도 관측한 exit_code가 0이 아니면 실패로 처리한다. 최신 native 취소·응답 종료 기록은 이전 CLI 진행 보고에 우선한다.

## 실행·연결

일반 주소의 기본 화면은 실제 하네스 관측 대기다. `?view=demo` 또는 메뉴의 **로컬 규칙 데모**에서 이전 저장 자료와 결과를 그대로 연다. **작업 모션 예시**는 실제 CLI 실행과 분리된 동작 시연이다.

공개 웹 주소만 열었다고 PC의 CLI와 자동 연결되는 것은 아니다. 기존 `tools/start_release.py`로 선택한 설치 폴더의 읽기 서버를 열거나, 기록 보기에서 JSONL/JSON/live.js를 데이터로 읽는다. 서버 연결은 명시된 loopback 주소·메모리 내 조회 토큰을 사용한다. 기록·명령 원문·자격증명을 공개 사이트로 업로드하지 않는다. 기존 연결 방법은 [릴리즈 연결](RELEASE-CONNECTION.md)을 따른다.

새 프론트는 하네스의 판단 코드·기본 모델·설치본·hooks·작업 DB를 수정하지 않는다. 공식 ZIP 자체의 UI 교체나 그 ZIP을 새로 설치한 것으로 보고하지 않는다. 로컬 실행 시 새 프론트 빌드 경로를 `--dist`로 지정할 수 있다.

## 남아 있는 관측 한계

1. 니즈 구조화·기능 대조·콘셉트 작성이 메인 AI 내부에서 이어질 때 개별 Skill 시작·끝 사건이 없을 수 있다. 이때는 분석 구간/CLI 보고/확인 중으로 표시한다. 정확한 내부 적용 시점을 주장하려면 하네스 쪽의 실제 단계 사건이 추가로 필요하다.
2. 미래 릴리즈의 새 Skill을 자동 설치·자동 발견한다고 주장하지 않는다. 현재 여섯 정의는 확인한 태그와 일치하며, 목록·관측 형식이 바뀌면 대조 후 갱신해야 한다.
3. 관측된 명령 실행·지침 반환·파일 저장과 원문 의미 품질·실물 개선 효과는 별개다. 애니메이션은 물리 시뮬레이션이나 실기기 제어가 아니다.
4. 이번 검증은 일반 코드 검사, 브라우저 UI, 명시적인 합성 기록 재생이다. 새 실제 상품기획 CLI/모델 요청이나 v0.18.0 실제 업무의 종단 간 실행을 수행하지 않았다.

## 보존

기존 테마·원본 인물 PNG·전 화면 공장·선택 후 오른쪽 패널·Escape 복귀·1~6개 구역의 병렬 크기 조절·기록 재생을 유지한다. 기존 브라우저 저장 키와 분석 엔진을 바꾸지 않는다. 이전 보존 브랜치/커밋은 덮어쓰지 않는다.

### v0.18 Codex 도우미 연결의 한계

릴리즈의 codex_follow.py는 child SubagentStart를 prompt_id 없이 내보내고, 후속 사건에는 child 고유 turn을 사용한다. 메인 spawn 관측에는 반환된 launched_agent_id가 빠져 있다. 따라서 시각이 가깝다는 이유로 이번 질문의 도우미라고 추정하지 않는다. 확인된 부모 호출→반환 child ID가 없는 실제 기록은 오른쪽 패널의 “같은 세션에서 본 도우미 · 이번 질문과 연결 미확인”에만 표시한다. 방 확대·Skill 사용 표시·현재 도우미 수에 포함하지 않는다.

이 한계를 없애려면 상위 관측기가 실제 부모 호출과 반환 native agent ID를 연결해 내보내야 한다. 이번 작업에서는 공식 릴리즈나 다른 저장소를 수정하지 않았다. 합성 QA의 바인딩 완료 사례는 해당 증거가 있는 경우의 표현 검증이며, v0.18 Codex 전체 연결의 실증이 아니다.

### v19 이름표·메인 상태 표시 보완

연구원이 이동하는 공간을 이름표 배치의 보호 영역으로 사용한다. 이름표 사이의 간격을 늘리고 작게 정리하며, 구역 밖으로 이동한 이름표는 가는 선으로 해당 작업실과 연결한다. 공장 위치·원본 캐릭터·병렬 실행 확대와 실제 실행 상태 투영은 유지한다. 메인 기획 AI는 동일한 실행 상태로 이름표와 본체 테두리를 주황색으로 켜고, 연기 입자·SVG는 제거했다. 모션 예시의 메인 이름 아래 미리보기 문구를 제거했으며 상단의 실제 CLI 실행 아님 표시는 유지한다.
