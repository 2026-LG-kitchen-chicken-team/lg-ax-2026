# KITCHEN AX · 상품기획 팩토리

## product-v0.15.0 릴리즈 연결

`?view=harness`는 정이량이 배포한 [lg-ax-harness product-v0.15.0](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-harness/releases/tag/product-v0.15.0)의 실제 Codex·Claude 관측 기록을 읽는 화면입니다. 공장 전체 화면과 다섯 공간을 유지합니다. 자료 공간에 자료 조회·웹 조사의 두 Skill을 구분해 표시하고 나머지 네 Skill을 각 공간에 연결합니다. 설치된 역할을 실행 중이라고 가정하지 않습니다.

설치 준비와 실제 AI 업무 수행은 별개입니다. 세션이 없으면 연결됨·세션 대기이며, 지침 읽기·명령 관측·저장 결과·최종 응답을 구분합니다. DB 결과는 네이티브 세션과 업무 식별자 세 개가 일치할 때만 표시합니다. 원문 질문·명령·키를 공용 사이트로 보내지 않습니다. [릴리즈 연결·검증 안내](docs/RELEASE-CONNECTION.md)를 참고하세요.

로컬 런처는 현재 선택한 native 요청의 공개 진행·명령 결과를 고정 상태로 투영합니다. 준비 점검 중에는 중앙 메인 기획자가 활성화되고, 완료 후 실제 설치·파일·SQLite 검사와 조회한 Skill 지침 수를 보여줍니다. 지침 확인은 실행 완료가 아닙니다. CLI 보고로 파악한 단계와 실제 명령으로 관측한 Skill 실행은 표시를 구분합니다. 원본 릴리즈·CLI·프로젝트 훅은 수정하지 않습니다.

`tools/start_release.py --workspace <설치된 codex 폴더> --dist <빌드된 dist 폴더>`로 로컬 공장과 수동 관찰기를 함께 시작합니다. 조회 키는 새로 생성해 메모리에만 유지합니다. 모델을 호출하지 않으며 이 폴더에서 시작하는 새 CLI 세션을 기다립니다. `--latest`를 명시하면 해당 폴더의 가장 최근 세션을 따라갑니다. 실행 창을 닫거나 Ctrl+C로 종료하면 이 런처가 시작한 자식 프로세스만 종료합니다.

일반 공개 주소의 상품기획 데모·브라우저 저장 기록과 기존 GitHub 보존 커밋은 변경하지 않습니다.

## 이전 팀원·CLI 개발 하네스 관제

이전 팀 개발 Controller용 읽기 화면은 `?view=team`으로 엽니다. 릴리즈 연결 설정의 ‘이전 개발 관제’에서도 전환할 수 있습니다. 일반 주소에서는 기존 상품기획 로컬 데모와 저장 기록을 그대로 사용합니다.

관제 모드의 업무 공간은 정이량·황대겸·신진하·최길웅과 팀 검수 대기를 나타냅니다. 개발 작업을 상품기획 다섯 Skill의 실행으로 표시하지 않습니다. 담당자·배정 작업·최근 Worker 자기보고·작업 할당 기한·조회 연결 상태를 구분하고, 확인되지 않은 처리량·명령 원문·LLM 동작은 만들지 않습니다.

브라우저 연결부와 별도 읽기 서버를 구현했으며, 실제 정이량 PC의 DB와는 아직 연결하지 않았습니다. 연결 전 기본 상태는 **하네스 연결 대기**입니다. [읽기 서버 설치·연결 안내](docs/HARNESS-CONNECTION.md)를 따라 실제 하네스 PC에서 설정해야 합니다. 이 서버는 운영 Controller API를 호출하거나 작업 할당·팀 모드·Worker를 변경하지 않습니다.

인증 코드는 브라우저 탭 메모리에만 유지합니다. 공개 Site에 팀의 비밀·DB·실행 기록을 포함하지 않았습니다. 현재 연결은 같은 PC의 loopback 읽기 서버를 대상으로 하며, 다른 PC에서 원격으로 조회하려면 별도의 인증된 중계가 필요합니다. 공개 HTTPS 화면에서 로컬 연결이 제한되면 같은 소스의 로컬 웹 화면을 사용하세요.

고객 리뷰와 같은 제품 모델의 기존 기능·사용 조건을 대조하는 웹 워크스페이스입니다. 밝은 스마트 팩토리 시안에 맞춰 실제 THREE.js 작업 공간과 컨베이어를 만들었습니다. 기본 화면은 공장이 전체 뷰포트를 채우며, 노드·자료·결과·진행 단계·실행 기록을 선택하면 공장이 왼쪽으로 이동하고 오른쪽 패널이 열립니다. 닫으면 다시 중앙으로 돌아옵니다. 다섯 공간은 독립 AI가 아니라 다섯 Skill의 업무 역할입니다.
현재 작업은 기존 헤더의 한 줄 상태로 표시합니다. 단계 선택 시 오른쪽 패널에서 실제 처리 대상·단위, 해당 단계의 결과, 최근 작업과 다음 행동을 확인합니다. 기본 화면에 새 고정 요약·활동 패널을 추가하지 않으며 카메라와 공장 배치는 유지합니다. 진행 수가 제공되지 않으면 집계 전으로 표시합니다.


## 실행

Node.js 22 이상과 Python 3.10 이상을 사용합니다.

```powershell
npm install
npm run dev
```

표시된 localhost 주소를 브라우저에서 엽니다. 별도 터미널에서 Python 실행기를 선택 실행합니다.

```powershell
python -m backend.server --port 8032
```

웹 오른쪽 상단 설정 → `http://127.0.0.1:8032` → 연결 확인. 로컬 웹 미리보기에서 연결을 검증했습니다. HTTPS 배포 웹에서 localhost 서버에 연결하는 경우 브라우저 네트워크 정책에 따라 제한될 수 있습니다. Python 서버의 자세한 API·CORS·LLM 환경 변수·저장 규약은 backend/README.md에 있습니다.

- 기획 요청·조건 수정, CSV/JSON/TXT/PDF 입력, PDF 페이지·원문 일치 확인, 같은 모델의 근거 연결.
- 자료 조회 → 니즈 구조화 → 기능 대조 → 콘셉트 작성 → 검토·수정. 브라우저와 Python 모두 실제 입력을 처리하는 로컬 규칙 구현.
- 최대 3개 콘셉트·요구사항, 불명확한 상황의 사용자 확인/가정 포함/보류, 근거 부족·중복 후보 보류/제외.
- 실행·일시정지·계속·중지, 선택 단계부터 재실행과 이후 결과 무효화, 최대 2회 자동 검사·수정, 회차별 수정 전후 기록.
- 실제 처리 상태와 연결된 현재 작업·진행 수·원문 상세·다섯 공간 강조·타임라인. 모르는 진행률을 가짜 퍼센트로 표시하지 않음.
- 전체 현황, 현재 실행 노드 추적 복귀, 모바일·키보드·동작 축소.
- 브라우저 저장/복원, 이전 실행 탐색, JSON 전체 기록·CSV 대조표/요구사항 내보내기.
- Python의 다섯 단계 API, SQLite 실행 저장, 교체 가능한 LLM JSON HTTP 어댑터 및 연결 계약.

## 연결 대기와 한계

현재 배포는 브라우저 로컬 규칙 모드입니다. 실제 LLM 의미 분석과 독립 서브 에이전트는 연결되지 않았습니다. Python 실행기는 별도 로컬 실행이며 LLM 어댑터의 명시적 계획 API를 제공하지만 다섯 Skill 전체의 LLM 의미 분석은 연결 대기입니다. 키나 URL이 있다고 실제 호출 성공으로 표시하지 않습니다.

초기 자료는 가상 모델 3개·합성 리뷰 42개이며 냉장고 청소·수납·정리 범주를 다룹니다. 제품군 자유 입력은 다른 가전에 대한 분석 검증을 의미하지 않습니다. OCR·자동 웹 수집·PDF/PPT 보고서·시장성·물리 성능·제조 가능성 검증은 미구현 또는 별도 범위입니다. LLM 계획 API는 URL·모델·키를 서버 환경 변수로 설정합니다. 키를 웹 코드에 저장하지 않습니다.

업로드 문서의 원문 지시문은 실행 명령으로 사용하지 않습니다. 합성/실제 구분·버전·모델·원문 위치를 보존하며 문서 미언급을 기능 부재로 단정하지 않습니다. 브라우저 저장은 같은 브라우저에만 적용되고 백그라운드 실행·기기 간 동기화는 제공하지 않습니다.
