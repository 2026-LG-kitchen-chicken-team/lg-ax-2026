2026-09-27. 사용자 지시: 후보 검증(1번)과 최종 주제 선정(2번)을 진행한다. 선정 권한은 Codex에 위임했다. 신청서 작성·접수는 이번 작업 범위가 아니다. 전체 접수 목표는 사용자 요청대로 **9/27 오늘**이다.

## 비교 대상과 선정 방법

- A4 Kitchen Gap: 문서에 남아 있는 사람의 수고를 추출하고, 기존 기능과 대조해 기획 기회 가설과 검증 계획을 만드는 Theme A Agent.
- B1 Kitchen Rehearsal: 사용자 상황과 가전 기능으로 UX 흐름을 만들고 충돌을 검사하는 Theme B Agent.
- B5 Dish-to-Done: 식기세척 완료 이후 사용 준비까지의 UX를 설계하는 Theme B Agent.
- 기존 11개 중 공식 문제 단서가 있고 핵심 검증을 좁힐 수 있는 A4/B5, 기존 기술 예제가 있는 B1을 비교한다. B4는 인계 수요의 근거가 현재 더 약하고, 나머지는 초기 비교의 중복·자료·범위 위험이 남는다. 전 후보를 실행한 것은 아니다.

공통 기준은 과제 적합성, 실제 데이터 접근, 기존 기능/도구와 차별성, 핵심 실행 가능성, 10/20까지 구현·검증 부담이다. 공식 배점이나 임의의 수상 확률은 사용하지 않는다. 통과 테스트 개수로 서로 다른 제품 가치를 순위 매기지 않는다.

## 공통 실험 조건

같은 식기세척 여정과 공식 출처를 사용한다. 입력은 세 종류다.

1. 기본 입력: 공개 문서·기능 표가 있을 때 결과를 만드는가.
2. 반례 입력: 이미 있는 기능, 기능 충돌, 확인되지 않은 완료 상태를 성공으로 오인하지 않는가.
3. 정보 변경/누락: 근거·모델 정보·사용자 응답이 없거나 목표가 바뀔 때 보류/변경하는가.

실행 모드를 구분한다.

- 자료 검색·해석과 후보별 산출물 작성: 현재 대화의 Codex가 수행하는 보조 실행.
- 증거 연결, 기능 대조, 순서 충돌, 상태 전이: Python 표준 라이브러리로 실제 실행하는 최소 Skill.
- 문서 자동 추출·개방형 아이디어 생성·자동 수정·모델 API 호출: 아직 구현·측정하지 않음.
- 원자료는 실제 공개 자료지만 이를 입력용 레코드로 구조화하는 작업은 Codex가 수행한다. 구조화 추출 정확도 실험으로 보고하지 않는다.
- 시간·완료 이벤트·새 기능을 추가한 반례는 합성 입력이며, 실제 기기 또는 소비자 관찰로 표시하지 않는다.

이 실험은 제한된 핵심 기능 확인과 선정 판단을 위한 개발용 실험이다. 독립 평가 세트·사용자 연구·정확도 벤치마크가 아니다. 모델 지연·비용·반복 생성 품질은 측정하지 않는다. 환경변수와 작업 폴더에서 모델 API 설정이 확인되지 않았다. 다른 곳의 자격 증명을 탐색하거나 새 유료 서비스를 활성화하지 않는다.

## 출처와 결과 기록

- `sources.json`: 실제 읽은 출처의 짧은 요약, 적용 범위, 한계. 공개 자료의 부재를 기능 부재의 증명으로 사용하지 않는다.
- `pilot_inputs.json`: Codex가 작성한 구조화 입력. 원문에서 자동 추출한 결과가 아니다.
- `pilot_outputs.json`: 최소 Skill 실행 결과. `python scripts/topic_trial.py`로 재생성.
- `기획/주제검증_결과.md`: 공통 비교, 실제 발견한 문제, 한계.
- `기획/최종주제_선정.md`: 선정과 범위·구현 경로·남은 위험.

선정 조건: 접근 불가능한 실기기나 비공개 데이터가 필수면 핵심 범위를 줄인다. 근거를 추가해도 결과를 검증할 수 없거나 기존 기능을 단순 재포장하면 순위를 낮춘다. 모든 후보의 API 비용·실사용 효과 미검증은 공통 위험으로 남긴다.
