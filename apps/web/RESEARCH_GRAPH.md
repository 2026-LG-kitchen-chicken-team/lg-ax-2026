# W3 실제 기획 관계 그래프

현재 채팅의 수동 WEB 지원 구현이다. 기존 팀원의 직접 성과나 실모델 기획 품질 검증으로 기록하지 않는다.

`PlanningBrief.relations`의 원본 from_id/to_id, relation, source_ids, inferred를 소비한다. source→problem supports/contradicts, problem→concept proposes와 같은 반환된 연결만 표시하며 인용 배열·기존 제품 대조 목록으로 새 관계를 만들지 않는다. 같은 ID가 충돌하거나 연결 노드를 알 수 없는 관계는 개수를 알리고 그리지 않는다.

선택 문제에서 두 단계 이내를 탐색한다. 관계 유형과 추론 표시로 좁혀 보고 최대 18개 노드·24개 관계를 표시한다. 제한으로 생략된 건수를 표시하며, 그래프 크기나 연결 수를 시장 발생 빈도·중요도 점수로 해석하지 않는다. co_occurs는 함께 언급된 기록이며 원인·효과·발생 빈도를 뜻하지 않는다. 점선은 inferred=true이며 실선도 검증된 사실을 뜻하지 않는다.

SVG의 원문 노드는 마우스·Enter/Space로 기존 원문 상세를 연다. 문제·개선안 노드는 관련 원문을 선택할 수 있다. 같은 관계를 키보드로 조작 가능한 목록에도 제공하며 연결별 source_ids와 추론 여부를 보여준다. `이 문제로 기획 조건 검토`는 선택한 문제를 목적 입력으로 옮길 뿐 모델 실행·저장 요청을 자동으로 시작하지 않는다.

검사 데이터는 기존 공개 DOM 원문의 구조 검사이며 임의 고객 후기 본문이나 정상 기획 결과를 제품 화면에 넣지 않았다. W3 관계·범위·표시 제한·키보드/재사용 검사 6개와 영향받는 새 W1 흐름 검사 4개, 총 10개가 통과했다. TypeScript를 포함한 production build도 통과했다. 기존 500kB 번들 경고는 후속 화면 분할 대상으로 남긴다. 실제 Qwen이 생성한 기획 관계의 품질과 브라우저 전체 흐름은 통합 인수에서 따로 확인해야 한다.

예약·자동화·Worker·운영 서비스·모델·Figma·PR은 변경하지 않았다.
