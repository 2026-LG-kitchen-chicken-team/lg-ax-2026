# 자동 표 연결 검증에 필요한 실제 출력

대상: #14 / DATA `@ginaginaring`, 검수·인터페이스 조정: PM `@jeongiryang`.

이번 검수에서는 모델/OCR을 다시 실행하지 않았다. 먼저 이미 생성된 불변 출력이 있는지 확인하고 제공해야 한다. 없다면 PM이 생산 담당·입출력 범위와 다음 작업을 배정해야 한다. 아래는 **검수에 필요한 정보 목록**이며, 새로운 공통 Schema의 채택이나 실제 추출 결과가 아니다.

## 1. 원본 및 실행 식별

- 원본 PDF 불변 위치·SHA-256, 문서 ID, 자료 버전/개정, 물리 PDF 페이지(1부터 시작).
- table/cell/header/footnote의 ID와 원문 위치. bbox의 단위·좌표 원점·페이지 크기·DPI·회전/전처리 변환을 명시.
- producer 코드 commit/파일 SHA, 모델 및 구성 요소 ID·revision·설정, input/output SHA, 실행 기록. 수동 지정 metadata와 자동 예측 값을 구분.
- 기존 14개 OCR 입력 crop PNG를 보유 중이면 원파일 또는 불변 보관 위치·SHA. 원문에서 새로 만든 비교 렌더로 기존 입력의 bytes 보존을 대신 증명하지 않기.

## 2. 연결별 필수 정보

| 연결 | 필요한 관측 출력 | 주요 대조 사례 |
| --- | --- | --- |
| 행/절 → 값 | 실제 row/section ID·index, 행 머리글·값 셀 ID, 원문 bbox 또는 문자 범위 | DUE 제품 크기/무게; MW 소비전력/고주파 출력 |
| 열/병합 범위 → 값 | column index와 시작 기준, row/column span, 적용 열 목록, header→cell 관계 | DUE 공통 14인용·1600 W, MW 공통 출력/소비전력 |
| 모델/제품 타입 → 셀 | 원문에서 읽은 모델 머리글, 계열 패턴/정확 SKU 구분, 타입·유형 조건과 적용 범위 | DUE 오른쪽 빌트인과 왼쪽 상판 제거 치수; MW23/25 계열 |
| 숫자/물리량 → 행 | raw 값과 파싱 값, 폭/높이/깊이 순서, 범위·소수점·한정자, quantity ID | MW 1570 W 소비전력 ≠ Max.1000 W 고주파 출력 |
| 단위/머리글 → 값 | 단위 문자·unit source cell/range, 명시 단위와 헤더 상속 구분, value→unit 관계 | MW 외형 치수의 mm는 값 crop 밖 행 머리글 |
| 각주/조건 → 값·모델 | marker ID·본문 ID·각 bbox/range와 연결 edge, Max./일부모델/시간 조건의 적용 값 | MW p37 *1의 짧은 시간 조건; FR p22 스패너 일부모델 *1 |

## 3. 인수 판단

- 각 필드가 실제 자동 처리에서 출력됐는지와 수동 후처리 여부를 명시한다. 입력의 `source_model_id`, `manually_assigned_source_column`만 반복한 경우 자동 모델/열 검출 성공으로 세지 않는다.
- 원문에 각주가 없는 항목은 전체 구조 출력에서 확인 가능한 빈 관계 목록/적용 범위로 나타내야 한다. 전체 출력 자체가 없는 경우와 구분한다.
- 각주 ID는 문서 SHA·개정·페이지의 범위에 묶는다. FR과 MW의 `*1`을 같은 전역 ID로 연결하지 않는다.
- DUE 왼쪽 상판 제거 치수와 오른쪽 빌트인 치수는 숫자가 같아도 다른 셀/조건으로 유지한다. MW23FDI에 오른쪽 깊이370 또는 용량25 L를 붙이면 오류다.
- 공용 PDF의 T876 유형/부품과 MW 모델별 기능 안내는 정확 SKU 적용 자료가 없으면 미확인으로 유지한다. 외부5 cm 자료는 그 원문·적용성 검토가 별도로 필요하다.
- 본값1000과 각주 번호1을 별도 구조로 취급한다. 저장 OCR의 `∗1`을 본값 목록의 두 번째 수치로 사용한 과거 평가 실패는 보존하고, 향후 별도 수정/재검토 이력을 남긴다.

실제 출력 수령 후 이 PR의 고정 원문/참조 ID에 대조해 일치·오류·미확인을 채울 수 있다. 출력 부재 상태에서는 자동 정확도/오류 건수는 `null`, 연결 판정은 **검증 불가**다. PM 전체 승인·운영 통합 완료·#14 Done과 구분한다.
