# #14 비교 조건과 측정 기준

현재 상태는 준비 완료/성능 미측정이다. 기계가 읽는 원본은 protocol.json이다.

## 검색 비교

| 방법 | 고정 설정 |
|---|---|
| BM25 | 기존 scripts/model_benchmark.py, k1=1.5/b=0.75, Unicode 단어·casefold |
| BGE-M3 | 기존 고정 revision, CLS/L2 dense, FP32, max_length256, batch8 |
| BGE-M3 + 재정렬 | 같은 BGE 후보 최대10개, 고정 reranker revision, raw logits/max_length256 |

모든 방법에 같은 corpus와 **모델 ID+정확한 문서 버전 필터를 검색 전에** 적용한다.
검색 입력은 text만 사용하며 정답/질문 분류/근거 ID를 임베딩 입력에 붙이지 않는다.
현재 corpus는 기존 사실 요약27개다. 냉장고의4개 문단은 작으므로 Hit@1을 주 지표로 삼고 Recall@3만으로 우위를 주장하지 않는다.

- 답이 있는11질문: Hit@1, Recall@3, MRR@3. 복수 정답 질문은 각 근거의 회수율을 계산한다.
- 답이 없는4질문: 순위 평균에 넣지 않고 필요한 조건 요청·다른 모델 거부·미확인 유지 및 금지 주장 여부를 별도로 검토한다.
- 모델/버전 혼입: 반환 근거의 메타데이터로 검사. 같은 모델의 옛 문서 원본이 없어 이 범위 검증은 추가 자료 확보 뒤 보완한다.
- 오류/timeout은 누락하지 않고 실패로 기록한다. 빈 검색 결과의 혼입률은 NA로 둔다.
- 같은 CPU/FP32/4threads에서 방법별 warmup2회, 질문별 측정5회. 모든 방법에 같은 순서(seed20261005)를 적용한다.
- median/p95/실패 수·peak RSS를 기록한다. 모델 로드·색인·렌더/전송 시간은 별도 기록한다. GPU 실험은 별도 트랙이다.
- 실제 토큰 길이를 기록한다. 잘림이 발견되면 설정 버전을 바꾸고 세 방법 모두 재실행한다.

## OCR 비교

세 실문서의 문장3·숫자/표3, 총6사례를 준비했다. PDF 해시·페이지·짧은 원문과 숫자/단위 정답을 고정했다.
원본 텍스트 PDF 추출과 300DPI/RGB로 렌더한 **수동 줄/행 crop의 기존 Paddle 인식**을 비교한다.
crop 좌표·이미지 크기·hash는 실제 실행 전 고정한다. crop 생성도 아직 실행하지 않았다.
문자오류율(CER)은 원문과 맞춘 줄에만 적용하고, 표/도면은 숫자·단위·모델 열 연결 정확도를 따로 기록한다.
숫자·소수점·단위·모델명은 정규화 과정에서 제거하지 않는다.

기존 모델은 글자 인식 모델이다. 문서 전체의 영역 탐지·표 구조 분석 모델이 선택된 것으로 간주하지 않는다.
수동 crop 성공을 전체 페이지 OCR 성공으로 보고하지 않는다. 실제 스캔 원본도 아직 없다.
식기세척기 p57은 빌트인 열의598×815×567mm·45kg, 전자레인지 p37은 MW23FDI 열의깊이369mm를 원본 표로 확인했다.

## 선택·완료 기준

먼저 모델/버전 혼입·조건 삭제·근거 부족 단정을 해결한다. 동일 질문의 방법별 성공/실패와 정확도·시간을 함께 비교한다.
개발 질문에서 좋아 보여도 독립 평가 우위로 표현하지 않는다. 정확도가 같으면 단순하고 빠른 기준선의 유지 여부를 검토한다.
실제 결과·환경·실패·근거를 PM에게 인수하고 #13 경로와 통합 확인한 뒤 방법 채택·#14 최종 완료를 판정한다.
결과 양식의 null/빈칸은 미측정이며 0점/실패0회가 아니다.
기존 bootstrap 실행 코드는 정답 없는 질문·Hit@1/MRR·반복 측정을 지원하지 않으므로 이 질문을 그대로 전달하지 않는다.
5단계에서 이 고정 protocol을 따르는 실행 어댑터를 연결한 뒤 측정한다. 준비 완료는 실행 어댑터 구현 완료를 뜻하지 않는다.
