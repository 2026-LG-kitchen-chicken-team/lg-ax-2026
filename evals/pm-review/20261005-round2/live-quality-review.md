# PM 실제 모델 품질 검토 메모

검토일: 2026-10-05 KST. 독립 검수 AI가 원본 실행 로그와 공급 자료를 읽어 작성했다. 공유 통합 작업 공간의 코드·개인 기록은 수정하지 않았으며, 이 검수에서 모델·서버를 직접 실행하지 않았다.

**판정 점수는 아직 산정하지 않았다.** enum 개선 전 실제 Qwen 실행 7건은 보류 5건·실패 2건·완료 0건이다. 최종 후보는 전부 0개이며, 검증을 통과해 저장된 의미 검토도 0건이다. 잘못된 결과를 내보내지 않은 것은 안전성 동작의 근거지만, 모든 보류가 올바른 상품기획 판단이라는 근거는 아니다. fixture 통과를 실제 모델 품질 완료로 표현하면 안 된다.

## 검토 범위와 실행 조건

- 원본: [live-lg-final summary.json](../../../evals/pm-review/20261005-round2/live-lg-final/summary.json) 및 같은 폴더의 7개 실행 JSON. 개발 예시 1건과 독립 제외 조건 입력 6건이며, 공급 자료는 합성 고객 리뷰·가상 설명서다. 실제 고객 수요·제품 성능 증거가 아니다.
- 모델: `qwen3:8b`, digest `500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41`. Ollama native schema + 로컬 검증, 생성 전후 digest 확인. temperature 0 / context 16,384 / 출력 상한 8,192 / seed 42 / thinking false.
- 아래 토큰은 각 `model_calls[].metadata`의 실제 `prompt_eval_count` / `eval_count` 합계이며, 실패 출력과 수정 호출도 포함한다. 29회 호출에서 **입력 62,177 / 출력 37,516 / 합계 99,693 토큰**이다. 비교 기준선 측정이 없으므로 토큰 절감률은 산정할 수 없다.
- 7건이 사용한 저장된 의미 검토 schema의 condition에는 enum이 없다. 최신 [semantic_review.py](../../../packages/core/src/lgax_core/semantic_review.py)는 제외 조건 원문 enum과 `request.exclusions` / `features.conditions` 구분 지침을 추가했다. 이 최신 변경의 효과는 아래 7건으로 검증되지 않는다. 루트가 최신 enum 재실행·API test2 검증을 진행한다는 보고와 전체 독립 품질 완료를 구분한다.

## 공급 설명서와 보류의 반대 근거

| 사례 | 실제 공급 자료가 말하는 내용 | 검토 해석·한계 |
|---|---|---|
| development-normal | 식품을 모두 비운 뒤 선반 전체를 분리 세척할 수 있다. | 대조 단계는 기존 기능 존재와 잔여 불편을 구분했다. 새 기능이라는 이유만으로 기존 기능과 충돌한다고 한 의미 검토는 “다른 모델 기능 혼용” 위반 근거가 아니다. 다만 자동 식품 분리의 작동 원리가 약하고 일부 ≤10% 에너지 가정은 검증되지 않아, 후보 자체의 품질 문제는 남는다. |
| normal | 회전 접시는 분리 세척하고, 받침 아래 홈은 젖은 천으로 닦는다. | 좁은 홈의 불편은 남을 수 있다. 자동 청소가 기존 수동 방식과 다르다는 설명은 카메라·원격 서버 제외 위반을 입증하지 않는다. 후보의 자동화 원리와 제조·안전 가정은 별도 검토가 필요하다. |
| changed_exclusion | 선반·보관함은 밖에서 씻고, 내부 물 분사는 제공하지 않는다. | 초기 후보는 접근 구조·서비스·수동 도구 중심이라 자동 액체 분사 장치 금지와 양립할 여지가 있다. 검토는 가정이 미실측이라는 이유로 uncertain을 만들고, 제외 조건이 하나인데 조건 간 상충 확인 문구를 질문으로 복사했다. 이것만으로 전면 보류를 정당화할 수 없다. |
| negation | 필터를 꺼내 흐르는 물로 씻으며, 필터 자동 세척 모드는 제공하지 않는다. | 모델이 다시 자동 모드 존재 여부를 묻는 것은 이미 공급된 명시적 답과 맞지 않는다. 새 하드웨어 금지에 따른 실현 가능성 확인은 필요할 수 있지만, 허용한 명칭까지 금지로 바꾼 이유는 오류다. |
| synonym | 식품을 꺼낸 뒤 선반을 분리하고 밖에서 세척한다. | 검토는 급수통·펌프 조건 대신 식품 이동·전원 차단·이동성을 논했다. 다만 후보 중 밖에서 씻는 이동식 선반은 기존 기능과 중복할 가능성이 있어 모든 후보가 좋은 답이라고 할 수 없다. |
| ambiguous_mode | 뜨거운 회전판은 충분히 식힌 뒤 씻으며 분리할 수 있다. | 현재 부품만 사용한다는 제한 때문에 가능 여부를 확인하는 보류는 방어 가능하다. 그러나 현재 즉시 세척 기능 부재를 곧바로 새 모드 기획 불가로 바꾸면 잔여 불편 분석의 목적을 놓친다. 냉각 안전 조건을 지키면서 허용 부품으로 가능한 범위를 물어야 한다. |
| conflicting_conditions | 필터는 손으로 씻고, 세척액 공급 장치는 설명서에 명시되지 않았다. | 상충한 두 요청 때문에 보류하는 결과는 타당할 수 있다. 핵심 질문은 새 펌프 금지와 추가 펌프 필수 중 어떤 조건을 바꿀지다. “미명시=미지원”은 별도 근거 오류이며, 결과 상태만 맞았다고 의미 판단 성공으로 채점하면 안 된다. |

## 개선 우선순위 제안

1. **enum은 범위 복사 오류의 수정으로 한정한다.** 후보 인용 오류, 부정문 오독, 기존 기능 부재와 기획 불가의 혼동은 남는다. 특정 제품 단어 금지나 급한 quote.enum 하드코딩으로 정답을 고정하지 않는다.
2. **보류가 필요한 불확실성과 향후 검증 과제를 구분한다.** 현재 구현은 uncertain 또는 questions가 하나라도 있으면 hold한다. `unverified_assumptions`는 명시된 가설 자체를 결함으로 오해하기 쉽다. 가정의 표시·근거·검증 계획을 평가하고, 조건 준수 판단을 막는 불확실성에 보류를 적용하는 기준을 검토한다. 단순 미래 효과 검증 질문만으로 전 후보를 막지 않는다.
3. **모델의 반복 기록 부담을 줄이는 실험을 한다.** 후보 3개·조건 1개만으로 제외 3행+품질 12행을 작성하며 이유·후보 인용·근거 인용을 반복한다. 검토 5호출만 입력 13,432 / 출력 18,930토큰이었다. 후보/조건 대상과 해시·행렬 완전성은 코드가 구성하고, 모델은 작은 단위의 판단을 작성하는 방식을 비교할 수 있다. 판정을 미리 정하거나 원문 검증을 약화하지 않는다.
4. **형식 복구와 상품기획 보류를 분리한다.** `exclusion_pair_or_literal_condition`을 고객 보류 이유로 복사하면 안전하게 멈췄어도 업무상 이유가 틀리다. 내부 result와 바깥 hold_reasons의 이중 생성도 반복 실패 원인이므로 하나의 내부 표현을 어댑터가 계약에 투영하는 방식을 검토한다.

스키마 크기는 의미 검토에서 약 2.4~2.5KB였고 출력은 3,002~4,060토큰이었다. 확인한 호출은 `done_reason=stop`이며 출력 상한 8,192에 못 미친다. 따라서 잘림이나 context 부족을 현재 실패 원인으로 단정할 근거는 없다. 스키마 복잡성·반복 부담이 품질에 영향을 준다는 해석은 실험할 가설이지 입증된 인과관계가 아니다.

## 판정과 재개 경계

이번 검수는 실행 사실·출력 오류·반대 근거의 분석이다. 독립 점수, 강한 일반 LLM 기준선과의 공정 비교, 모델 선택 확정, 전체 Agent/Skill 품질 완료는 남았다. 개발 예시와 독립 평가를 분리하고 같은 자료·조건·모델 설정·출력 예산·전체 재시도 토큰으로 비교해야 한다. enum 적용 후 API 재실행이 성공해도 위 7사례의 의미 품질을 모두 입증하지 않는다.

확인 원본 summary SHA-256: `993572d42f0b54bfc939c00b2d3762251ebc373f723ba701306a09caaeac575d`.
읽기 시점 최신 semantic_review.py SHA-256: `43bf14e29b44c7fa176f3315f9b757321a1c25f38c925eca40dfe40cf6e00a5d`. 이는 새 enum 코드의 해시이며 이전 7건 실행 코드의 해시로 사용하면 안 된다. 7건 로그는 모델·요청·프롬프트·schema를 보존하지만 정확한 실행 소스 commit은 이 summary에 없으므로 최종 PM 근거에 별도 연결해야 한다.


PM 후속: 최신 enum 지침의 실제 API2 재실행은 api-live/summary.json에 있으며 두 건 held·각 의미 검토1건/후보0이다. 형식 문제가 줄었으나 의미 정확도는 미완료다. 원본 독립 검수 메모는 private에 보존했다.
