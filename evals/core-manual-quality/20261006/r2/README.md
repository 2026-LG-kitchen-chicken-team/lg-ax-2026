# 수동 R2 세 입력 준비

[PM R2 배정](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-2026/issues/11#issuecomment-6009749444)에 따라 정상·같은 목표의 조건 변경·근거 부족 보류 검증용 입력을 분리했다. 정상/변경은 R1 개발 입력과 원 자료의 바이트를 그대로 유지한다. 근거 부족 자료는 냉장고 설명서 `MANUAL-001`과 연결 기능 `FEATURE-001`만 제외하고 리뷰·제품·원문 위치·다른 제품 자료는 유지한다. 이는 AI가 준비한 합성 개발 변형이며 실제 고객 자료나 사용자가 새 조건을 확정한 회차가 아니다.

[input-provenance.json](input-provenance.json)은 원/새 입력과 자료 SHA, 변형 필드, 실행 후보 소스 pin을 기록한다. 출력 정답이나 독립 평가 답안을 프롬프트에 추가하지 않았다. 빈 기능 목록을 기능 부재의 증거로 해석하지 않는다. 실제 실행에서는 설명서 누락에 맞는 질문·보류가 나오는지 별도로 대조한다.

PM이 공통 입력 직렬화/래퍼를 수정하는 [PR169](https://github.com/2026-LG-kitchen-chicken-team/lg-ax-2026/pull/169)의 고정 후보 `c2c9eaa98864598d2fcec901861a78b9fecabea8`를 격리 QA용으로 읽었다. 해당 파일을 이 브랜치에서 중복 편집하거나 병합/품질 인수를 대신하지 않는다. 원 8B 실패/원 비용은 보존한다.

이번 준비의 실제 모델 생성은 0이다. 입력 계약·출처 연결 검사는 실제 accept/held/failed 또는 독립 의미 평가를 대신하지 않는다. 첫 실행 상한은 3입력·24회 생성이며 내부 공유 수정은 기존 최대2회다. 중앙 잔여 한도/토큰 상한 공지는 사용자 지시로 미정으로 유지한다. 후속에 알려진 더 낮은 제한·중단 지시는 적용한다. 27B 새 설치/실행과 자동화 ON은 수행하지 않는다.

격리 환경에서 `python evals/core-manual-quality/20261006/r2/validate_inputs.py`로 입력/자료 계약과 scope·SHA를 확인할 수 있다. 실행 원 입력·응답·trace·실제 호출/토큰 사용량과 PM 인수는 후속 별도 근거로 기록한다.
