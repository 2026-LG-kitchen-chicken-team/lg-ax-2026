# PM DATA 인수 근거 · 2026-10-06

요청 출처는 현재 PM 작업의 직접 위임이다. 대상은 PR #133/#138/#141과 #131/#127/#129의 자료 원본·부분 실행 이력이며, 판단·수정·공통 계약·API·웹·자동화·공유 담당자 기록은 편집하지 않는다. 첫 코드 커밋은 `d4b09783adcacb23cf8fb7321f62f6e27cbbcfc7`, 기준 main은 `02f9a643e92c4665f2f0f71a5690f9ed6ed28930`이다. 새 자료팩과 후속 스타일 수정은 별도 커밋으로 인수한다.

- `code-intake.json`: 처음 인수한 코드와 26개 집중 검사, 전체 저장소 검사 시도의 결과.
- `source-intake.json`: 인수 시점의 원본 PR 전체 SHA·파일 해시·제외 내역. 코드의 원본 해시와 최종 파일 해시는 다를 수 있으며, 후속 파일 해시·변경 이유는 `final-intake.json`에 둔다. 담당자 원본 작업 기록 2개는 원본 커밋에 보존하고 중복 복사하지 않았다.
- `source-download.json`: 승인된 공식 LG PDF 3개의 실제 다운로드, 기대 해시와 일치 여부.
- `parser-wheel.json`: 추가 설치 없는 선택적 pypdf 6.10.0 휠, 공식 PyPI URL·해시·라이선스.
- `validation.json`: 실행 조건, 실제 검사 결과, 실패·한계와 원본 로그 해시. 큰 실행 로그는 PM의 비공개 근거 폴더에 보존한다.
- `final-intake.json`: 최종 DATA 코드와 새 자료팩 파일의 고정 해시, 재현 입력 위치, 미완료 범위.

실제 버그는 DocumentStore가 복사한 자료와 별개로 호출자의 원본에서 조회 인덱스를 만들던 점이었다. 인덱스도 내부 복사본에서 만들도록 수정하고 입력·조회 결과 변이에 대한 회귀 검사를 인수했다. CSV 가져오기는 크기·행 수·UTF-8·고정 열·모델/자료 버전/원문 종류·행 위치·ID 중복을 검사한다. 원문 범위 검증은 현재 원본 바이트의 해시와 정확한 인용·위치를 검사하며 caller가 제공한 추출본을 OCR 결과로 표현하지 않는다. 후속 `collections.abc` 가져오기와 테스트 리터럴 변경은 현재 저장소 린트 규칙을 맞춘 것으로 계약·동작 변경이 없다.

승인된 고정 Docker 이미지에서 네트워크와 인증 마운트 없이 실행했다. 호스트 Python은 내보내기·해시·다운로드·근거 기록에만 사용했다. 실제 모델 호출·GPU·활성 PM/Worker·작업 대기열·비용·원본 담당자 기록은 변경하지 않았다.

집중 기능 검사는 원문 재등록·6개 추가 위치·3제품 정상/변경 입력·상충 조건·변조 거부·조회 격리·날짜 부재를 검사한다. 전체 저장소 첫 시도는 1,210개 중 오류 4개, skip 3개였다. 읽기 전용 내보내기 폴더에 쓰려던 비관련 테스트 3개와 MCP stdio 자식 연결 종료 1개이며, 이 실패를 보존하고 전체 저장소 PASS로 바꾸지 않는다. 최초 26개 집중 검사는 통과한 뒤 검증 기록기의 시간 필드 참조가 실패했으며, 원본 로그를 보존하고 기록기를 고친 후 45개 실제 검사를 별도 실행했다. 첫 린트는 읽기 전용 캐시 때문에, 두 번째는 스타일 경고와 Windows 마운트의 실행 비트 인식 때문에 실패했다. 캐시를 사용하지 않고 실행 비트 전용 경고를 제외한 실질 스타일 검사를 새로 실행한다. 저장소 파일은 Git에서 100644다.

공개 자료팩은 고객 리뷰 0건으로 보류 예상 입력이다. 이전 실험 로그는 그 당시 실행의 원본이며 이번 모델 재실행 증거가 아니다. 합성 리뷰 36건은 5모델별 10/10/10/3/3건이고 날짜가 없어 추세 분석 대상 0건이다. 독립 평가·실모델 의미 품질·전체 저장소 CI와 PM 병합/통합 승인은 후속으로 남는다.
