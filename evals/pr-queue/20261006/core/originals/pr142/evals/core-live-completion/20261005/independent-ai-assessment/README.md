# 독립 AI 평가와 판단 사유 검사 보완

PR #142의 기존 head `3bb9201144accdf9806fcea70e0cfc95b07a2f13`에 제출된 합성 6사례·12개 원 출력을 별도 문맥의 AI 평가자가 채점했다. 생산 모델/GPU를 다시 실행하지 않았다. 작성 대화·결론·방법 대응키를 제공하지 않고 원문, 가린 출력, 사전 고정 기준과 동일 출력 계약만 제공했다. 평가 완료 파일의 해시를 고정한 뒤에만 아래 방법별 결과를 해석했다.

평가자는 작성자와 같은 기반 모델·파일시스템을 공유하며, 입력 제한은 지시로 적용했다. OS 격리나 사람 평가를 주장하지 않는다. 방법 이름만 가렸으므로 출력 구조가 방법을 드러낼 수 있다. 정확한 평가 모델 버전은 도구에서 제공되지 않았다. 한 평가자·한 합성 묶음으로 일반 성능 순위나 고객 효용을 결론내리지 않는다.

| 사례 | Agent | 단일 프롬프트 기준선 |
|---|---|---|
| HOLD-01 정상 불편 | fail | pass |
| HOLD-02 기존 END 표시 | uncertain | pass |
| HOLD-03 다른 모델·버전 자료 | uncertain | pass |
| HOLD-04 상충 리뷰 | pass | fail |
| HOLD-05 설명서 없음 | pass | fail |
| HOLD-06 명세 변경 | uncertain | fail |

Agent는 pass 2 / fail 1 / uncertain 3, 기준선은 pass 3 / fail 3이다. 원문 조건만으로 결론을 정할 수 없거나 실제 의미 답변이 없는 결과는 uncertain이다. HOLD-03의 범위 오류 거절은 맞지만 실질 판단 품질은 미관측이다. HOLD-02/06은 기능 지원과 실제 불편 해소의 사용 조건을 구분해야 한다. 이 판정을 작성자가 통과로 바꾸지 않았다.

차단 결함과 상세 원문·출력 경로는 [평가자 보고서](report.md), [판정 원본](findings.json), [완성 scorecard](completed-scorecard.json), [인용 감사](citation-audit.json)에 있다. 네 파일은 평가자 원 바이트를 그대로 복사했다. [provenance](provenance.json)에 입력·산출물 SHA256, 문맥/격리 한계와 완료 범위를 기록했다. [사전 기준](reviewer-protocol.md), [고정 평가 입력](reviewer-inputs/input-freeze.json), [기계적 무결성 검사](integrity-validation.json)도 함께 제출한다.

인용 지표는 명시적으로 원문에 귀속한 인용 출현 1개 검사 / 정확 인용 0개다. UI 이름·용어에 붙인 따옴표 5개는 제외 사유를 남겼다. 다른 카드의 0/0은 미관측이며 정확도 null이다. bare 근거 ID의 의미 충실도를 이 숫자로 대체하지 않는다. 모델/버전 오류와 명시된 동일 조건 기능 재포장 후보는 관측 0건이지만 제품 전체 신규성·효과를 입증하지 않는다. 사람 편집 시간은 측정하지 않아 null을 유지했다.

## 로컬 코드 보완과 검증 범위

HOLD-01 Agent는 원문의 청소 접근 어려움을 `concept_assessments[0].reason`에서 "모서리 세정이 불가능한 물리적 한계"로 확대했다. 기존 의미 검토 입력에는 후보 본문만 있고 이 판단 사유가 빠져 있었다. 이번 수정은 같은 `concept_id`의 판단 사유도 검토 문맥·생성용 인용 선택지·원문 인용 검사에 포함한다. 기존 제품 기능 부재/불가능/원인 단정도 근거와 대조하도록 지침을 보완했다.

인용은 해당 후보의 본문 또는 같은 후보의 사유에만 묶인다. 다른 후보의 사유나 바뀐 출력 해시는 거절한다. 공유 최대 2회 수정 예산·공통 계약·검사 기준 수는 유지했다. 원 실패 출력·빈 scorecard·평가자 점수는 수정하지 않았다.

- 관련 코어 회귀검사 103개 통과, 변경 파일 Ruff 통과. 새 회귀 3개는 원 실패 사유 인용, 다른 후보의 사유 차용 거절, 출력 해시 변경 거절을 검증한다.
- 지침 일치·harness·phase2·공통 계약 검사는 통과했다. 검사 로그와 소스/로그 해시는 [verification](verification/summary.json)에 있다.
- 첫 검사 복사본은 sandbox의 DLL 로드 거부로 시작하지 못했다. 인증 환경을 비운 복사본과 Python 네트워크 차단으로 검사했고, Git 경로/객체 참조를 준비한 뒤 정적 검사를 완료했다. 이 방식은 OS 권한 분리의 증거가 아니다. 실패 원 기록도 private에 보존했다.
- 테스트에서 작성한 오류 판정은 회귀 fixture이다. **수정 코드의 실제 Qwen3.5:27B 재검증은 이번 제출에서 실행하지 않았다.** 같은 모델·pin/옵션으로 알려진 문제 1건을 추후 재검증해 이 PR에 별도 추가한다. 기존 평가 이후의 개발 회귀이며 새 독립 평가로 세지 않는다.

`independent_ai_assessment_complete=true`는 제한된 AI 채점 산출물의 완료다. 공식 평가·모델 채택·PM 승인·병합·통합·CORE002~005 Done은 미완료다. 기존 수집 파일의 `evaluation_complete=false` 및 준비 상태는 당시의 원 기록으로 보존하며, 최신 AI 채점 상태는 이 폴더의 provenance를 따른다.
