# 실제 인수에 필요한 기존 산출물

신진하 DATA의 현재 인수는 source/report metadata까지다. 새 모델/OCR/서버 재시작/공유 서비스 설치 없이 이미 있는 승인된 출력·읽기 범위로 다음 단위를 인수한다. 비밀·답안은 Issue/PR에 첨부하지 않는다.

## A. R9 최신 normal/revision — PM·CORE

대상은 `run-1f83d846191941aea21153897b944ec1`과 `run-754268c6b0cb41bba50c5b8d713332d9`다. PM009/E056의 각2call/0repair/6source·구조 complete 보고는 보존하되 이 창의 수신 증명과 구분한다.

1. 이미 저장된 비밀 없는 원 PlanningBrief/result JSON과 byte/SHA, 승인된 읽기 위치. 공개 projection과 private native response/trace는 각각 원 해시·가림 범위를 구분한다.
2. 실제 generation 당시 code commit, loaded bundle ID/SHA, selected Source ID·객체, full-input/source context pin, 실제 모델 tag/digest/설정. 현재 publication main을 과거 실행 code pin으로 추정하지 않는다.
3. normal brief ID·revision parent ID·이전 brief와 조건 문자열. 같은 입력목록/facts를 유지했다는 실제 자료와 현재 실제 HTTP GET `/api/research/planning-runs/{run_id}` 및 대응 MCP의 원응답/SHA/시각. 원 저장 run 전체와 최신 응답을 구분한다.
4. 이미 보존된 discover/plan/repair 원응답·실패·재시도/공유한도·usage. 이 단위로 새 호출을 요청하지 않는다. 없으면 미생성/미보존을 명시한다.

수신 뒤 실제 file SHA·selected scope·facts/부모를 먼저 대조하고, 이전16 PM findings는 원 위치로 재사용한다. 새로 달라진 주장만 증상·주체·시점·기대/성과·혼합·공용 설명서 조건에 대조한다. 원출력이 없으면 의미 정확도/해결 여부는 미확인이다.

## B. #14 자동 graph/adapter — PM·생산 담당·CORE

PR258의 p57/p37 수동5셀과 CORE 읽기 회신을 재사용한다. 필요한 것은 **실제 자동 producer graph**의 원파일·SHA·producer code/settings·고정 원PDF SHA/판본·물리쪽/bbox 좌표 기준 및 승인 adapter 담당/commit/소비 receipt다. 승인된 동일 제품·판본·Evidence3 연결을 대조한다. 없으면 담당·첫2페이지 출력 단위만 정하고 정확도/오류 수는 null을 유지한다.

DFE 일반845mm/상판제거815mm를 DUE 빌트인815mm 조건으로 전이하지 않는다. MW1570W 소비전력과1000W 출력/시간각주를 구분하고 M07로 출력/각주를 증명하지 않는다. 원 sidecar를 새 자동 예측이나 생산 Schema로 등록하지 않는다.

## C. #15 기존 input-only — PM·DATA·CORE

기대 ZIP SHA `e73d3393ad43e0bb9cf5f19944cc6c23c3fa69c72a1a140d6d680037e89ffaa8`, 11,106bytes·11entries·6primary+paired1/6groups다. 최신 기존 CORE 수신 보고는0이며 actual SHA/bytes/entry 목록은 null이다.

1. PM: 기존 승인 무료 비공개 endpoint/client 또는 양쪽에서 접근 가능한 공유 경로, 송신·수신 PC 매핑·읽기 범위·승인 출처. CORE clone-relative 폴더를 전송 주소로 취급하지 않는다.
2. DATA: 그 경로 인수 후 기존 input-only ZIP/metadata만 전달한다. 원 outbox/manifest는 재생성하지 않고 Gold/reviewer-only/demo/방식키를 포함하지 않는다.
3. CORE: 실제 받은 ZIP SHA/bytes/11-entry path·size·SHA, metadata/schema/case/group/source/model/version 대조와 인증된 수신 시각을 남긴다. DATA 발신 검사의 PASS를 본인 수신으로 바꾸지 않는다.
4. PM: Gold·표본 독립성·후보/답안/코드 작성에서 분리된 최종 채점자·비공개 검토 경로를 확정한다. 같은 canonical input SHA의 이미 생성된 Agent/일반 LLM 결과가 있으면 원출력/full-input/실패/usage pin을 별도 인계한다.

기존 후보는 합성·미승인 진단/반례용이다. R9 실제 후기 결과나 과거3시나리오를 이7입력의 성능으로 승계하지 않는다. 실제 전송·생성·채점 전에는 점수/토큰/비용/독립 평가 Done을 만들지 않는다.
