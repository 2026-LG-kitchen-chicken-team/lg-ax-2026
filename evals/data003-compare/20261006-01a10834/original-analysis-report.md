### corpus 차이와 정답 대응

기존 개발 corpus는 `DATA003-dev-20261005.1`의 **사실 요약 27개**다. PM의 등록 원문 corpus는 `lg-manual-scope-20261006.3-pm-intake`의 **설명서 인용 21개**다. 공통 ID 15개, 개발 전용 12개, 현재 원문 전용 6개이며 공통 15개 모두 본문이 달라졌다. 같은 ID·같은 모델/설명서 개정이어도 같은 텍스트 입력이 아니다. 기존 `F-M/D-M/M-M` 별칭은 실제 문서 source ID로 덮어쓰지 않았다.

추가된 F12/F13/D03/M06/M07/M13 6개는 PM 자료에 이미 포함됐다. `accepted-six-confirmation.json`은 원 제안 상태를 역사 기록으로 유지하면서 현재 버전에서의 존재·원문·해시만 확인한다. 새 등록은 하지 않았다. 냉장고 5cm/10cm 출처 조건 상충, DUE 빌트인 오른쪽 열과 프리스탠딩 상판 제거 치수의 중복, MW 최대 출력 각주/소비전력 구분/전원 분리 후 유지 미확인은 보존했다.

기존 정답 ID의 존재 범위는 11/11이다. 이것은 검색 적중률이 아니다. **FR-01의 기존 정답 ID `T876MEE1H1-MANUAL-F10`은 현재 원문에서 선반을 들어 빼는 방법을 담고, ‘식품 먼저 치우기’는 `T876MEE1H1-MANUAL-F10-FOOD`에 있다.** 기존 질문·gold 파일은 그대로 보존했다. 새 대응표에는 `F10-FOOD`를 PM 검토용 제안으로만 기재했다. 이 대응을 확정하기 전 새 corpus의 의미상 정답 적중률 총점을 확정하지 않는다.

현재 자료의 등록 사실은 PM의 README/자료팩·원문 범위 검사에 근거한다. 이 스냅샷을 #13이 이번 수동 세션에서 새 등록→API 조회→재시작까지 통과한 결과로 대신 표시하지 않는다. #13 실제 출력이 오면 `13-handoff-contract.json`의 필드와 해시를 대조한다. 내용이나 ID가 달라지면 새 버전 입력을 따로 준비한다.

### 과거 corpus 성적 — 이번 재검산

| 방법 | 기존 Hit@1 | 기존 중앙 지연 | 기존 p95 |
|---|---:|---:|---:|
| BM25 | 10/11 | 0.6337ms | 0.9264ms |
| BGE-M3 | 11/11 | 316.2207ms | 365.0488ms |
| BGE-M3 + 재정렬 | 11/11 | 6006.4974ms | 9531.8831ms |

각 방법 15문항×5회=75회, 합계225회다. 적중·Recall/MRR 분모는 근거 있는11문항이고 근거 부족4문항은 제외한다. 위 지연은 근거 있는11문항의 성공55회 기준이며 전체75회·실패·근거 부족/빈 결과의 지연은 원시 표에 별도 유지했다. 각 방법의 빈 결과5회는 버전 미지정 FR-04에 해당하며 기능 미지원 판정이 아니다. 실제 예외 실패0이고, BM25의 MW-01 정답 누락과 한국어 어형/단위 토큰 문제는 원 분석 파일로 유지했다. 재정렬은 이 기존 개발셋에서 추가 적중 없이 지연이 증가했다. 이 성적을 새 원문21개 성적으로 가져오지 않았다.

현재 API `search_method=literal_token_count`는 부분문자열 빈도 검색이다. API 응답·지연은 BM25·BGE·재정렬 결과와 별도 기록해야 한다. BM25의 0점 후보가 반환되는 경우와 실제 빈 목록도 구분한다.

### OCR 문자·숫자·단위·표 오류

기존 14영역×5회=70회를 재사용했다. 완전 일치8/14, micro CER6.8702%, 본값 숫자15/15, 명시적 단위12/12, 엄격한 숫자 필드10/11이다. 단위가 crop 밖에 있는 MW 치수는 명시적 단위 분모에서 제외한다. 이 평가의 NFC·연속 공백 정리는 점수 계산 사본에만 적용하며 원문/corpus를 정규화하지 않았다.

불일치6영역은 공백 누락5건과 `1000 W*1 → 1000 W∗1` 각주 기호 변화1건이다. 후자는 엄격 파서가 추가 숫자1을 남기는 실패를 기록했다. OCR-DW-TABLE-04의 `1600 W → 1600W`, OCR-MW-TABLE-01의 `476 × 272 × 369 → 476×272×369` 등 문자 차이를 숫자·단위 본값 성공으로 지우지 않았다. 오류별 원문/인식문/페이지/crop/hash는 `ocr-error-ledger.json`과 CSV에 있다.

**표의 행·열·모델 연결 오류율은 null/미측정**이다. 사람이 고정한 행 crop의 숫자 인식 성공을 표 전체 추출 성공으로 표시하지 않는다. `ocr-table-review-plan.json`은 DUE 제품 타입/열, MW 최대 출력/각주/소비전력의 실제 추출 출력이 제공될 때 기록할 비교 항목이다. 새 레이아웃 모델을 설치하거나 같은 70회 OCR을 반복하지 않았다.

## 파일과 실행 조건

- `prepared/model-corpus.json`, `model-queries.json`: 정답/기대 답변을 제거한 모델 입력. 모델·문서 개정·근거 ID·원문을 유지하고 provenance는 별도 manifest에 연결한다.
- `prepared/corpus-manifest.json`, `current-corpus-lineage.csv`: 원문21개와 출처/PDF hash/페이지/Unicode 시작·끝 범위/text hash.
- `prepared/question-evidence-map.json`, `corpus-difference.*`: 기존 정답표 보존·변경된 인용과 적용 조건 검토.
- `prepared/comparison-protocol.json`, `retrieval-measurement-template.*`: 세 방법 공통 입력 hash/질문 순서, top3, 재정렬 후보10, CPU4, float32, CLS/L2, 길이256, seed20261005, 질문당5회/방법당warmup2 조건. **현재225행 전부 미실행이며 점수·빈 결과·지연은 null/빈 칸.**
- `prepared/historical-recalculation.json`, `historical-retrieval-attempts.csv`, `historical-ocr-attempts.csv`: 기존 실행의 재검산과 원시 행.
- `prepared/analysis-checks.json`: 원 결과 산술·문자 거리45항목 일치. `independent-arithmetic-checks.json`: 저장된 순위와 숫자/단위 파싱의 추가528항목 일치. 이는 파일·산술 검증이며 저장소 시험·독립 Agent 평가가 아니다.
- `prepared/model-environment-reuse.json`: 기존 세 모델의 고정 revision/라이선스와19파일 존재·크기 조회. 원 가중치 해시를 재사용했으며 대형 가중치 전체 hash 재검사/모델 로딩은 하지 않았다. 기존 CPU venv가 있다고 현재 인증 없는 격리 실행이 승인된 것으로 보지 않는다. 기존 고정 validator image의 모델 모듈 부재 관측과 #12 예약을 남겼다. 새 환경·모델 서비스·서버·자동화·인증을 변경하지 않았다.
