## 원 요청과 해석

- 해석: 파일별 선택 인수와 실제 사용자 경로 연결이 목적이다. 팀원 개인 수행 문서·과거 실패/비용/중앙 상태를 대신 고치지 않는다. 월별·계절별 그래프는 이 인수 범위에 포함하지 않는다.

## 통합과 수정

- 실제 후보 상세에 근거 추적을 연결했다. 판단 당시 원문과 현재 조회 원문을 분리하고, 변경/삭제/없는ID/다른 모델·버전을 표시한다. 현재 자료 미조회는 삭제로 추정하지 않는다. 변경된 원문은 이전 인용을 덮어쓰지 않는다.
- 공개 bootstrap과 비공개 작업실은 자료가 다를 수 있으므로 동일 dataset SHA가 확인돼야 현재 자료 대조에 사용한다. 현행 공개 응답에는 이 SHA가 없으므로 실제 화면은 저장된 판단 원문을 표시하고 최신 자료 변경·삭제를 단정하지 않는다. 컴포넌트의 변경/삭제 검사는 고정된 비교 입력으로 검증하며 최신 자료 전체 조회 연결은 후속이다.
- HistoryView에 회차 구분 타임라인을 연결했다. 자료 버전만 변한 경우를 사용자 조건 변경으로 표시하지 않는다. 누락·순환·타 프로젝트·중복ID·회차 불일치이면 이전 실행의 후보·질문과 비교하지 않는다. 합성 화면 예시와 저장된 실행 표시를 구분한다.
- 사용자 답변은 현재 질문과 원 실행 ID를 포함한 새 PlanningRequest의 기획 요청에만 추가한다. 제품 모델·문서/자료 범위·제외 조건·기존 원 기록은 유지한다. 비어 있거나 과도하거나 다른 실행의 질문이면 거절한다. 입력 취소는 저장하지 않고 서버 실패는 답변을 유지한다.
- 원 자동 추가 질문 작업 `auto-bb18aeb662ec3c3d`는 failed 상태를 고치지 않았다. Issue25의 PM 배정문(`5996879000`)을 확인했지만 원 미게시 산출물/validator 로그는 공개 경로에서 확인하지 못했다. ClarificationPanel은 이번 PM 별도 구현이며 원 모델 산출물 복구로 표현하지 않는다.
- 일부 초기 'Agent 연결 예정' 안내를 연결 여부·저장된 실제 결과 기준 문구로 정리했다. 요청 저장만 성공한 경우와 판단 완료/보류/실패는 계속 구분한다.

## 검사와 남은 범위

검사 전 source commit을 고정하고 실제 결과를 `validation.json` 및 로그에 연결한다. 검사 실행 전에는 통과를 주장하지 않는다. React 검토는 Hook 순서/의존, 순수 입력 비교, 원문 텍스트 escaping, 레이블/키보드 접근성, 실패 입력 유지, 중복 제출 방지를 점검했다. 실제 브라우저 및 모델 통합 검사는 PM 후속이다. 추가 질문의 답변이 기획 품질을 높이는지는 아직 평가하지 않았다. 코드 구현/CI와 전체 참가작 완성은 구분한다.
