## 통합과 수정

- 실제 후보 상세에 근거 추적을 연결했다. 판단 당시 원문과 현재 조회 원문을 분리하고, 변경/삭제/없는ID/다른 모델·버전을 표시한다. 현재 자료 미조회는 삭제로 추정하지 않는다. 변경된 원문은 이전 인용을 덮어쓰지 않는다.
- 공개 bootstrap과 비공개 작업실은 자료가 다를 수 있으므로 동일 dataset SHA가 확인돼야 현재 자료 대조에 사용한다. 현행 공개 응답에는 이 SHA가 없으므로 실제 화면은 저장된 판단 원문을 표시하고 최신 자료 변경·삭제를 단정하지 않는다. 컴포넌트의 변경/삭제 검사는 고정된 비교 입력으로 검증하며 최신 자료 전체 조회 연결은 후속이다.
- HistoryView에 회차 구분 타임라인을 연결했다. 자료 버전만 변한 경우를 사용자 조건 변경으로 표시하지 않는다. 누락·순환·타 프로젝트·중복ID·회차 불일치이면 이전 실행의 후보·질문과 비교하지 않는다. 합성 화면 예시와 저장된 실행 표시를 구분한다.
- 연결된 회차 이력과 전체 실행 선택기를 함께 유지해 다른 분기/옛 실행도 선택할 수 있다. 기존 측정 범위 검사에서 선택 버튼의 `aria-current` 누락을 발견해 복구했다. 요청 내용이 같은 후보 변화 예시는 서버 규칙에 맞게 요청 회차를 유지하며, 잘못된 내부 수정 회차는 기존 전후 비교에서도 보류한다.

## 검사와 남은 범위

검사 전 source commit을 고정하고 실제 결과를 `validation.json` 및 로그에 연결한다. 검사 실행 전에는 통과를 주장하지 않는다. React 검토는 Hook 순서/의존, 순수 입력 비교, 원문 텍스트 escaping, 레이블/키보드 접근성, 실패 입력 유지, 중복 제출 방지를 점검했다. 실제 브라우저 및 모델 통합 검사는 PM 후속이다. 추가 질문의 답변이 기획 품질을 높이는지는 아직 평가하지 않았다. 코드 구현/CI와 전체 참가작 완성은 구분한다.

첫 `4dc5699` 소스의 검사 실패는 `initial-failure.json`과 원 Vitest 로그에 보존한다. 8개 실패(선택 표식 3개·합성 요청 회차 5개)는 원인별로 수정했으며, 새 패널 5개·실제 App 연결 2개 검사는 이 첫 실행에서도 통과했다. 종료 후 생성된 npm 의존성 링크를 원본 전체 스냅샷에 포함한 supervisor 오류는 검사 실패와 구분하며, 후속 supervisor는 원본 파일 목록의 실제 일반 파일/해시만 검사한다. 원 bb18 자동 작업의 실패·비용·미게시 상태를 이 PM 재검증으로 덮어쓰지 않는다.

`c643001e249b52744a3a298acf9f7b6e6673c31a`의 전체 검사에서는 설치·Vitest 343통과/5실연결 생략·실행 정책4통과·타입·빌드가 모두 통과하고 원본 파일 변경이 없었다. 정확한 archive SHA와 무인증/네트워크 차단/비게시 권한 경계는 `baseline-full-validation.json`과 네 로그에 보존한다.

독립 검수에서 공통 계약이 허용하는 pending/running 기록을 빈 최종 결과로 비교할 수 있음을 지적받았다. 현재 생성 API는 최종 상태까지 반환하지만 UI 계약의 중간 상태도 방어해야 한다. `d268debb73362ed4449e5990c4e42dac2341a9d9`에서는 선택/이전 실행이 중간 상태이면 후보 제거·질문 해소로 비교하지 않으며 요청·회차 정보는 계속 표시한다. 회귀4개와 관련 기존 검사, 타입·빌드를 추가 검증한 정확한 결과는 `validation.json`으로 별도 연결한다. c643 전체 검사와 d268 추가 검사는 같은 commit의 전체 검사로 합쳐 표현하지 않는다.
